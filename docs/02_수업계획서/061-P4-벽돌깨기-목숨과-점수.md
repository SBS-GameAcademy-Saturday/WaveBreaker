## 00:10–00:45 · 같이 치기 ★

### ① 점수부터 (8분)

`061_Lives_Start` 를 연다. 060 완성 상태다.

> 💬 "블록을 깨면 점수가 올라야 합니다. **누가 점수를 올릴까요?**"
>
> 학생 답을 기다린다. "공이" / "매니저가" 둘 다 나온다.

> 💬 "공이 매니저를 알아야 하면 서로 얽힙니다. **매니저가 세는 게 낫습니다.**"
> 💬 "매니저는 이미 블록 수를 세고 있죠. **줄어든 만큼 점수를 주면** 됩니다."

```csharp
private int lastBrickCount;
private int score;

private IEnumerator CheckClearRoutine()
{
    yield return null;                       // ← 한 프레임 기다린다

    lastBrickCount = GameObject.FindGameObjectsWithTag("Brick").Length;

    while (true)
    {
        yield return new WaitForSeconds(clearCheckInterval);

        int now = GameObject.FindGameObjectsWithTag("Brick").Length;

        if (now < lastBrickCount)
        {
            score += (lastBrickCount - now) * 10;
            UpdateHud();
        }

        lastBrickCount = now;

        if (now == 0) Finish("클리어!  —  R 키로 다시");
    }
}
```

> 💬 "**줄어든 개수 × 10점.** 0.5초에 두 개가 깨졌으면 20점이 한 번에 들어갑니다."
> 💬 "이미 세고 있던 값을 **한 번 더 쓰는** 겁니다. 새로 만들 게 없어요."

> 🚨 **`yield return null;` 이 왜 첫 줄에 있는지**가 이 블록의 핵심이다.
>
> 처음엔 `while` 안에서 첫 개수를 기록했다. 그런데 **0.5초를 기다리는 사이에 깨진 블록이
> 점수에 안 잡혔다.** 실제로 재보니 블록 50 → 49 인데 점수가 0 이었다.
>
> 💬 "그럼 코루틴 시작하자마자 세면 되지 않나요?"
> 💬 "**그것도 안 됩니다.** `Start` 실행 순서는 유니티가 정하는데, 이 시점에는
> `BrickSpawner.Start` 가 아직 안 돌았을 수 있어요. 블록이 0개로 세어집니다."
> 💬 "**한 프레임만 기다리면** 그 프레임의 `Start` 가 전부 끝나 있습니다. 그래서 `yield return null;` 이에요."
>
> 🔑 051에서 배운 `yield return null` ("다음 프레임까지")이 **실제로 필요한 첫 자리**다.
> 그때는 "이런 것도 있다" 였는데 오늘은 **없으면 점수가 틀린다.**
>
> 📊 실측: 이 줄을 넣기 전에는 블록 11개를 깼는데 점수가 100점(10개분)이었다.
> 넣은 뒤에는 블록 1개에 정확히 10점이 들어온다.

### ② 목숨 (11분) — 오늘의 핵심

```csharp
[SerializeField] private int maxLives = 3;

private int lives;

void Start()
{
    lives = maxLives;
    StartCoroutine(CheckClearRoutine());
    UpdateHud();
}
```

`ball == null` 일 때 하던 일을 바꾼다.

```csharp
if (ball == null)
{
    lives--;
    UpdateHud();

    if (lives <= 0)
    {
        Finish("게임 오버  —  R 키로 다시");
    }
    else
    {
        Invoke(nameof(RespawnBall), 1f);
        ball = null;                     // 재생성 전까지 이 블록이 또 안 돌게
        isRespawning = true;
    }
}
```

> 🚨 **여기가 오늘 최다 사고 지점이다.**
> 💬 "`ball == null` 이 참인 동안 이 코드가 **매 프레임 돕니다.** 목숨이 순식간에 0이 돼요."
> 💬 "057에서 `isGameOver`로 막았던 것과 **똑같은 문제**입니다."

**그래서 상태 표시가 하나 더 필요하다.**

```csharp
private bool isRespawning;

void Update()
{
    if (isOver) { /* R 재시작 */ return; }

    if (isRespawning) return;            // ← 이 줄이 오늘의 핵심

    if (ball == null) { /* 위 코드 */ }
}
```

> 💬 "**한 번만 실행되게 하는 것** — 이번 Phase에서 세 번째 나옵니다. `isGameOver`, `isOver`, `isRespawning`."
> 💬 "패턴이 보이죠? **상태를 표시로 남긴다.** 앞으로 계속 씁니다."

### ③ `Invoke` — 잠깐 뒤에 (9분)

```csharp
private void RespawnBall()
{
    ball = Instantiate(ballPrefab, ballSpawnPoint.position, Quaternion.identity);

    isRespawning = false;
}
```

| 조각 | 뜻 | 어디서 |
|---|---|---|
| `Invoke(nameof(RespawnBall), 1f)` | **1초 뒤에 이 메서드를 부른다** | 오늘 |
| `Instantiate(ballPrefab, ...)` | 공을 새로 만든다 | **047** |
| `ballSpawnPoint` | 어디에 놓을지 | **047의 `firePoint`** 와 같다 |

> 💬 "**`Invoke`는 코루틴의 간단한 버전**입니다. '몇 초 뒤에 이거 해줘' 만 하면 될 때 씁니다."
> 💬 "051에서 배운 코루틴으로도 됩니다. **한 줄이면 되는 일에 코루틴은 과해요.**"

```csharp
// 코루틴 버전 — 같은 일을 한다
IEnumerator RespawnRoutine()
{
    yield return new WaitForSeconds(1f);
    RespawnBall();
}
```

> ⚠️ **`nameof`** 를 처음 쓴다.
> 💬 "`Invoke`는 원래 **메서드 이름을 문자열로** 받습니다. `\"RespawnBall\"` 처럼요."
> 💬 "그런데 문자열은 **오타를 못 잡습니다.** `nameof`를 쓰면 이름이 틀리면 컴파일 에러가 나요."
> 💬 "049의 `CompareTag` vs `tag ==` 와 같은 이야기입니다. **틀렸을 때 알려주는 쪽**을 고릅니다."

### ④ 화면에 보여준다 (5분)

```csharp
private void UpdateHud()
{
```

## 01:35–01:50 · 데모 + 정리

학생 2명 데모. **`isRespawning`을 빼먹어 목숨이 순식간에 0이 된 학생**이 있으면 그걸 먼저 보여준다.
이 Phase에서 세 번째 나오는 패턴이라 여기서 못을 박는다.

**마무리 정리 (한 장) — 한 번만 실행되게 하는 표시**

| 회차 | 표시 | 막는 것 |
|---|---|---|
| 057 | `isGameOver` | 게임오버가 매 프레임 불리는 것 |
| 060 | `isOver` | 클리어와 게임오버가 겹치는 것 |
| **061** | **`isRespawning`** | **목숨이 한 번에 다 깎이는 것** |

> 💬 "**상태를 표시로 남긴다** — 세 번 나왔으면 패턴입니다. 본 프로젝트에서도 계속 씁니다."

## 🚨 흔한 사고 & 대응 (강사용)

| 에러/상황 | 진짜 원인 | 대응 |
|---|---|---|
| **목숨이 한 번에 0이 됨** | **`isRespawning` 없음** | **오늘 1등.** 매 프레임 깎인다 |
| 공이 다시 안 나옴 | `isRespawning`을 안 풀었다 | `RespawnBall` 끝에서 `false` |
| 공이 여러 개 생김 | `Invoke`가 여러 번 예약됨 | 예약 전에 `isRespawning = true` |
| `Invoke` 가 안 불림 | 메서드가 `private` 이어도 된다 | 이름 오타. `nameof` 를 쓴다 |
| 점수가 시작하자마자 500점 | 첫 개수를 기록 안 함 | 코루틴 첫 줄에서 `lastBrickCount` 기록 |
| **첫 블록 하나가 점수에 안 잡힘** | `yield return null` 없이 바로 셈 | 한 프레임 기다린 뒤 기록 |
| 블록이 0개로 세어짐 | `Start` 실행 순서 | `yield return null` 로 한 프레임 기다린다 |
| HUD가 안 바뀜 | `UpdateHud`를 안 부름 | 값이 바뀌는 자리마다 |
| `NullReferenceException` | `Ball Prefab` / `Ball Spawn Point` 빔 | Inspector 확인 |
| 게임오버 후에도 공이 생김 | 예약된 `Invoke`가 남음 | `CancelInvoke()` 를 `Finish`에 |
| 재시작하면 점수가 남음 | `static` 사용 | 지금은 `static`을 쓰지 않는다 |
