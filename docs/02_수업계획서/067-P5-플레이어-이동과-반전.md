1. **입력을 읽는 스크립트**와 **움직이는 스크립트**를 나눈다 ← 규칙 ②

>
> 🔑 **설계 의도**: 042에서 한 것과 **결과는 똑같다.** 다른 건 **구조**뿐이다.

## 00:10–00:45 · 같이 치기 ★

### ① 플레이어를 놓는다 (5분)

`Game.unity` 에 빈 GameObject `Player` 를 만든다.

| 컴포넌트 | 값 |
|---|---|
| `Sprite Renderer` | 캐릭터 그림, Sorting Layer `Player` |
| `Circle Collider 2D` | 반지름 0.4 정도 |
| `Rigidbody 2D` | `Gravity Scale 0` · `Freeze Rotation Z` |
| Tag | **`Player`** |

> 💬 "042·063에서 한 그대로예요. **새로운 게 없습니다.**"

### ② 입력만 읽는 스크립트 (11분) — 오늘의 핵심

`Scripts/Player/PlayerInput.cs`

```csharp
using UnityEngine;

public class PlayerInput : MonoBehaviour
{
    public Vector2 MoveInput { get; private set; }

    void Update()
    {
        float h = Input.GetAxisRaw("Horizontal");
        float v = Input.GetAxisRaw("Vertical");

        MoveInput = new Vector2(h, v).normalized;
    }
}
```

> 💬 "**이 스크립트가 하는 일은 하나뿐입니다.** 키보드를 읽어서 값으로 담아둔다."
> 💬 "**움직이지 않습니다.** 움직이는 건 다른 스크립트 일이에요."

**세 가지를 짚는다.**

| 조각 | 뜻 | 어디서 |
|---|---|---|
| `Input.GetAxisRaw` | 키를 숫자로 | **040** |
| `.normalized` | 대각선이 빠른 문제를 막는다 | **059** |
| `{ get; private set; }` | **밖에서 읽기만** 가능 | 6주차 property |

> 💬 "**6주차에 배운 property** 입니다. 밖에서는 읽을 수만 있고, 값을 넣는 건 이 스크립트뿐이에요."
> 💬 "`public Vector2 MoveInput;` 로 그냥 열면 **아무나 바꿉니다.** 그러면 나중에 누가 바꿨는지 못 찾아요."

> ⚠️ **`Update` 에서 읽는 이유**: 입력은 프레임 단위로 들어온다. 042에서 배운 그대로다.
> 💬 "`GetKeyDown` 은 `FixedUpdate` 에 쓰면 씹힌다고 했죠. 입력은 `Update` 입니다."

> 🚨 **클래스 이름 주의.** `PlayerInput` 은 Input System 패키지에도 같은 이름이 있다.
> 우리는 `using UnityEngine.InputSystem;` 을 쓰지 않으므로 충돌하지 않는다.
> 학생이 그 `using` 을 추가하면 **모호한 참조 에러**가 난다 — 그때는 `using` 을 지운다.

### ③ 그 값으로 움직인다 (10분)

`Scripts/Player/PlayerController.cs`

```csharp
using UnityEngine;

public class PlayerController : MonoBehaviour
{
    [SerializeField] private float moveSpeed = 5f;
    [SerializeField] private PlayerInput input;
    [SerializeField] private Rigidbody2D rb;

    void FixedUpdate()
    {
        rb.linearVelocity = input.MoveInput * moveSpeed;
    }
}
```

▶ Play → **움직인다.**

> 💬 "042와 **결과가 똑같습니다.** 코드도 거의 같아요. 다른 건 **입력을 어디서 읽느냐**뿐입니다."

**여기서 반드시 나오는 질문에 답한다.**

> 학생: "결과가 같은데 왜 나눠요?"
>
> 💬 "좋은 질문입니다. **지금은 이득이 없어요.**"
> 💬 "그런데 나중에 **게임패드를 붙이거나**, **AI가 조종하는 캐릭터**를 만들 때,
> `PlayerController` 는 하나도 안 고칩니다. **읽는 쪽만 바꾸면 돼요.**"
> 💬 "그리고 버그가 났을 때 **'값이 잘못 들어왔나' / '값은 맞는데 이상하게 움직이나'** 로 나눠서 볼 수 있습니다."

> 🔑 **네트워크 얘기는 하지 않는다.** 25주차에 회수한다.

### ④ 좌우 반전 (9분)

```csharp
[SerializeField] private SpriteRenderer sprite;

void FixedUpdate()
{
    Vector2 move = input.MoveInput;

    rb.linearVelocity = move * moveSpeed;

    if (move.x != 0f)
    {
        sprite.flipX = move.x < 0f;
    }
}
```

▶ Play → **왼쪽으로 가면 뒤집힌다.**

| 방법 | 코드 | 비고 |
|---|---|---|
| `Sprite Renderer` 의 `Flip X` | `sprite.flipX = true;` | **자식은 안 뒤집힌다** |
| Scale X 음수 | `transform.localScale = new Vector3(-1, 1, 1);` | 자식까지 전부 뒤집힌다 |

> 💬 "033에서 **Scale X 를 음수로** 하면 뒤집힌다고 배웠죠. 그것도 됩니다."
> 💬 "그런데 **Scale 을 뒤집으면 자식도 같이 뒤집힙니다.** 나중에 체력바를 자식으로 달면 글자가 거울이 돼요."
> 💬 "그래서 **`flipX`** 를 씁니다. 그림만 뒤집혀요."

> ⚠️ **`if (move.x != 0f)` 가 왜 필요한가.**
> 💬 "없으면 **키를 뗐을 때 오른쪽으로 돌아갑니다.** 마지막 방향을 유지해야죠."

### ⭐ 도전 미션

- [ ] `.normalized` 를 빼고 대각선이 빨라지는지 확인한다 (그리고 되돌린다)
- [ ] `flipX` 대신 `Scale X` 음수로 바꿔보고, 자식 오브젝트를 하나 달아 차이를 본다
- [ ] `moveSpeed` 를 `[SerializeField]` 로 열어 Play 중에 조절해본다 (037)
- [ ] `PlayerInput` 에 `Shift` 를 읽는 `IsRunning` 을 추가하고 `PlayerController` 에서 쓴다
- [ ] `MoveInput` 을 `public Vector2 MoveInput;` 로 바꿔보고 왜 위험한지 한 줄로 쓴다
- [ ] 서 있을 때 애니메이션을 멈춘다 (`Animator.speed = 0`) — Phase 7 선행
- [ ] 입력을 읽는 쪽만 바꿔 **마우스 클릭 방향으로** 움직이게 해본다

> 💡 마지막 도전이 규칙 ②의 이유를 가장 잘 보여준다. **`PlayerController` 는 한 줄도 안 고쳐진다.**

| 에러/상황 | 진짜 원인 | 대응 |
