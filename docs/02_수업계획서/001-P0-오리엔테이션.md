## 00:15–00:40 · 완성작 라이브 시연 ★

**이 25분이 오늘의 전부다.** 슬라이드로 설명하지 말고 실제로 플레이한다.

**시연 순서**

1. 타이틀 화면 → "방 만들기" → **접속 코드가 뜬다**
2. 보조 진행자(또는 두 번째 화면)가 그 코드로 입장
3. 둘이 같이 웨이브를 막는다. 5분간 실제 플레이. 죽어도 된다 — 오히려 좋다
4. 레벨업 3택 선택 장면에서 **채팅으로 학생들에게 물어본다**: "뭐 고를까요?"

**시연 중 강사가 반드시 말할 것**

> "이거 제가 만든 게 아니고, **여러분이 7개월 뒤에 만들 겁니다.** 지금 코딩 한 줄도 모르는 상태로요."

> "지금 화면 두 개가 서로 연결돼 있죠. 이건 마지막 두 달에 배웁니다. **앞의 다섯 달은 이 게임을 혼자 하는 버전으로 먼저 완성해요.**"

**절대 하지 말 것**

- 코드 보여주기 (오늘은 코드라는 단어도 최소로)
- "어렵지만" "쉽지 않지만" 같은 예방주사 — 1일차에 겁주면 그대로 이탈한다
- 개발 기간·난이도 자랑

## 00:40–00:55 · 7개월 로드맵

로드맵 표를 화면에 띄우고 **3개 지점만** 짚는다.

| 시점 | 학생에게 하는 말 |
|---|---|
| 1개월차 | "C# 문법을 콘솔로 확실히 다집니다. **게임은 아직 안 만듭니다**" |
| **7주차** | "**여기서 유니티를 켭니다.** 화면에서 캐릭터가 움직여요" |
| 3개월차 | "작은 게임 3개를 끝까지 만들어 봅니다" |
| 5개월차 | "**게임 하나가 완성돼서 빌드가 나옵니다.** 여기서 이미 친구한테 보낼 수 있어요" |
| 7개월차 | "그 게임에 멀티를 붙입니다" |

> **7주차 지점을 반드시 명시할 것.** C# 선행 구성이라 6주 동안 콘솔만 본다. "언제 게임 만들어요?"에 얼버무리면 불안이 커진다. **"7주차부터"** 라고 정확히 말한다.
>
> 5개월차 지점도 **강조**할 것. "멀티가 안 되면 어쩌지"라는 불안을 처음부터 없앤다.

## 01:05–01:30 · 수업 규칙 & 도구

**① 하루 2시간은 이렇게 굴러갑니다** (고정 타임테이블 공유)

- "제가 치는 걸 **같이 치세요.** 보기만 하면 절대 안 늡니다"
- "뒤 40분은 혼자 하는 시간. 제가 한 명씩 돌면서 봅니다"

**② 매일 끝에 스크린샷 하나 올립니다**

> "잘 된 거 말고 **그날 화면**을 올리는 겁니다. 안 되면 안 되는 화면을 올리세요. 그게 제일 좋은 질문이에요."

**③ 질문 규칙** — 에러가 나면

1. 콘솔 창 **빨간 줄 전체**를 스크린샷
2. 그 코드 부분도 같이
3. `#질문` 채널에 올리기

> "'안 돼요'만 쓰면 저도 못 도와줍니다. **화면을 보여주세요.**"

**④ 디스코드 채널 안내** — `#공지` `#질문` `#자랑` `#자료`

> `#자랑` 채널을 반드시 만들 것. 노베이스 반에서 남의 결과물이 가장 강한 동기다.

## 01:30–01:50 · 자기소개 (전원)

한 명씩 마이크 켜고 30초. **강사가 먼저 시범.**

- 닉네임(수업 내내 쓸 것)
- 좋아하는 게임 하나
- 이 수업 끝나고 만들고 싶은 것

> 연령대가 섞인 반이다. 나이·직업은 **묻지 않는다.** 닉네임으로만 부르는 문화를 1일차에 고정하면 이후 질문 장벽이 크게 낮아진다.
