## 00:10–00:50 · 같이 하기 ★

### ① `Image` 를 직접 만져본다 (10분)

`HUD` 에 `UI → Image` 를 하나 만들고 Inspector 를 본다.

| 항목 | 뜻 |
|---|---|
| **Source Image** | 어떤 그림을 쓸지 |
| **Color** | 그림에 곱할 색 |
| **Image Type** | ← 오늘의 주인공 |
| Raycast Target | 클릭을 받을지 |

**Image Type 4가지**

| Type | 하는 일 |
|---|---|
| Simple | 그냥 늘려서 그린다 |
| Sliced | 모서리를 안 늘리고 가운데만 늘린다 (버튼용) |
| Tiled | 반복해서 깐다 |
| **Filled** | **일부만 그린다** ← 우리 것 |

**Filled 를 고르면 생기는 칸**

| 항목 | 값 | 뜻 |
|---|---|---|
| Fill Method | **Horizontal** | 가로로 채운다 |
| Fill Origin | **Left** | 왼쪽부터 |
| **Fill Amount** | **0 ~ 1** | **얼마나 채울지** |

▶ Fill Amount 슬라이더를 손으로 움직여 보여준다.

> 🔑 💬 "**이게 전부입니다.** 체력바는 이 숫자를 코드로 바꾸는 것뿐이에요."

> 🚨 **Source Image 가 비어 있으면 `Fill Amount` 가 안 먹는다.**
> 그림이 없으면 Unity 는 그냥 사각형을 그리고 끝낸다. **반드시 스프라이트를 넣는다.**

### ② 🐛 강사가 겪은 것 — 기본 스프라이트로 하면 찌그러진다 (5분)

처음엔 Unity 기본 `UISprite` 로 만들었다. 결과가 이랬다.

> 화면: 체력바의 **왼쪽 끝이 둥글게 늘어나 뾰족한 모양**이 됐다.

**원인**: `UISprite` 는 **모서리가 둥근** 그림이다.
`Sliced` 로 쓰면 모서리를 안 늘려서 괜찮은데, **`Filled` 는 Sliced 를 무시하고 통째로 늘린다.**
둥근 모서리가 그대로 늘어나 뾰족해진 것이다.

**고친 것**: **8×8 흰 사각형** 스프라이트(`UI_Bar.png`) 를 만들어 썼다.

| 항목 | 값 |
|---|---|
| 크기 | 8 × 8 (색만 있으면 되니 클 이유가 없다) |
| Texture Type | `Sprite (2D and UI)` |
| Filter Mode | `Point (no filter)` |
| Compression | `None` |

> 💬 "**흰색으로 만드는 이유**는 `Image` 의 Color 로 아무 색이나 곱할 수 있어서예요."
> 💬 "빨강 바, 파랑 바를 그림 두 장으로 만들 필요가 없습니다. **한 장이면 됩니다.**"

### ③ 바 하나는 두 겹이다 (8분)

```
HealthBar        ← Image (배경, 어두운 색)   + StatBar 스크립트
  ├ Fill         ← Image (Filled, 빨강)      ← 이게 줄어든다
  └ Label        ← TMP_Text ("13 / 20")
```

| 부분 | 왜 필요한가 |
|---|---|
| **배경** | 없으면 **줄어든 만큼이 그냥 사라진다.** 얼마나 남았는지 모른다 |
| **Fill** | 실제로 줄어드는 부분 |
| **Label** | 정확한 숫자도 궁금할 때가 있다 |

**Fill 의 RectTransform** — 부모 안쪽으로 2px 씩 들어가게 한다.

| 항목 | 값 |
|---|---|
| Anchor | Min `(0,0)` Max `(1,1)` (사방 Stretch) |
| Left / Right / Top / Bottom | 각각 `2` |

> 💬 "사방 Stretch 로 두면 **부모 크기를 바꿔도 Fill 이 알아서 따라옵니다.** 092 회수예요."

**우리 색 값**

| 부분 | 색 |
|---|---|
| 배경 (둘 다) | `(0.17, 0.17, 0.22, 0.95)` |
| 체력 Fill | `(0.85, 0.25, 0.25)` 빨강 |
| 경험치 Fill | `(0.35, 0.72, 1.0)` 하늘 |

### ④ `StatBar` — 하나로 둘 다 (12분)

`Scripts/UI/StatBar.cs`

```csharp
using TMPro;
using UnityEngine;
using UnityEngine.UI;

// 094회차 · 숫자 대신 "길이" 로 보여준다.
// 체력바든 경험치바든 하는 일이 똑같아서 스크립트 하나로 둘 다 쓴다.
public class StatBar : MonoBehaviour
{
    [SerializeField] private Image fill;
    [SerializeField] private TMP_Text label;
    [SerializeField] private string format = "{0} / {1}";

    public void Set(int current, int max)
    {
        // 0 으로 나누면 NaN 이 나오고 바가 통째로 사라진다.
        if (fill != null) fill.fillAmount = max > 0 ? (float)current / max : 0f;

        if (label != null) label.text = string.Format(format, current, max);
    }
}
```

| 조각 | 뜻 |
|---|---|
| `(float)current / max` | **`(float)` 를 빼면 정수 나눗셈**이 돼서 13/20 이 **0** 이 된다 |
| `max > 0 ?` | 0 으로 나누면 `NaN`. 바가 사라진다 |
| `label != null` | 경험치바엔 라벨이 없다. 없어도 돌아가야 한다 |
| `string.Format` | `{0}` 자리에 첫 인자, `{1}` 에 두 번째 |

> 🚨 **`(float)` 를 빼먹는 사고가 오늘 1등이다.**
> 일부러 빼고 실행해 보여준다. 바가 **꽉 찼다가 죽는 순간 0** 이 된다.
> 💬 "020회차에서 배운 **정수 나눗셈**입니다. C# 에서 `13 / 20` 은 `0` 이에요."

> 💬 "**왜 `HealthBar` 랑 `ExpBar` 를 따로 안 만들었을까요?**"
> 🔑 💬 "하는 일이 똑같으니까요. **'현재값 / 최대값 만큼 채워라.'** 그게 다입니다."
> 💬 "체력이든 경험치든 보스 체력이든 **전부 이 하나로** 됩니다."

**Inspector 배선**

| `HUDView` 칸 | 넣을 것 |
|---|---|
| Health Bar | `HealthBar` (`Fill` 이 아니라 **부모**) |
| Exp Bar | `ExpBar` |

| `StatBar` 칸 | 넣을 것 |
|---|---|
| Fill | 자기 자식 `Fill` |
| Label | 자기 자식 `Label` (경험치바는 **비워둔다**) |
| Format | `{0} / {1}` |

▶ Play → 맞는다 → 빨간 바가 줄어든다. 젬을 먹는다 → 파란 바가 찬다.

### ⑥ 재본 값 (5분)

```

경험치 3/5   →  ExpBar    fill = 0.600
체력 0/20    →  HealthBar fill = 0.000   label = "0 / 20"
```

> 💬 "`13 / 20 = 0.65`. 계산이 맞죠. **바의 65% 가 빨갛습니다.**"
