## 00:10–00:45 · 같이 하기 ★

### ① 플레이어를 찾는다 (5분)

```csharp
private Transform player;

private void Start()
{
    GameObject found = GameObject.FindWithTag("Player");

    if (found != null)
    {
        player = found.transform;
    }
}
```

> 💬 "071에서 몬스터가 한 거랑 **똑같습니다.** 젬도 게임 중에 생기니까 드래그를 못 해요."

### ② 가까우면 끌려온다 (12분) — 오늘의 핵심

```csharp
[SerializeField] private float magnetRange = 2.5f;
[SerializeField] private float moveSpeed = 8f;

private void Update()
{
    if (player == null) return;

    // 자석 범위 밖이면 가만히 있는다.
    if (Vector2.Distance(transform.position, player.position) > magnetRange) return;

    transform.position = Vector3.MoveTowards(
        transform.position, player.position, moveSpeed * Time.deltaTime);
}
```

▶ Play → 젬 근처로 가면 **쭉 끌려온다.**

**한 조각씩 짚는다.**

| 조각 | 뜻 |
|---|---|
| `Vector2.Distance(A, B)` | A 와 B 사이 거리 |
| `> magnetRange` → `return` | 멀면 아무것도 안 한다 |
| `Vector3.MoveTowards(지금, 목표, 걸음)` | 목표 쪽으로 **딱 그만큼만** 간다 |
| `moveSpeed * Time.deltaTime` | 초당 `moveSpeed` 만큼 (039) |

> 🔑 **`MoveTowards` 와 `Lerp` 의 차이** — 여기서 한 번 짚는다.
>
> | | 움직이는 방식 | 도착 |
> |---|---|---|
> | `MoveTowards` | **일정한 속도** | 정확히 도착한다 |
> | `Lerp` | 가까울수록 느려짐 | 영원히 조금씩 남는다 |
>
> 💬 "젬은 **딱 도착해야** 합니다. 그래서 `MoveTowards` 예요."
> 💬 "카메라는 **부드럽게** 따라가야 했죠. 그래서 068에서 `SmoothDamp` 를 썼습니다."

> 🚨 **`Time.deltaTime` 을 빼면 컴퓨터마다 속도가 다르다.** 039에서 배운 그대로다.
> 그리고 **레벨업으로 시간이 멈추면(084) 젬도 멈춘다.** 그게 맞는 동작이다.

### ④ 숫자를 바꿔본다 (12분) — 오늘의 진짜 내용

**`Magnet Range` 를 바꿔가며 직접 플레이한다.**

| 범위 | 느낌 |
|---|---|
| `1` | 거의 밟아야 먹는다. 081과 큰 차이 없다 |
| **`2.5`** | 스쳐 지나가면 먹힌다. 적당하다 |
| `6` | 가만히 서 있어도 다 온다 |
| `20` | 화면의 모든 젬이 온다. **주울 필요가 없어진다** |

> 💬 "20으로 하면 편하죠. 그런데 **재미가 없어집니다.**"
> 💬 "젬이 어디 있는지 보고 **거기로 갈지 말지** 정하는 게 판단이거든요."
> 💬 "077에서 칼 개수 정할 때랑 **똑같은 이야기**입니다. 강한 게 재미있는 게 아니에요."

**`Move Speed` 도 바꿔본다.**

| 속도 | 느낌 |
|---|---|
| `2` | 젬이 느릿느릿 따라온다. 답답하다 |
| **`8`** | 착 붙는다 |
| `30` | 순간이동처럼 보인다 |

> 💡 **Phase 6 예고**: 나중에 업그레이드로 **자석 범위가 늘어난다.**
> 오늘 `magnetRange` 를 `[SerializeField]` 로 빼둔 게 그때 쓰인다.

### ⭐ 도전 미션 — 범위를 직접 정한다

> 🎯 **오늘의 진짜 과제.** 내가 재미있다고 느끼는 값을 찾는다.

- [ ] `magnetRange` 를 `1` / `6` / `20` 으로 바꿔보고 **각각 뭐가 달라지는지** 쓴다
- [ ] `moveSpeed` 를 `2` 로 낮춰보고 답답한 정도를 느껴본다
- [ ] 끌려오는 동안 젬이 **점점 빨라지게** 한다 (가까울수록 `moveSpeed` 증가)
- [ ] 젬이 끌려올 때 **살짝 커지게** 한다 (`localScale`)
- [ ] `MoveTowards` 를 `Vector3.Lerp` 로 바꿔보고 **차이를 관찰**한다
- [ ] `Time.deltaTime` 을 지우고 실행 → 무슨 일이 나는지 쓴다 (039)
- [ ] 자석 범위를 **플레이어 쪽에서** 관리하게 바꾼다 (젬이 아니라 플레이어가 끌어당긴다)

> 💡 다섯 번째가 `MoveTowards` 와 `Lerp` 의 차이를 몸으로 알려준다.
> 일곱 번째는 **설계가 바뀌는** 문제다. 해본 학생은 데모시킨다 — 어느 쪽이 나은지 토론이 된다.

## 01:35–01:50 · 데모 + 정리

학생 3명 데모. **자기가 정한 범위와 이유**를 말하게 한다.

**마무리 정리 (한 장)**

| 함수 | 어떻게 움직이나 | 쓰는 곳 |
|---|---|---|
| `Vector3.MoveTowards` | **일정 속도**, 정확히 도착 | 젬 자석 (082) |
| `Vector3.SmoothDamp` | 부드럽게, 서서히 멈춤 | 카메라 (068) |
| `Vector3.Lerp` | 가까울수록 느려짐 | 도착이 중요하지 않을 때 |

> 💬 "셋 다 '목표로 다가간다' 인데 **느낌이 다릅니다.** 상황에 맞는 걸 고르세요."

## 🚨 흔한 사고 & 대응 (강사용)

| 에러/상황 | 진짜 원인 | 대응 |
|---|---|---|
| **젬이 안 끌려옴** | 범위가 너무 작다 | **오늘 1등.** Gizmo 로 눈으로 본다 |
| 젬이 안 끌려옴 (2) | `player` 가 `null` | Tag `Player` 확인 (063) |
| `NullReferenceException` | `player == null` 검사 없음 | `Update` 첫 줄 |
| **화면의 젬이 전부 옴** | 범위가 너무 크다 | **오늘 2등.** `2.5` 부터 |
| 젬이 순간이동함 | `Time.deltaTime` 누락 | 039 |
| 젬이 플레이어를 지나쳐 감 | `MoveTowards` 가 아닌 직접 이동 | `MoveTowards` 는 넘어가지 않는다 |
| 젬이 부들부들 떨림 | 목표에 도착했는데 계속 계산 | 정상. 먹히면 사라진다 |
| Gizmo 가 안 보임 | Game 뷰를 보고 있음 | Scene 뷰 (078) |
| 젬이 벽을 통과함 | Trigger 라서 정상 | 설명해준다 |
| 젬이 밀려남 | Rigidbody 가 Dynamic | `Kinematic` (081) |
| 레벨업 중에 젬이 멈춤 | `Time.deltaTime` 이 0 | **정상.** 084에서 다룬다 |
