## 00:10–00:50 · 같이 하기 ★

### ① 타일 3×3 을 깐다 (10분)

빈 GameObject `Ground` 를 만들고 그 **자식으로** 타일 9개를 놓는다.

| 항목 | 값 |
|---|---|
| 타일 크기 | **20 × 20** (월드 유닛) |
| 배치 | `(-20,20) (0,20) (20,20)` / `(-20,0) (0,0) (20,0)` / `(-20,-20) (0,-20) (20,-20)` |
| `Sprite Renderer` | 바닥 그림, Sorting Layer **`Background`** |
| Tag | `Ground` |

> 🚨 **타일 크기와 배치 간격이 정확히 같아야 한다.** 20짜리 타일을 19 간격으로 놓으면 **이음새가 보인다.**
> 💬 "숫자를 눈대중으로 넣지 마세요. **Position 을 직접 타이핑**합니다."

> 💡 **바닥 그림이 20 유닛이 되게 하는 법**: 그림이 64px, PPU 가 32 면 화면에서 **2 유닛**이다.
> 그래서 타일의 **Scale 을 10** 으로 준다. `2 × 10 = 20`.
> 💬 "그림 크기 ÷ PPU × Scale. 이게 화면에서의 크기예요." (053 복습)

> ⚠️ 타일에 **Collider 는 안 붙인다.** 바닥은 부딪히는 게 아니라 **깔려 있는 그림**일 뿐이다.

### ② 규칙을 먼저 말로 정한다 (8분) — 코드보다 먼저

> 💬 "코드 짜기 전에 **규칙을 한 문장으로** 만들어 봅시다."
>
> 💬 "타일이 플레이어한테서 **너무 멀어지면**, **반대편으로 옮긴다.**"

**두 개의 숫자를 학생과 같이 구한다.**

**Q1. 얼마나 멀어지면 옮길까?**

```
타일 3장이 나란히 있으면 전체 폭은  20 × 3 = 60
플레이어는 그 한가운데 있으니 양쪽으로 각각  60 ÷ 2 = 30
```

> 💬 "**30**입니다. 30보다 멀어진 타일은 이제 안 보여요."

**Q2. 얼마나 옮길까?**

> 💬 "**60**입니다. 전체 폭만큼요."

**칠판에 그린다.**

```
옮기기 전:   [-20] [ 0 ] [ 20]        플레이어 →→→
                                       (플레이어가 x=11 을 넘으면
                                        -20 타일이 31 만큼 멀어진다)
옮긴 뒤:            [ 0 ] [ 20] [ 40]   (-20 이 +60 되어 40)
```

> 🚨 **왜 60인가.** 이 회차 계산 사고 1등이다.
> 💬 "40을 쓰면? **이미 타일이 있는 자리로 갑니다.** 겹치고 반대쪽에 구멍이 생겨요."

### ③ 코드로 옮긴다 (14분) — 오늘의 핵심

`Scripts/Manager/InfiniteGround.cs` 를 만들어 **`Ground` 부모에 하나만** 붙인다.

```csharp
using UnityEngine;

public class InfiniteGround : MonoBehaviour
{
    [SerializeField] private float tileSize = 20f;
    [SerializeField] private int gridCount = 3;

    private Transform player;

    void Awake()
    {
        player = GameObject.FindWithTag("Player").transform;
    }

    void LateUpdate()
    {
        float span = tileSize * gridCount;   // 60 — 맵 한 판의 폭
        float half = span / 2f;              // 30 — 이만큼 멀어지면 옮긴다

        foreach (Transform tile in transform)
        {
            Vector3 diff = tile.position - player.position;

            if (diff.x > half) tile.position += Vector3.left * span;
            if (diff.x < -half) tile.position += Vector3.right * span;
            if (diff.y > half) tile.position += Vector3.down * span;
            if (diff.y < -half) tile.position += Vector3.up * span;
        }
    }
}
```

▶ Play → 달려도 **바닥이 계속 이어진다.**

> 🎉 여기서 반응이 온다. **Scene 뷰를 켜두고** 달리게 하면 타일이 순간이동하는 게 보인다.

**한 조각씩 짚는다.**

| 조각 | 뜻 |
|---|---|
| `foreach (Transform tile in transform)` | **내 자식들을 하나씩** 꺼낸다 (타일 9장) |
| `tile.position - player.position` | **플레이어에서 타일까지의 거리와 방향** (063) |
| `diff.x > half` | 오른쪽으로 30보다 멀다 |
| `Vector3.left * span` | **왼쪽으로 60** 옮긴다 |
| `LateUpdate` | 플레이어가 다 움직인 **뒤에** 검사한다 (068) |

> 💬 "`if` 네 개가 전부입니다. 오른쪽으로 멀면 왼쪽으로, 위로 멀면 아래로."
> 💬 "가로 세로를 **따로따로** 봅니다. 그래서 **대각선으로 달려도** 안 뚫려요."

> 💡 **왜 `foreach (Transform ... in transform)` 이 자식을 도는가**
> `Transform` 은 자식 목록을 갖고 있다. `foreach` 에 그냥 넣으면 자식이 하나씩 나온다.
> 💬 "타일마다 스크립트를 붙일 필요가 없습니다. **부모 하나가 아홉 개를 다 관리**해요."

### ④ 왜 매 프레임 검사하나 (5분)

> 💬 "이 코드는 **매 프레임** 아홉 개를 전부 확인합니다. 낭비 아닐까요?"
> 💬 "아홉 개입니다. 컴퓨터한테 이건 아무것도 아니에요."
>
> 💬 "그리고 매 프레임 보기 때문에 **절대 안 뚫립니다.**
> 한 번 놓쳐도 다음 프레임에 바로 고쳐지거든요."

> 💡 **강사 메모**: 이 방식은 대각선 이동에서도 구멍이 나지 않는다.
> 타일이 플레이어 기준 가로·세로 각각 −30~+30 안에 항상 머무르므로,
> 어느 방향으로든 **바닥이 최소 20 유닛은 더 있다.** 카메라 반폭(약 8.9)보다 훨씬 넓다.

### ⑤ 절대 하면 안 되는 것 (3분) — 최다 사고 예방
