## 00:10–00:50 · 같이 하기 ★

### ① 프레임을 숫자로 잰다 (10분)

"느린 것 같다" 는 측정이 아니다. **숫자로 재야 한다.**

```csharp
// 잴 때 쓰는 두 값
Time.frameCount              // 지금까지 그린 프레임 수
Time.realtimeSinceStartup    // 진짜 시계 (timeScale 을 안 탄다)

평균 FPS = 흐른 프레임 수 / 흐른 시간
```

> 💡 Game 뷰 오른쪽 위 **Stats** 버튼을 눌러도 FPS 가 나온다. 다만 **순간값**이라 흔들린다.
> 평균을 보려면 위 방식이 낫다.

> 🚨 **재기 전에 반드시 확인할 것 — `timeScale`**
> 강사가 처음 잴 때 **레벨업 창이 열려 있었다.** `timeScale = 0` 이라 게임이 멈춘 상태였고,
> "몬스터 4764마리인데 458 FPS!" 라는 **엉터리 결과**가 나왔다.
> 💬 "멈춘 게임은 당연히 빠릅니다. **측정 전에 상태를 확인하세요.**"

### ② 렉을 만든다 (10분)

`WaveManager` 의 `SpawnOne()` 을 반복해서 부른다. (인스펙터 우클릭 → `한 마리 소환`)

또는 테스트용으로 `spawnInterval` 을 `0.02` 로 줄여 본다.

▶ 몬스터가 쌓이는 걸 보며 FPS 를 잰다.

| 살아 있는 몬스터 | 평균 FPS |
|---|---|

| 1802 | 263.0 |

> 💬 "3668마리에서 **45 FPS.** 열 배 가까이 느려졌습니다."

> 💡 숫자는 컴퓨터마다 다르다. **곡선의 모양이 같으면 된다.**

### ④ 프로파일러를 연다 (10분)

`Window → Analysis → Profiler` → Play → **CPU Usage** 를 본다.

| 항목 | 뜻 |
|---|---|
| **PlayerLoop** | 게임 코드 전체 |
| `FixedUpdate` | 물리. 몬스터 `Move()` 가 여기 있다 |
| `Rendering` | 그리기 |
| **GC.Alloc** | **쓰레기가 생긴 양** ← 오늘의 관심사 |

> 💬 "몬스터가 3000마리면 `FixedUpdate` 가 **3000번** 돕니다. 매 프레임에요."
> 💬 "그리고 만들 때마다 `Instantiate`, 죽을 때마다 `Destroy` 를 합니다."

### ⑤ 🔑 원인은 두 가지다 (10분) — 오늘의 핵심

**강사가 두 가지를 따로 재봤다.**

**(가) 오브젝트가 많아서** — 위 ③ 표. 개수가 늘면 프레임이 떨어진다.

**(나) 만들고 버리는 비용** — 500개씩 재봤다.

```
Instantiate 500개 : 9.2 ms   (1개당 18 µs)
Destroy     500개 : 2.0 ms   (1개당  4 µs)
합계 11.2 ms → 60FPS 한 프레임(16.7ms) 기준 0.7프레임 분량
관리 힙 4 KB 증가

SetActive 껐다 켜기 500개 : 2.6 ms  (1개당 5 µs)   힙 0 KB
```

> 🔑 💬 "만들고 버리는 건 **1개당 22 µs**, 껐다 켜는 건 **5 µs.**"
> 💬 "**4배 넘게 차이납니다.** 그리고 껐다 켜기는 **쓰레기가 0** 이에요."

> 🚨 💬 "그런데 여기서 중요한 게 있습니다."
> 💬 "우리 게임은 1초에 몇 마리나 만들까요?" → 웨이브가 올라도 **초당 2~3마리** 정도다.
> 💬 "초당 3마리면 **66 µs**입니다. 한 프레임이 16700 µs 인데요."
>
> 🔑 💬 "**즉, 만들고 버리는 비용은 우리 게임에서 프레임을 안 잡아먹습니다.**"
> 💬 "프레임을 잡아먹는 건 **개수**예요."

**칠판**

```
느려지는 원인 두 가지

(가) 오브젝트가 많다        →  프레임을 직접 잡아먹는다   ← 우리 게임의 진짜 원인
(나) 만들고 버리기가 비싸다  →  1개당 22µs. 쓰레기가 쌓인다

풀링(102·103)은 (나) 를 고친다.
(가) 는 개수에 상한을 걸어야 고쳐진다.
```

> 💬 "그래서 다음 두 회차에 **둘 다** 합니다."
> 💬 "풀링만 하고 '왜 여전히 느리지?' 하면 곤란하잖아요."

<details>
<summary>막히면 열기 (정답)</summary>

```csharp
private void Update()
{
    frames++;
    elapsed += Time.unscaledDeltaTime;   // 멈춰도 재야 하니 unscaled

    if (elapsed < 0.5f) return;

    float fps = frames / elapsed;

    if (label != null)
        label.text = $"{fps:F0} FPS   몬스터 {Enemy.AliveCount}";

    frames = 0;
    elapsed = 0f;
}
```

> 💡 `Enemy.AliveCount` 는 103회차에서 만든다. 오늘은
> `Object.FindObjectsByType<Enemy>(FindObjectsSortMode.None).Length` 를 써도 된다.
> 다만 **이 함수 자체가 무겁다.** 0.5초에 한 번만 부르는 이유가 그것이다.

**몬스터를 많이 만드는 법**
`WaveManager` 인스펙터 우클릭 → `한 마리 소환` 을 여러 번. 또는 `Spawn Interval` 을 `0.02` 로.
**측정이 끝나면 반드시 되돌린다.**

**플레이어가 즉사해서 못 재면**
`PlayerHealth` 의 `Max Health` 를 `9999` 로 잠깐 올린다. **되돌리는 걸 잊지 않는다.**

</details>
