## 00:10–00:40 · 같이 하기 ① 밸런싱

### 목표는 하나 — "10분이 지루하지도 불가능하지도 않게" (30분)

089회차에서 만든 SO 를 그대로 쓴다. **코드는 안 고친다.**

| 확인할 것 | 어디 |
|---|---|
| 1분에 죽으면 | 너무 어렵다 |
| 10분에 상처 하나 없으면 | 너무 쉽다 |
| 보스를 못 잡으면 | 보스 체력 ↓ 또는 무기 피해 ↑ |
| 레벨업이 안 뜨면 | `baseExp` ↓ |
| 레벨업이 너무 자주 뜨면 | `expStep` ↑ |

**주로 만지는 값**

| 파일 | 값 |
|---|---|
| `Enemy_Charger/Runner/Tank` | 체력 · 피해 · 속도 |
| `Boss_1/2/3` | 체력 |
| `WeaponData` | 칼 피해 · 총 간격 · 총 피해 |
| `PlayerLevel` | `baseExp` `expStep` |
| `WaveManager` | `spawnInterval` `waveDuration` `maxAlive` `bossTimes` |

> 💬 "**한 번에 하나만 바꾸세요.** 세 개를 동시에 바꾸면 뭐가 효과였는지 모릅니다."

> 💡 **테스트할 땐 `bossTimes` 를 `{40, 80, 120}` 으로 줄인다.**
> **제출 전에 `{180, 360, 600}` 으로 되돌리는 걸 잊지 않는다.** (090 회수)

## 00:50–01:30 · 같이 하기 ② 빌드 ★

### ① Build Settings — 켤 씬을 고른다 (8분)

`File → Build Profiles` (또는 `Build Settings`)

> 🚨 **연습 씬이 목록에 잔뜩 들어 있을 것이다.** 체크를 **끈다.**
> 지우지 말고 **체크만 끈다.** 나중에 다시 볼 일이 있다.

| 켬 | 씬 |
|---|---|
| ✅ | `Title` (0번) |
| ✅ | `Game` (1번) |
| ✅ | `Result` (2번) |
| ❌ | 나머지 연습 씬 전부 |

**실측** — 강사가 재본 값

| | 씬 15개 켬 | 씬 3개만 켬 |
|---|---|---|
| 빌드 시간 | **64.0초** | 7.0초 (두 번째 빌드) |
| 빌드 크기 | 105 MB | **105 MB** |

> 💬 "**크기는 안 줄었죠.**" — 105 MB 중 대부분은 유니티 엔진 자체(`UnityPlayer.dll` 35 MB 등)다.
> 💬 "그래도 **연습 씬은 끕니다.** 학생 게임에 벽돌깨기가 들어가 있을 이유가 없어요."

### ② Player Settings — 게임의 이름표 (10분)

`Edit → Project Settings → Player`

| 항목 | 우리 값 | 뜻 |
|---|---|---|
| **Company Name** | `WaveBreaker Class` | 저장 폴더 이름이 된다 |
| **Product Name** | `웨이브 브레이커` | **창 제목**에 뜬다 |
| Default Screen Width / Height | `1280` / `720` | 처음 열릴 때 크기 |
| **Fullscreen Mode** | `Windowed` | 창 모드로 시작 |
| **Resizable Window** | ✅ | 창 크기를 바꿀 수 있다 |
| Run In Background | ✅ | 창을 클릭 안 해도 계속 돈다 |

> 💬 "**091~092에서 해상도 대응을 해뒀죠.** 그래서 창 크기를 바꿔도 UI 가 안 깨집니다."
> 💬 "그걸 안 했으면 여기서 Resizable 을 못 켭니다."

**Other Settings → Scripting Backend**

| 백엔드 | 빌드 속도 | 실행 속도 |
|---|---|---|
| **Mono** | **빠르다** | 보통 |
| IL2CPP | **아주 느리다** (수십 분) | 빠르다 |

> 🚨 **수업에서는 `Mono` 를 쓴다.** IL2CPP 로 두면 빌드에 20~40분이 걸려 회차가 날아간다.
> 💬 "나중에 진짜로 배포할 땐 IL2CPP 를 씁니다. 오늘은 아니에요."

**저장 폴더가 어디 생기나**

```
C:\Users\<이름>\AppData\LocalLow\<Company Name>\<Product Name>\
    └ Player.log        ← 실행 중 로그. 문제가 나면 여기를 본다
```

### ③ 빌드 (12분)

`File → Build And Run` (또는 `Build`)

**저장 위치**

```
프로젝트폴더\Builds\WaveBreaker_Single\
```

> 🚨 **`Assets` 폴더 안에 빌드하면 안 된다.** 유니티가 그걸 다시 에셋으로 읽으려 든다.
> 프로젝트 폴더 **바깥이나 옆**에 만든다.

**강사가 실제로 빌드한 결과**

```
결과      = Succeeded
걸린 시간 = 64.0초
빌드 크기 = 105 MB   (파일 203개)
에러 0  경고 0
WaveBreaker.exe = 652 KB
```

**폴더 안에 뭐가 들어 있나**

| 파일/폴더 | 크기 | 뭔가 |
|---|---|---|
| `WaveBreaker.exe` | 0.64 MB | **실행 파일.** 이걸 더블클릭한다 |
| `UnityPlayer.dll` | 35.4 MB | 유니티 엔진 본체 |
| `WaveBreaker_Data\` | 대부분 | 씬·이미지·소리 |
| `UnityCrashHandler64.exe` | 1.7 MB | 죽었을 때 기록 |
| `MonoBleedingEdge\` | | C# 실행기 (Mono) |

> 🔑 💬 "**폴더를 통째로 줘야 합니다.** `.exe` 만 보내면 안 돌아가요."
> 💬 "친구한테 보낼 땐 **폴더를 압축**해서 보냅니다."

### ④ 실행 확인 (8분)

▶ `WaveBreaker.exe` 를 더블클릭.

**강사가 확인한 것**

```
프로세스 시작됨    8초 뒤 살아있음 = True
메모리 = 594 MB
Player.log — 에러 없음, 물리(PhysX)·입력 초기화 정상
```

**확인할 것**

- [ ] 창 제목이 **웨이브 브레이커**
- [ ] 타이틀 화면이 뜬다
- [ ] [시작] 을 누르면 게임이 된다
- [ ] 창 크기를 바꿔도 UI 가 안 깨진다
- [ ] `Alt` + `F4` 로 꺼진다

> 🚨 **검은 화면만 나오면** Build Settings 에 씬이 없는 것이다. 0번이 `Title` 인지 본다.
