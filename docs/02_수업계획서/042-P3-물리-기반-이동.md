### ② Rigidbody를 코드에 연결한다 (8분)

`Player`에 `Rigidbody 2D`를 붙인다. **`Gravity Scale = 0`**, **`Constraints → Freeze Rotation Z` 체크.**

> ⚠️ **이 두 개는 오늘 반드시 같이 한다.**
> `Gravity Scale`을 안 내리면 캐릭터가 화면 아래로 떨어지고,
> `Freeze Rotation Z`를 안 걸면 벽에 스치는 순간 **캐릭터가 빙글빙글 돈다.**

새 스크립트 `PlayerPhysicsMove` 를 만든다.

```csharp
using UnityEngine;

public class PlayerPhysicsMove : MonoBehaviour
{
    [SerializeField] private float moveSpeed = 5f;
    [SerializeField] private Rigidbody2D rb;      // Inspector 에서 끌어다 넣는다

    void Update()
    {
        Debug.Log(rb.linearVelocity);
    }
}
```

**Inspector의 `Rb` 칸에 `Player` 자신을 드래그해 넣는다.**

> 💬 "040회차에 `Item` 칸에 오브젝트를 끌어다 넣었죠. **똑같습니다.**"
> 💬 "다른 점 하나. 칸의 타입이 `GameObject`가 아니라 **`Rigidbody2D`** 예요.
> 그래서 오브젝트를 끌어다 놓으면 유니티가 **그 오브젝트에 붙은 `Rigidbody 2D`를 알아서 찾아** 넣습니다."

> ⚠️ **드래그하는 대상은 Hierarchy의 `Player` 자기 자신**이다. "자기 걸 자기한테 넣는다"가
> 어색해서 멈칫하는 학생이 많다. 화면 공유로 천천히 한 번 보여준다.
>
> 💡 코드로 찾는 방법(`GetComponent`)은 **046회차**다. "그때 이 드래그가 없어집니다."

### ③ `linearVelocity` — 속도를 넣는다 (12분) — 오늘의 핵심

```csharp
using UnityEngine;

public class PlayerPhysicsMove : MonoBehaviour
{
    [SerializeField] private float moveSpeed = 5f;
    [SerializeField] private Rigidbody2D rb;

    void Update()
    {
        float h = Input.GetAxisRaw("Horizontal");
        float v = Input.GetAxisRaw("Vertical");

        rb.linearVelocity = new Vector2(h, v) * moveSpeed;
    }
}
```

▶ Play → **움직인다. 그리고 벽에서 멈춘다.**

> 🎉 여기서 시간을 준다. 벽에 밀어붙여 보게 한다. 040과 체감이 완전히 다르다.

**두 가지를 반드시 짚는다.**

| 짚을 것 | 설명 |
|---|---|
| `Vector2` | `Vector3`가 아니라 **`Vector2`**. 2D 물리는 z를 안 쓴다 |
| `Time.deltaTime`이 **없다** | `linearVelocity`는 **위치가 아니라 속도**다 |

> 💬 "039회차에 `Time.deltaTime`을 곱했죠. **오늘은 안 곱합니다.** 왜일까요?"
> 💬 "`linearVelocity`는 **'1초에 얼마나 갈지'** 를 넣는 칸이에요. 이미 **'1초에'** 가 들어 있습니다."
> 💬 "**위치를 넣으면 `deltaTime`을 곱하고, 속도를 넣으면 안 곱합니다.** 이거 하나만 기억하세요."

| 무엇을 넣나 | `deltaTime` | 예 |
|---|---|---|
| **위치** (`transform.position`) | **곱한다** | 038 · 039 · 040 |
| **속도** (`rb.linearVelocity`) | **안 곱한다** | 오늘 |

> ⚠️ **Unity 6에서 이름이 바뀐 항목이다.** 인터넷 자료에는 전부 **`rb.velocity`** 로 나온다.
> 💬 "검색하면 `velocity`라고 나올 거예요. **유니티 6에서 `linearVelocity`로 바뀌었습니다.**
> `velocity`로 쓰면 노란 경고가 뜨는데, 그게 '이름 바뀌었다'는 뜻입니다."

### ④ `FixedUpdate` — 왜 메서드가 하나 더 있나 (8분)

`Update`를 `FixedUpdate`로 **이름만** 바꾼다.

```csharp
void FixedUpdate()
{
    float h = Input.GetAxisRaw("Horizontal");
    float v = Input.GetAxisRaw("Vertical");

    rb.linearVelocity = new Vector2(h, v) * moveSpeed;
}
```

▶ Play → **똑같이 움직인다.** 겉으로는 차이가 없다. 그래서 **왜 바꾸는지**를 말로 짚는다.

| | 언제 | 몇 번 | 쓰는 것 |
|---|---|---|---|
| `Update` | 화면 한 장마다 | 컴퓨터마다 **다르다** (60번? 144번?) | **입력** 읽기, 화면 관련 |
| `FixedUpdate` | **정해진 시간마다** | 누구든 **1초에 50번** | **물리** (Rigidbody 만지는 것) |

> 💬 "화면은 컴퓨터마다 몇 장 그리는지 다릅니다. 그런데 **물리 계산까지 컴퓨터마다 다르면** 게임이 달라져요."
> 💬 "그래서 유니티는 물리용 시계를 **따로** 돌립니다. 그게 `FixedUpdate`고, **누구 컴퓨터에서든 1초에 50번**입니다."
> 💬 "규칙 하나: **`rb.` 으로 시작하는 줄은 `FixedUpdate`에.** 나머지는 `Update`에."

> ⚠️ **`Input.GetKeyDown`은 `FixedUpdate`에 쓰면 씹힌다.** 오늘 코드는 `GetAxisRaw`라
> 안 씹히지만, 학생이 스페이스 발사를 `FixedUpdate`에 넣으면 반응이 이상해진다.
> **"눌린 순간을 잡는 건 `Update`에"** 를 미리 한 번 말해둔다. (046회차 총알 발사에서 다시 나온다)

> 💡 **`Interpolate`** 를 묻는 학생이 있으면: "`Rigidbody 2D`의 `Interpolate`를 `Interpolate`로 바꾸면
> 움직임이 부드러워집니다. 50번을 60장에 나눠 그려주는 거예요." 까지만. 켜보게는 한다.

## 01:35–01:50 · 데모 + 정리

학생 2명 데모. `AddForce`를 해본 학생(⭐도전)이 있으면 반드시 보여주게 한다.
미끄러지는 조작감을 다 같이 보는 게 `linearVelocity`의 의미를 굳힌다.

**마무리 정리 (한 장)**

| | 040까지 | 오늘부터 |
|---|---|---|
| 누가 옮기나 | **내가** 좌표를 대입 | **물리 엔진**에게 부탁 |
| 코드 | `transform.position = ...` | `rb.linearVelocity = ...` |
| 어디에 쓰나 | `Update` | **`FixedUpdate`** |
| `Time.deltaTime` | **곱한다** | **안 곱한다** |
| 벽을 만나면 | **통과한다** | **멈춘다** |

> 💬 "표의 맨 아랫줄이 오늘의 이유입니다. **벽에서 멈추려고** 방식을 바꾼 거예요."
