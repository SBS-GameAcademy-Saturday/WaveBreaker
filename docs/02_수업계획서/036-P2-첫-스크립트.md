### ① 스크립트 만들기 (7분)

`Project` 창 → `Assets/_Project/Scripts/Practice/` → 우클릭 → **Create → Scripting → MonoBehaviour Script**

이름: **`HelloUnity`** ← 만드는 즉시 이름을 정한다

> 🚨 **오늘 최다 사고 예고. 여기서 못을 박는다.**
> 💬 "**파일 이름과 클래스 이름이 다르면 스크립트가 안 붙습니다.**"
> 💬 "그래서 만들자마자 이름을 정하세요. 나중에 파일명만 바꾸면 **안 붙습니다.**"
>
> 강사가 **일부러 재현한다**: 파일명을 `Test`로 바꿔서 드래그 → `Can't add script behaviour` 오류를 보여준다.
> 💬 "이 에러 오늘 반드시 봅니다. 보면 **파일 지우고 다시 만드는 게 제일 빨라요.** 이름 고치는 것보다 빠릅니다."

### ② 콘솔 코드와 나란히 놓기 (8분) — 오늘의 핵심

더블클릭해서 열면 이렇게 생겼다.

```csharp
using UnityEngine;

public class HelloUnity : MonoBehaviour
{
    void Start()
    {

    }

    void Update()
    {

    }
}
```

**6주차 콘솔 코드를 옆에 띄우고 비교한다.**

| 콘솔에서 (5~6주차) | 유니티에서 (오늘) | 같은 것 |
|---|---|---|
| `class Enemy` | `class HelloUnity` | **똑같은 클래스** |
| `: 아무것도 없음` | `: MonoBehaviour` | **상속** (6주차에 배웠다) |
| `void Attack()` | `void Start()` | **똑같은 메서드** |
| 내가 `Main`에서 호출 | **유니티가 알아서 호출** | 부르는 사람만 다르다 |

> 💬 "새로 배우는 거 하나도 없습니다. **클래스, 상속, 메서드** — 전부 5~6주차에 한 거예요."
> 💬 "딱 하나 다른 건, `Start`랑 `Update`는 **여러분이 부르지 않아도 유니티가 알아서 불러준다**는 겁니다."

> ⚠️ `MonoBehaviour`가 뭐냐고 물으면: **"컴포넌트가 되게 해주는 부모 클래스"** 까지만.
> 상속 구조를 더 파고들면 오늘 목표가 날아간다. "6주차 상속 기억나죠? 그거예요."

### ③ Start — 한 번만 (7분)

```csharp
void Start()
{
    Debug.Log("안녕하세요, 유니티 / Start 는 한 번만 실행됩니다.");
}
```

저장(`Ctrl+S`) → **유니티로 전환** → 잠깐 기다림 → `HelloUnity`를 `Box`에 드래그 → ▶ Play

Console에 **한 줄** 찍힌다.

> ⚠️ **"저장 → 유니티로 전환 → 잠깐 기다림"** 이 3단계를 오늘 최소 3번 소리 내어 반복한다.
> 저장 안 하고 Play해서 "안 나와요"가 반드시 나온다.
>
> 💬 "`Debug.Log`는 콘솔의 `Console.WriteLine` 자리입니다. **찍히는 곳만 바뀐 거예요.**"

### ④ Update — 매 프레임 (8분)

```csharp
void Update()
{
    Debug.Log("Update!");
}
```

▶ Play → **Console이 순식간에 잠긴다.** 이걸 일부러 보여준다.

> 💬 "몇 번 찍힌 걸까요?" → Console 우측 숫자를 보여준다. 수백 번.
> 💬 "`Update`는 **화면이 한 장 그려질 때마다** 실행됩니다. 1초에 60번쯤이에요."

**그래서 세는 걸로 바꾼다.**

```csharp
using UnityEngine;

public class HelloUnity : MonoBehaviour
{
    [SerializeField] private string greeting = "안녕하세요, 유니티";

    private int updateCount;

    void Start()
    {
        Debug.Log(greeting + " / Start 는 한 번만 실행됩니다.");
    }

    void Update()
    {
        updateCount++;

        if (updateCount % 60 == 0)
        {
            Debug.Log("Update 가 " + updateCount + "번 실행됐습니다.");
        }
    }
}
```

> 💬 "`%`는 나머지죠. 3주차에 배웠습니다. **60번에 한 번만** 찍으라는 뜻이에요."
> 💬 "`updateCount++`도 3주차 반복문에서 썼던 그거예요."

`[SerializeField]`가 붙은 `greeting`이 **Inspector에 보인다**는 것만 짚고 넘어간다.

> 💬 "저건 다음 시간 주제입니다. 오늘은 '보이네?'만 확인하세요."

```csharp
using UnityEngine;

public class MyFirstScript : MonoBehaviour
```

### ⭐ 도전 미션

- [ ] `Debug.LogWarning` / `Debug.LogError`를 써보고 Console 색이 어떻게 다른지 확인한다
- [ ] Console 우측 위 **Collapse** 버튼을 켜고 뭐가 달라지는지 한 줄로 쓴다
- [ ] `Awake()` 메서드를 추가하고 `Start`와 **어느 쪽이 먼저 찍히는지** 확인한다

- [ ] `%` 값을 1로 바꿔보고 Console이 어떻게 되는지 본다 (그리고 되돌린다)

## 🚨 흔한 사고 & 대응 (강사용)

| 에러/상황 | 진짜 원인 | 대응 |
|---|---|---|
| **`Can't add script behaviour`** | **파일명 ≠ 클래스명** | **오늘 1등.** 파일을 지우고 다시 만든다. 이름 고치기보다 빠르다 |
| 코드를 고쳤는데 반영 안 됨 | 저장 안 함 / 컴파일 대기 중 | "저장 → 유니티 전환 → **잠깐 기다림**" 3단계 |
| Console에 아무것도 안 뜸 | 스크립트를 안 붙임 | Inspector에 스크립트가 보이는지 확인 |
| Console이 잠김 | `Update`에서 매 프레임 로그 | **의도된 시연.** `%`로 줄인다 |
| 우측 하단에 빙글빙글 아이콘 | 컴파일 중 | "저게 돌면 기다리세요" |
| 빨간 줄이 뜨는데 안 읽음 | 에러 읽는 습관 없음 | **더블클릭하면 그 줄로 간다**는 걸 알려준다 |
| `;` 빠뜨림 | 1주차 그대로 | "1주차에 했죠" — 콘솔 감각을 계속 연결한다 |
| 대소문자 틀림 (`debug.log`) | C# 대소문자 구분 | "C#은 대소문자를 구분합니다. 1주차 그대로" |
| `MonoBehaviour`가 뭐냐고 물음 | 좋은 질문 | "컴포넌트가 되게 해주는 부모"까지만. 깊이 안 간다 |
| 스크립트를 Project 창에서 Inspector로 드래그 | 붙는 대상이 Hierarchy 오브젝트 | **Hierarchy의 오브젝트 위에** 놓게 한다 |
