## 🎯 오늘의 목표

1. 젬을 먹으면 **경험치가 쌓인다**
2. 필요한 만큼 모이면 **레벨이 오른다**
3. **레벨업 곡선**을 숫자 두 개로 설계한다

> ⚠️ **오늘 안 하는 것**: 시간 정지(084), 카드 선택(085).
> 레벨은 오르지만 **아직 강해지지는 않는다.** Console 과 HUD 에 숫자만 오른다.
>
> 🔑 **설계 의도**: 오늘의 코드는 짧다. 대신 **"몇 개 모아야 오를까"** 에 시간을 쓴다.
> 숫자 두 개(`baseExp` · `expStep`)로 **한 판의 리듬 전체**가 정해진다.
> 게임 디자인이 코드가 아니라 **숫자**라는 걸 처음 제대로 겪는 회차다.

### ② 레벨업 곡선 (14분) — 오늘의 핵심

> 💬 "몇 개 모으면 레벨이 오를까요? **5개?** 그럼 다음 레벨도 5개?"
> 💬 "그러면 10레벨이든 100레벨이든 똑같이 5개입니다. **후반이 너무 쉬워져요.**"

**칠판 — 세 가지 방식**

```
① 고정        5, 5, 5, 5, 5 …            → 후반이 너무 쉽다
② 더하기      5, 8, 11, 14, 17 …          → 완만하게 어려워진다  ★ 오늘 쓰는 것
③ 곱하기      5, 10, 20, 40, 80 …         → 금방 벽에 부딪힌다
```

> 💬 "**② 더하기**를 씁니다. 레벨마다 **일정하게** 더 필요해져요."
> 💬 "식으로 쓰면 이렇습니다."

```
다음 레벨까지 필요한 경험치 = baseExp + (Level - 1) × expStep
```

| Level | 계산 | 필요 경험치 |
|---|---|---|
| 1 | `5 + 0 × 3` | **5** |
| 2 | `5 + 1 × 3` | **8** |
| 3 | `5 + 2 × 3` | **11** |
| 4 | `5 + 3 × 3` | **14** |

```csharp
[SerializeField] private int baseExp = 5;
[SerializeField] private int expStep = 3;

public int NeedExp => baseExp + (Level - 1) * expStep;
```

> 🔑 **`=>` 는 "계산해서 돌려주는 값"** 이다.
> 💬 "`NeedExp` 는 **저장하는 값이 아닙니다.** 물어볼 때마다 계산해요."
> 💬 "레벨이 오르면 자동으로 값이 바뀝니다. 따로 갱신할 필요가 없어요."

### ③ 레벨을 올린다 (10분)

```csharp
public void AddExp(int amount)
{
    Exp += amount;

    // 한 번에 두 레벨이 오를 수도 있다. while 로 돌린다.
    while (Exp >= NeedExp)
    {
        Exp -= NeedExp;
        Level++;

        Debug.Log($"레벨 업!  Lv.{Level}  (다음까지 {NeedExp})");
    }
}
```

▶ Play → 젬을 모으면 —

```
레벨 업!  Lv.2  (다음까지 8)
레벨 업!  Lv.3  (다음까지 11)
```

**한 조각씩 짚는다.**

| 조각 | 뜻 |
|---|---|
| `Exp -= NeedExp` | **쓴 만큼 뺀다.** 남은 건 다음 레벨로 |
| `while` (`if` 아님) | 한 번에 **두 레벨**이 오를 수 있다 |
| `NeedExp` 가 순서대로 | `Level++` 뒤엔 **이미 새 값**이다 |

> 🚨 **`if` 로 쓰면 젬을 20개 한 번에 먹어도 레벨이 1만 오른다.**
> 일부러 `if` 로 바꿔 `AddExp(100)` 을 해보여준다.

> 🚨 **`Exp = 0` 으로 만들면 남는 경험치가 사라진다.**
> `-=` 를 써야 초과분이 다음 레벨로 넘어간다. 061에서 목숨을 깎던 것과 같은 이야기다.

> 💡 **한 번에 두 레벨이 오르면?** 지금은 **카드가 한 번만** 뜬다(085).
> 두 번 뜨게 만들 수도 있지만 지금은 그럴 필요가 없다. **간단한 게 낫다.**

### ⑤ 곡선을 바꿔본다 (2분)

| `baseExp` | `expStep` | 느낌 |
|---|---|---|
| `5` | `3` | 초반에 빠르게, 갈수록 완만 — **기본값** |
| `3` | `1` | 레벨이 계속 팡팡 오른다 |
| `10` | `10` | 3레벨부터 거의 안 오른다 |

### ⭐ 도전 미션 — 곡선을 직접 설계한다

- [ ] `AddExp(100)` 을 한 번 불러 **레벨이 여러 번 오르는지** 확인한다
- [ ] `while` 을 `if` 로 바꿔보고 위를 다시 해본다 — 차이를 쓴다
- [ ] 곡선을 **곱하기**로 바꿔본다 (`baseExp * Level`)
- [ ] `baseExp` / `expStep` 을 바꿔 **"5분에 10레벨"** 이 되게 맞춰본다
- [ ] 레벨업할 때 Console 대신 **화면 가운데**에 크게 띄운다 (080의 `centerLabel`)
- [ ] 경험치 바(Image `fillAmount`)를 만든다
- [ ] 최고 레벨을 기록해뒀다가 게임오버 화면에 보여준다

## 01:35–01:50 · 데모 + 정리

학생 3명 데모. **자기가 정한 곡선 숫자와 이유**를 말하게 한다.

**마무리 정리 (한 장)**

| 오늘 배운 것 | |
|---|---|
| 누적과 소비 | `Exp += amount` → `Exp -= NeedExp` |
| `while` (`if` 아님) | 한 번에 여러 레벨 |
| 계산 프로퍼티 `=>` | 저장 안 하고 물어볼 때 계산 |
| 곡선 = 숫자 두 개 | `baseExp` · `expStep` |

> 💬 "게임 디자인은 **코드가 아니라 숫자**입니다."
> 💬 "같은 코드로 완전히 다른 게임이 나와요. 숫자만 바꾸면요."

| 에러/상황 | 진짜 원인 | 대응 |
