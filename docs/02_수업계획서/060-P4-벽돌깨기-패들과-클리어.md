## 00:10–00:45 · 같이 치기 ★

### ① 패들 — 055에서 만든 그 코드 (9분)

`060_Breakout_Start` 를 연다. 059 완성 상태(블록 + 튀는 공)다.

바닥 근처에 가로로 긴 Square를 놓고 이름 **`Paddle`**.

| 항목 | 값 |
|---|---|
| Scale | `(2.5, 0.4, 1)` |
| `Box Collider 2D` | `Is Trigger` **끔** |
| `Rigidbody 2D` | **`Kinematic`** ← 공에 밀리면 안 된다 |

> 🚨 **`Kinematic` 이 오늘 첫 번째 함정**이다.
> 💬 "`Dynamic`으로 두면 **공에 맞아서 패들이 밀려납니다.** 041에서 배운 Body Type 기억나죠?"
> 💬 "**내가 조종하는 것, 물리에 밀리면 안 되는 것 → Kinematic.**"

```csharp
using UnityEngine;

public class Paddle : MonoBehaviour
{
    [SerializeField] private float moveSpeed = 10f;
    [SerializeField] private float limitX = 7f;

    void Update()
    {
        float h = Input.GetAxisRaw("Horizontal");

        Vector3 pos = transform.position;

        pos.x = pos.x + h * moveSpeed * Time.deltaTime;
        pos.x = Mathf.Clamp(pos.x, -limitX, limitX);

        transform.position = pos;
    }
}
```

> 💬 "**055에서 여러분이 만든 그거**입니다. `v`를 빼서 좌우로만 움직이게 한 거요."
> 💬 "다른 점 하나 — **`Mathf.Clamp`** 로 화면 밖으로 못 나가게 막았습니다."

| 조각 | 뜻 | 어디서 |
|---|---|---|
| `Input.GetAxisRaw("Horizontal")` | 좌우 입력 | **040** |
| `h * moveSpeed * Time.deltaTime` | 1초에 `moveSpeed` 만큼 | **039** |
| `Mathf.Clamp(값, 최소, 최대)` | 범위 밖으로 못 나가게 자른다 | **050** (체력에서 썼다) |

> 💡 **왜 `linearVelocity`가 아니라 `transform.position`인가**를 묻는 학생이 있다.
> 💬 "패들은 **Kinematic이라 물리가 안 밀어줍니다.** 그래서 직접 옮깁니다. 좋은 질문이에요."
> 💬 "정석은 `rb.MovePosition`인데 지금은 이걸로 충분합니다."

▶ Play → 좌우로 움직이고, **공이 패들에 튄다.**

### ② 공을 놓치면 (9분)

화면 **아래쪽**에 가로로 긴 빈 Square를 놓는다. 이름 **`DeadZone`**.

| 항목 | 값 |
|---|---|
| `Box Collider 2D` | **`Is Trigger` 켬** ← 통과하면서 알아채기만 |
| Tag | **`DeadZone`** (새로 만든다) |
| `Sprite Renderer` | **제거하거나 끈다** (안 보이게) |

`Ball` 에 추가한다.

```csharp
private void OnTriggerEnter2D(Collider2D other)
{
    if (other.CompareTag("DeadZone"))
    {
        Destroy(gameObject);
    }
}
```

> 💬 "**043의 동전과 같은 구조**입니다. 막지 않고 통과하면서 알아채기만 하죠."
> 💬 "그래서 이건 `Trigger`, 블록은 `Collision`. **한 스크립트에 둘 다 있어도 됩니다.**"

▶ Play → 공을 놓치면 **사라진다.**

### ③ 게임오버와 클리어 (13분) — 오늘의 핵심

**057의 `DodgeGameManager`를 옆에 띄운다.**

```csharp
using UnityEngine;
using UnityEngine.SceneManagement;
using System.Collections;
using TMPro;

public class BreakoutManager : MonoBehaviour
{
    [SerializeField] private TextMeshProUGUI resultText;
    [SerializeField] private GameObject ball;

    private bool isOver;

    void Start()
    {
        StartCoroutine(CheckClearRoutine());
    }

    void Update()
    {
        if (isOver)
        {
            if (Input.GetKeyDown(KeyCode.R))
            {
                Time.timeScale = 1f;
                SceneManager.LoadScene(SceneManager.GetActiveScene().name);
            }
            return;
        }

        if (ball == null)
        {
            Finish("게임 오버  —  R 키로 다시");
        }
    }

    private IEnumerator CheckClearRoutine()
    {
        while (true)
        {
            yield return new WaitForSeconds(0.5f);

            if (GameObject.FindGameObjectsWithTag("Brick").Length == 0)
            {
                Finish("클리어!  —  R 키로 다시");
            }
        }
    }

    private void Finish(string message)
    {
        if (isOver) return;

        isOver = true;

        resultText.text = message;
        resultText.gameObject.SetActive(true);

        Time.timeScale = 0f;
    }
}
```

**057과 나란히 놓고 같은 줄을 짚는다.**

| 하는 일 | 057 (피하기) | 060 (벽돌깨기) |
|---|---|---|
| 죽음 감지 | `player == null` | **`ball == null`** |
| 한 번만 | `isGameOver` | `isOver` |
| 멈춤 | `Time.timeScale = 0` | **똑같다** |
| 재시작 | `LoadScene(...)` | **똑같다** |
| 끝나는 방법 | 죽음 하나 | **죽음 + 클리어 둘** |

> 💬 "**거의 그대로죠.** 게임이 완전히 다른데 뼈대는 같습니다."
> 💬 "057에서 말한 네 줄 — **시작 · 진행 · 끝 · 다시**. 그게 게임의 뼈대예요."

**클리어 판정은 왜 코루틴인가.**

> 💬 "`FindGameObjectsWithTag`는 **씬 전체를 뒤지는** 무거운 함수입니다. 매 프레임 하면 안 돼요."
> 💬 "**0.5초에 한 번**이면 충분하죠. 사람 눈에는 즉시로 보입니다."
> 💬 "051에서 배운 코루틴이 **여기서 이렇게 쓰입니다.** 시간차가 필요한 건 전부 이걸로요."

> ⚠️ **`Finish`에 `if (isOver) return;` 이 있는 이유**를 짚는다.
> 💬 "게임오버랑 클리어가 **거의 동시에 일어날 수 있습니다.** 마지막 블록을 깨면서 공을 놓치면요."
> 💬 "먼저 온 걸로 끝냅니다. **먼저 들어온 사람이 임자.**"
