### ② `position` 과 `localPosition` (6분) — 033의 약속을 지키는 자리

> 💬 "033회차에 **월드 좌표와 로컬 좌표**를 배웠죠. 그게 코드에서는 이렇게 생겼습니다."

```csharp
Debug.Log("월드: " + transform.position);
Debug.Log("로컬: " + transform.localPosition);
```

**부모가 없는 물체에 붙여 본다.** 두 값이 **똑같이** 나온다.

> 💬 "부모가 없으면 로컬 기준이 곧 월드 원점이에요. 그래서 같습니다."

**이제 이 물체를 다른 물체의 자식으로 만들고** 다시 Play한다. **두 값이 달라진다.**

| 코드 | 뜻 | Inspector 에서 |
|---|---|---|
| `transform.position` | **월드 좌표** | 부모가 없을 때 보이던 그 값 |
| `transform.localPosition` | **로컬 좌표** | 부모가 있을 때 보이던 그 값 |

> 🔑 **이름이 그대로다.** `local`이 붙으면 로컬, 안 붙으면 월드.
> 💬 "Inspector에 뜨는 건 **항상 로컬**입니다. 부모가 없으면 그게 곧 월드인 거고요."
>
> ⚠️ **오늘 코드로 움직일 때는 `position`(월드)을 쓴다.** 지금 만드는 물체는 부모가 없어서
> 어느 쪽을 써도 결과가 같지만, **월드로 생각하는 습관**을 먼저 들인다.
> 로컬로 움직여야 하는 상황은 Phase 5(총구 위치)에서 나온다.

### ③ `Vector3` — 좌표 세 개 묶음 (7분)

> 💬 "`(2, 3, 0)` — 이게 하나짜리 값처럼 보이죠? 실제로 **숫자 세 개를 묶은 것**이고, 이름이 `Vector3`입니다."

```csharp
Vector3 myPos = new Vector3(1f, 2f, 0f);
transform.position = myPos;
```

| 쓰는 것 | 뜻 |
|---|---|
| `Vector3` | 숫자 **3개** 묶음 (x, y, z) |
| `Vector2` | 숫자 **2개** 묶음 (x, y) |
| `new Vector3(1f, 2f, 0f)` | 새로 하나 만든다 |

> 💬 "4주차에 배열 배웠죠. **비슷한 걸 3개만 담는 전용 상자**라고 생각하세요."
>
> ⚠️ `Vector2`와 `Vector3`를 섞으면 에러가 난다. **"2D여도 `position`은 `Vector3`"** 를 못 박는다.
> 학생이 `Vector2`로 쓰면 `Cannot implicitly convert` 에러가 난다.

**미리 만들어진 것들**

| | 값 | 방향 |
|---|---|---|
| `Vector3.right` | `(1, 0, 0)` | 오른쪽 |
| `Vector3.left` | `(-1, 0, 0)` | 왼쪽 |
| `Vector3.up` | `(0, 1, 0)` | 위 |
| `Vector3.down` | `(0, -1, 0)` | 아래 |
| `Vector3.zero` | `(0, 0, 0)` | 원점 |

> 💬 "`Vector3.right`는 그냥 `(1, 0, 0)`을 짧게 쓴 겁니다. **외울 필요 없고, 이름이 방향 그대로예요.**"

### ④ 더해서 움직이기 (12분) — 오늘의 핵심

```csharp
using UnityEngine;

public class Mover : MonoBehaviour
{
    [SerializeField] private float moveStep = 0.05f;

    void Update()
    {
        transform.position = transform.position + Vector3.right * moveStep;
    }
}
```

▶ Play → **계속 오른쪽으로 간다.**

**한 줄을 조각내서 읽는다.**

| 조각 | 뜻 |
|---|---|
| `Vector3.right * moveStep` | 오른쪽으로 `moveStep`만큼 |
| `transform.position + ...` | **지금 자리**에서 그만큼 더한 자리 |
| `transform.position = ...` | 그 자리로 **옮긴다** |

> 💬 "`=`는 '같다'가 아니라 **'넣는다'** 였죠. 4회차에 했습니다."
> 💬 "**지금 위치 + 조금 = 새 위치.** 이걸 매 프레임 반복하니까 움직여 보이는 거예요."

> 🚨 **가장 많이 나오는 실수 두 개를 미리 보여준다.**
>
> ```csharp
> transform.position.x = 5f;          // ❌ 컴파일 에러
> transform.position = Vector3.right; // ❌ 움직이는 게 아니라 (1,0,0)에 딱 붙는다
> ```
> 첫 번째는 왜 안 되는지 깊이 설명하지 않는다. **"통째로 넣어야 합니다"** 로만.

### ⑤ `Translate` — 짧게 쓰기 (4분)

```csharp
transform.Translate(Vector3.right * moveStep);
```

위의 긴 줄과 **똑같이 동작한다.**

> 💬 "`Translate`는 '**지금 자리에서 그만큼 옮겨라**'를 한 단어로 만든 겁니다. 더할 필요가 없어요."
> 💬 "둘 다 쓰입니다. 편한 걸 쓰세요."

### ⑥ 목표 지점으로 (시간 남으면)

```csharp
transform.position = new Vector3(3f, 2f, 0f);   // 순간이동
```

> 💬 "이건 **순간이동**입니다. 조금씩 가는 거랑 다르죠. 나중에 리스폰에 씁니다."

## 🚨 흔한 사고 & 대응 (강사용)

| 에러/상황 | 진짜 원인 | 대응 |
|---|---|---|
| `Cannot modify the return value...` | `transform.position.x = 5f` | **오늘 1등.** "통째로 넣어야 합니다" |
| `Cannot implicitly convert 'Vector2' to 'Vector3'` | `Vector2`를 씀 | "2D여도 position은 `Vector3`" |
| 물체가 안 움직임 | `Start`에 넣음 | `Update`에 넣어야 매 프레임 돈다 |
| 물체가 한 자리에 딱 붙음 | `= Vector3.right` (더하기 없음) | "**지금 위치 +** 를 빠뜨렸어요" |
| 너무 빨라서 순식간에 사라짐 | `moveStep`이 큼 | `0.01`로 줄이고 `F` |
| 물체가 안 보임 | 화면 밖으로 나감 | `F` 또는 `Start`에서 원점으로 |
| `new` 를 빼먹음 | `Vector3(1f,2f,0f)` | `new Vector3(...)` |
| `f` 를 빼먹음 | 4회차 그대로 | "소수점 뒤엔 f" |
| **"속도가 사람마다 달라요"** | `Time.deltaTime` 없음 | **의도된 것.** "039회차에 고칩니다" |
| 진도 빠른 학생이 `deltaTime`을 씀 | 좋은 신호 | 개별 칭찬. **반 전체에 공유하지 않는다** |
