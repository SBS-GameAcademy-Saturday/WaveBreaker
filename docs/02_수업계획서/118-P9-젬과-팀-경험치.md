## 00:10–00:50 · 같이 하기 ★

### ① 젬은 서버가 만든다 (10분)

몬스터가 죽을 때 젬을 떨군다. **죽는 판정이 서버에서 일어나니** 젬도 서버가 만든다.

```csharp
private void Die()
{
    Debug.Log($"[호스트] 몬스터 처치 — 젬을 떨군다");

    if (gemPrefab != null)
    {
        GameObject gem = Instantiate(gemPrefab, transform.position, Quaternion.identity);
        gem.GetComponent<NetworkObject>().Spawn();   // 🔑 Instantiate 만으로는 상대에게 안 보인다
    }

    // 서버가 없애면 모두에게서 사라진다.
    NetworkObject.Despawn();
}
```

> 💬 "117회차와 **똑같은 패턴**이죠. `Instantiate` + `Spawn()`."

> 🚨 **젬 프리팹도 목록에 등록**해야 한다. 안 하면 또 그 에러가 난다.

### ② 자석도 서버가 (8분)

082회차의 자석을 네트워크판으로 옮긴다.

```csharp
private void Update()
{
    // 자석도 서버가 움직인다. 위치는 NetworkTransform 이 보낸다.
    if (!IsServer) return;

    ...
    transform.position = Vector3.MoveTowards(
        transform.position, nearest.position, moveSpeed * Time.deltaTime);
}
```

> 💬 "**가장 가까운 플레이어**를 찾습니다. 082에서는 한 명이었지만 이제 둘이죠."
> 💬 "코드는 117의 몬스터와 같은 구조입니다."

### ③ 🔑 판정은 서버만 (12분) — 오늘의 핵심

```csharp
private void OnTriggerEnter2D(Collider2D other)
{
    // 🔑 판정은 서버만. 이 한 줄이 "둘 다 먹는" 사고를 막는다.
    if (!IsServer) return;
    if (taken) return;

    if (!other.TryGetComponent(out NetworkPlayerTag _)) return;

    taken = true;

    if (NetworkTeam.Instance != null) NetworkTeam.Instance.AddExp(exp);

    NetworkObject.Despawn();
}
```

| 줄 | 막는 것 |
|---|---|
| `if (!IsServer) return;` | **두 컴퓨터가 각자 판정**하는 것 |
| `if (taken) return;` | **한 프레임에 두 번** 처리되는 것 |

> 💬 "두 번째 줄이 왜 필요할까요?"
> 💬 "서버 한 곳에서만 판정해도, **같은 프레임에 두 플레이어가 동시에 닿을 수 있습니다.**"
> 💬 "`Despawn` 은 바로 안 끝나요. 그 사이에 두 번째 `OnTriggerEnter2D` 가 들어옵니다."

> 🔑 💬 "**090회차에서 보스가 5번 죽은 것과 같은 종류**입니다. 기억나세요?"
> 💬 "`Destroy` 가 프레임 끝에 처리돼서 `Die()` 가 여러 번 불렸죠. **같은 함정**이에요."

### ④ 팀 경험치 (12분)

```csharp
public class NetworkTeam : NetworkBehaviour
{
    public static NetworkTeam Instance { get; private set; }

    public NetworkVariable<int> Exp = new NetworkVariable<int>(
        0, NetworkVariableReadPermission.Everyone, NetworkVariableWritePermission.Server);

    public NetworkVariable<int> Level = new NetworkVariable<int>(
        1, NetworkVariableReadPermission.Everyone, NetworkVariableWritePermission.Server);

    public int NeedExp => baseExp + (Level.Value - 1) * expStep;

    // 서버만 부른다.
    public void AddExp(int amount)
    {
        if (!IsServer) return;

        Exp.Value += amount;

        // 한 번에 두 레벨이 오를 수도 있다 (083 회수).
        while (Exp.Value >= NeedExp)
        {
            Exp.Value -= NeedExp;
            Level.Value++;
        }
    }
}
```

> 💬 "**083회차의 `PlayerLevel` 과 계산이 똑같습니다.** `while` 로 도는 것까지요."
> 💬 "달라진 건 `int` 가 `NetworkVariable<int>` 가 된 것뿐이에요."

**레벨이 오르면 양쪽에 알린다** — `OnValueChanged` (115 회수)

```csharp
private void OnLevelChanged(int before, int after)
{
    // 양쪽 화면에서 다 불린다. 123회차에 여기서 레벨업 창을 띄운다.
    Debug.Log($"[{(IsServer ? "호스트" : "클라이언트")}] 팀 레벨 {before} → {after}");
}
```

> 💡 123회차에 **여기서 양쪽 레벨업 창을 띄운다.** 자리를 미리 만들어 두는 것이다.

<details>
<summary>막히면 열기 (정답)</summary>

코드는 위 ①·③·④ 블록 그대로다.

**증상별 원인표**

| 증상 | 원인 |
|---|---|
| **경험치가 두 배** | `taken` 검사 누락 |
| 젬이 상대에게 안 보임 | `Spawn()` 누락 |
| `NetworkPrefab is not registered` | 젬 프리팹 미등록 |
| `NetworkTeam.Instance` 가 null | 씬에 오브젝트가 없다 |
| `NetworkTeam` 이 동기화 안 됨 | **`NetworkObject` 컴포넌트 누락** |
| 레벨이 한쪽만 오름 | `NetworkVariable` 이 아니라 `int` 를 썼다 |
| 젬이 안 끌려옴 | `IsServer` 위치가 잘못됨 |

**씬 오브젝트에도 `NetworkObject` 가 필요하다**
`NetworkTeam` `NetworkWaveManager` 같은 매니저도 `NetworkBehaviour` 라면
**`NetworkObject` 컴포넌트가 있어야** 한다. 없으면 조용히 동작을 안 한다.

</details>

**확인 조건**: 젬을 먹으면 **양쪽 Console 에** 팀 레벨 로그가 뜨고, 경험치가 한 번만 들어간다.

### ⭐ 도전 미션

- [ ] `taken` 검사를 빼고 둘이 동시에 젬을 밟아본다 (그리고 되돌린다)
- [ ] `if (!IsServer)` 를 빼고 실행해 본다 (그리고 되돌린다)
- [ ] 젬을 먹은 **사람 이름**을 로그에 찍는다
- [ ] 경험치를 팀 공유가 아니라 **개인**으로 바꿔보고 어느 쪽이 재밌는지 쓴다
- [ ] 팀 레벨을 화면에 표시한다 (양쪽에서 같은지 확인)
- [ ] 젬이 일정 시간 뒤 사라지게 한다 (`Despawn` 주의)

> 💡 첫 두 개를 **전원이** 한다. 오늘의 두 줄이 각각 뭘 막는지 몸으로 안다.
> 💡 네 번째는 답이 정해진 게 아니다. **기획 판단**을 해보는 자리다.
