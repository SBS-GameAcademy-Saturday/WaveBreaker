## 00:10–00:50 · 같이 하기 ★

### ① 총알 — 예약 `Destroy` 의 함정 (14분)

지금 `Projectile` 은 이렇게 돼 있다.

```csharp
private void Start()
{
    rb.linearVelocity = transform.up * speed;
    Destroy(gameObject, lifeTime);   // 2초 뒤에 없애 줘
}
```

> 💬 "이걸 풀링으로 바꾸면 **무슨 일이 날까요?**"

시간을 준다.

> 🔑 💬 "**`Destroy(go, 2f)` 는 예약입니다.** 2초 뒤에 진짜로 없애요."
> 💬 "그런데 그 사이에 반납해서 **서랍에 들어가 있으면?**"
> 💬 "**서랍 속 물건이 사라집니다.** 다음에 꺼내려는데 없어요."

**고친다** — 수명을 직접 센다.

```csharp
private float lifeLeft;

// 🔑 재활용될 때마다 다시 돈다. Start 였으면 두 번째부터 안 날아간다.
private void OnEnable()
{
    rb.linearVelocity = transform.up * speed;
    lifeLeft = lifeTime;
}

private void Update()
{
    lifeLeft -= Time.deltaTime;

    // 안 없애면 계속 쌓인다 (048). 이제는 없애는 대신 반납한다.
    if (lifeLeft <= 0f) PoolManager.Despawn(gameObject);
}

private void OnTriggerEnter2D(Collider2D other)
{
    ...
    if (pierce <= 0) PoolManager.Despawn(gameObject);
}
```

> 🚨 **`Destroy(go, 초)` 를 쓰는 곳은 풀링과 절대 같이 못 쓴다.** 전부 찾아 바꾼다.

### ② 방향을 언제 정하나 (8분) — 순서 문제

`AutoGun` 은 지금 이렇게 쏜다.

```csharp
GameObject shot = Instantiate(projectilePrefab, transform.position, Quaternion.identity);
shot.transform.up = dir;   // 만든 뒤에 방향을 준다
```

`Instantiate` 는 `Start` 가 **다음 프레임**에 돌아서 이 순서가 통했다.
그런데 풀링은 `SetActive(true)` 하는 **그 자리에서 `OnEnable` 이 바로 돈다.**

```
Spawn 호출
  └ SetActive(true)
      └ OnEnable 실행   ← 여기서 transform.up 을 읽는다 (아직 옛날 방향!)
  return
shot.transform.up = dir   ← 너무 늦다
```

**고친다** — 꺼낼 때 방향을 같이 준다.

```csharp
Quaternion rot = Quaternion.FromToRotation(Vector3.up, dir);   // 064의 transform.up 과 같은 뜻

GameObject shot = PoolManager.Spawn(projectilePrefab, transform.position, rot);

if (shot != null && shot.TryGetComponent(out Projectile p))
{
    p.Setup(damage, pierce);
}
```

> 💬 "**순서가 바뀐 겁니다.** 예전엔 만들고 나서 방향을 줬는데, 이제는 방향까지 정해서 꺼내요."

**실측** — 재활용해도 방향이 제대로 바뀐다.

```
총알 1발   속도=(12.0, 0.0)     ← 오른쪽
재활용     속도=(0.0, 12.0)     ← 위쪽
```

### ③ 젬과 죽음 이펙트 (8분)

`ExpGem` 은 한 줄이다.

```csharp
// Destroy(gameObject);
PoolManager.Despawn(gameObject);
```

`DeathEffect` 는 조금 더 손이 간다. **조각을 `Start` 에서 만들고 있었다.**

```csharp
// 전 : Start 에서 조각 8개를 만든다
// → 재활용하면 Start 가 안 도니까 조각이 안 생긴다... 가 아니라
//   이미 있는 조각이 지난번 자리에 흩어진 채로 나온다

// 후
private void Awake()      // 조각을 만드는 건 처음 한 번만
{
    ... 조각 8개 생성 ...
}

private void OnEnable()   // 위치와 색을 되돌리는 건 매번
{
    elapsed = 0f;   // 이걸 안 하면 두 번째부터 꺼내자마자 사라진다

    for (int i = 0; i < shards.Length; i++)
    {
        shards[i].transform.localPosition = Vector3.zero;
        shards[i].color = color;
    }
}
```

> 🔑 💬 "**한 번만 할 일은 `Awake`, 매번 할 일은 `OnEnable`.**"
> 💬 "조각을 매번 새로 만들면 풀링을 하는 의미가 없죠."

**실측**

```
이펙트 재활용   조각 8→8개 (안 늘었다)
                elapsed=0   첫 조각 위치=(0,0,0)   알파=1.00
```

### ④ 🔑 개수 상한 (12분) — 오늘의 핵심

> 💬 "화면에 몬스터가 **300마리** 있는 거랑 **250마리** 있는 거, 구분되세요?"
> 💬 "안 됩니다. 그런데 **프레임은 열 배 차이**가 나요."

먼저 **살아 있는 수를 세야 한다.** `Enemy` 에 `static` 카운터를 둔다.

```csharp
// 살아 있는 몬스터 수. 웨이브 매니저가 상한을 걸 때 쓴다.
public static int AliveCount { get; private set; }

public static void ResetAliveCount() => AliveCount = 0;

protected virtual void OnEnable()
{
    AliveCount++;
    ...
}

protected virtual void OnDisable()
{
    AliveCount--;
}
```

> 🚨 **`static` 은 씬을 다시 열어도 안 사라진다** (097에서 배운 그것).
> 다시 시작하면 카운터가 이전 판 값을 갖고 있다. `GameManager.Awake` 에서 되돌린다.

```csharp
void Awake()
{
    ...
    Time.timeScale = 1f;
    Enemy.ResetAliveCount();   // static 은 씬을 다시 열어도 안 사라진다
}
```

**상한을 건다** — `WaveManager`

```csharp
[Header("개수 상한")]
[SerializeField] private int maxAlive = 250;

public void SpawnOne()
{
    if (enemyPrefabs.Length == 0 || spawnPoints.Length == 0) return;

    // 이미 꽉 찼으면 안 만든다.
    if (Enemy.AliveCount >= maxAlive) return;

    ...
}
```

> 💬 "**네 줄입니다.** 이게 오늘 프레임을 살립니다."

### ⑤ 실측 — 상한 전/후 (8분)

같은 조건(초당 수백 마리 소환 요청)에서 잰 값이다.

| 상태 | 살아 있는 몬스터 | 평균 FPS |
|---|---|---|
| 풀링 ✗ · 상한 ✗ | 3668 | **45.2** |
| 풀링 ✓ · 상한 ✗ | 2757 | **13.6** |
| **풀링 ✓ · 상한 250** | **210** | **442.3** |

> 🔑 💬 "가운데 줄을 보세요. **풀링만 해서는 프레임이 안 살아납니다.**"
> 💬 "맨 아래가 상한을 건 겁니다. **45 → 442.** 열 배예요."

> 💬 "그럼 풀링은 왜 했을까요?"

| 풀링이 준 것 | 값 |
|---|---|
| 만드는 비용 | 22 µs → **5 µs** |
| 쓰레기(GC) | 4 KB → **0 KB** |
| 재사용 비율 (12초 플레이) | **59%** |

> 💬 "**둘 다 필요합니다.** 상한은 프레임을, 풀링은 비용과 쓰레기를 잡아요."
> 💬 "그리고 상한을 걸면 **풀이 잘 도는** 구조가 됩니다. 250개 만들어 놓고 계속 돌려 쓰거든요."

<details>
<summary>막히면 열기 (정답)</summary>

코드는 위 ①~④ 블록 그대로다.

**`Destroy` 예약을 전부 찾는 법**
편집기에서 `Destroy(` 를 검색한다. 인자가 **두 개**인 것(`Destroy(go, 2f)`)이 예약이다.
우리 프로젝트에는 `Projectile` 한 곳뿐이었다.

**`maxAlive` 값 정하기**

| 값 | 느낌 |
|---|---|
| 100 | 후반이 심심하다 |
| **250** | ✅ 화면이 꽉 차 보이고 프레임도 산다 |
| 500 | 프레임이 떨어지기 시작 |

**자기 컴퓨터에서 정하는 법**: 상한을 `100` 부터 올려가며 **FPS 가 60 밑으로 떨어지는 값**을 찾고,
거기서 조금 낮춘다.

**상한을 걸었는데 몬스터가 안 늘어나면**
`AliveCount` 가 `--` 를 안 해서 계속 올라가는 중일 수 있다. `OnDisable` 을 확인한다.
`Debug.Log(Enemy.AliveCount)` 를 찍어 실제 마리 수와 맞는지 본다.

</details>

**확인 조건**: 상한 전/후 FPS 를 각각 재서 **차이가 나는 걸 자기 숫자로** 확인했다.

## 🚨 흔한 사고 & 대응 (강사용)

| 에러/상황 | 진짜 원인 | 대응 |
|---|---|---|
| **총알이 한 방향으로만 감** | 방향을 `Spawn` 뒤에 줬다 | **오늘 1등.** `OnEnable` 이 먼저 돈다 |
| 두 번째 총알이 안 날아감 | `Start` 를 그대로 뒀다 | 102 회수 |
| 서랍 속 총알이 사라짐 | `Destroy(go, 2f)` 가 남아 있다 | 검색해서 전부 제거 |
| 이펙트 조각이 계속 늘어남 | 조각을 `OnEnable` 에서 만든다 | 만들기는 `Awake` |
| 이펙트가 나오자마자 사라짐 | `elapsed` 를 안 되돌림 | `OnEnable` |
| **다시 시작하니 몬스터가 안 나옴** | `AliveCount` 가 안 초기화됨 | `static` 함정 (097) |
| `AliveCount` 가 계속 늘어남 | `OnDisable` 누락 | 켜고 끄는 짝을 맞춘다 |
| 상한을 걸어도 프레임 그대로 | 상한 값이 너무 크다 | 250부터 |
| 몬스터가 너무 안 나옴 | 상한이 너무 작다 | 100 미만은 심심하다 |
| 보스가 안 나옴 | `SpawnBoss` 에도 상한을 걸었다 | **보스는 상한 밖**이다 |
