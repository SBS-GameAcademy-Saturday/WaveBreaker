## 🎯 오늘의 목표

1. `Update` + 타이머 변수로 "3초 뒤에"를 만들어 보고 **불편을 겪는다**
2. **코루틴**으로 같은 걸 훨씬 짧게 쓴다
3. `yield return new WaitForSeconds(3f)` 가 **"여기서 3초 쉬었다 이어서"** 인 걸 안다

> ⚠️ **오늘 안 하는 것**: 몬스터 스폰. **052회차**다.
> `IEnumerator`가 **왜** 반환 타입인지, 컴파일러가 뭘 하는지는 **설명하지 않는다.**
> `while` 반복 코루틴도 안 한다. 오늘은 **한 번 쉬었다 이어지는 것**까지.
>
> 🔑 **설계 의도**: **이 Phase 최대 난관이다.** 그래서 오늘은 문법을 최소로 줄이고
> **"불편 → 해결"** 한 번만 태운다. `yield`를 문법으로 설명하는 순간 반이 무너진다.
> **"여기서 잠깐 쉬었다 이어서"** 이 한 문장으로 끝까지 간다.

## 00:10–00:45 · 같이 치기 ★

### ① 3초 뒤에 뭔가 하려면 (10분) — 오늘의 도입

> 💬 "**3초 뒤에** Console에 '발사!' 를 찍고 싶습니다. 어떻게 할까요?"
>
> 학생 답을 기다린다. "`Update`에서 시간을 세면 될 것 같다"가 나오면 최고.

**같이 쳐 본다.**

```csharp
using UnityEngine;

public class CoroutineDemo : MonoBehaviour
{
    private float timer;
    private bool done;

    void Update()
    {
        if (done) return;

        timer = timer + Time.deltaTime;

        if (timer >= 3f)
        {
            Debug.Log("발사!");
            done = true;
        }
    }
}
```

▶ Play → 3초 뒤에 한 번 찍힌다. **된다.**

> 💬 "됩니다. 그런데 **한 번 하는 데 변수가 두 개**나 필요했어요."
> 💬 "그럼 **3초 뒤에 하고, 또 2초 뒤에 하고, 또 1초 뒤에 하려면** 어떻게 될까요?"

**칠판에 그림만 그린다. 실제로 치지는 않는다.**

```
timer1, done1, timer2, done2, timer3, done3, 그리고 단계 변수...
```

> 💬 "이걸 **몬스터 웨이브 10개**에 하면 어떻게 될까요? 변수가 스무 개가 됩니다."
> 💬 "그래서 유니티는 **다른 방법**을 줍니다."

> ⚠️ **여기가 오늘의 핵심 순간이다.** 타이머 버전을 반드시 직접 쳐보게 한다.
> 이걸 건너뛰고 코루틴부터 주면 학생은 **"왜 이런 이상한 문법을 쓰지"** 로만 기억한다.

### ② 코루틴 — 같은 걸 세 줄로 (12분)

```csharp
using UnityEngine;
using System.Collections;

public class CoroutineDemo : MonoBehaviour
{
    void Start()
    {
        StartCoroutine(Fire());
    }

    IEnumerator Fire()
    {
        yield return new WaitForSeconds(3f);

        Debug.Log("발사!");
    }
}
```

▶ Play → **똑같이 3초 뒤에 찍힌다.** 변수는 **하나도 없다.**

> 💬 "**변수가 사라졌습니다.** 위에서 아래로 읽으면 그대로예요."
> 💬 "**'3초 쉬어라. 그 다음 발사를 찍어라.'** 그게 전부입니다."

**한 줄씩 짚는다. 딱 이만큼만.**

| 줄 | 뜻 |
|---|---|
| `using System.Collections;` | **이게 있어야 `IEnumerator`를 쓸 수 있다** |
| `IEnumerator Fire()` | **쉬었다 갈 수 있는 메서드**라는 표시 |
| `StartCoroutine(Fire())` | **시작해 달라고 부탁한다** |
| `yield return new WaitForSeconds(3f)` | **여기서 3초 쉬었다 이어서** |

> 🚨 **`IEnumerator`가 뭐냐고 반드시 묻는다.** 답은 정해두고 그 이상 안 나간다.
> 💬 "**'이 메서드는 중간에 쉴 수 있다'는 표시**입니다. 유니티랑 약속한 표기예요."
> 💬 "안에서 뭐가 도는지는 **나중에 궁금해지면** 보세요. 지금은 표시라고만 아세요."
>
> ⚠️ **컴파일러가 상태 머신을 만든다** 같은 설명은 절대 하지 않는다. 이 회차가 끝난다.

> 🚨 **`StartCoroutine`을 빼먹는 게 오늘 최다 사고다.**
> 💬 "`Fire()` 만 부르면 **아무 일도 안 일어납니다.** 에러도 안 나요."
> 💬 "코루틴은 **반드시 `StartCoroutine`으로 시작**해야 합니다."
>
> 강사가 **일부러 재현한다**: `Fire();` 로 바꿔서 Play → Console이 조용하다. 이걸 꼭 보여준다.

### ③ 여러 번 쉬기 (8분) — 오늘의 그림

```csharp
IEnumerator Countdown()
{
    Debug.Log("3");
    yield return new WaitForSeconds(1f);

    Debug.Log("2");
    yield return new WaitForSeconds(1f);

    Debug.Log("1");
    yield return new WaitForSeconds(1f);

    Debug.Log("발사!");
}
```

▶ Play → **1초 간격으로** `3` `2` `1` `발사!`

> 🎉 여기서 반응이 온다. 타이머 변수로 이걸 하려면 코드가 몇 배가 된다.

> 💬 "**위에서 아래로 읽으면 그대로 실행됩니다.** 중간에 쉬는 지점만 표시한 거예요."
> 💬 "이게 코루틴을 쓰는 이유 전부입니다. **시간이 걸리는 일을 순서대로 쓸 수 있다.**"

### ④ `yield return null` (5분)

```csharp
yield return null;   // 다음 프레임까지만 쉰다
```

> 💬 "`WaitForSeconds` 자리에 `null`을 넣으면 **한 프레임만** 쉽니다."
> 💬 "**`Update` 한 번 도는 만큼**이에요. 지금은 이런 것도 있다는 것만 아세요."

| 쓰는 것 | 얼마나 쉬나 |
|---|---|
| `yield return new WaitForSeconds(2f)` | **2초** |
| `yield return null` | **다음 프레임까지** (약 1/60초) |

> ⚠️ **`yield return null`을 `while` 안에 넣으면 `Update`와 같아진다**는 건 오늘 안 꺼낸다.
> 052에서 `while`이 나올 때 자연스럽게 이어진다.

## 01:35–01:50 · 데모 + 정리

학생 2명 데모. **`StartCoroutine`을 뺀 학생**이 있으면 반드시 보여주게 한다.
"에러도 없이 아무 일도 안 일어나는" 상황을 다 같이 보는 게 오늘의 안전장치다.

**마무리 정리 (한 장)**

| | `Update` + 타이머 | 코루틴 |
|---|---|---|
| 변수 | 시간마다 하나씩 | **없다** |
| 읽는 법 | 흩어져 있다 | **위에서 아래로** |
| 시작 | 저절로 | **`StartCoroutine`** |
| 쉬는 표시 | — | **`yield return`** |

> 💬 "코루틴은 어려운 게 아니라 **낯선** 겁니다. **'여기서 잠깐 쉬었다 이어서'** — 이 한 문장이 전부예요."
> 💬 "앞으로 웨이브, 스킬 쿨타임, 페이드인, 대사 출력 — **시간이 걸리는 건 전부 이걸로** 합니다."

## 🚨 흔한 사고 & 대응 (강사용)

| 에러/상황 | 진짜 원인 | 대응 |
|---|---|---|
| **아무것도 안 찍힘** | **`StartCoroutine`을 안 씀** | **오늘 1등.** 에러가 없어서 못 찾는다 |
| **한 번에 다 찍힘** | `yield return`을 빼먹음 | **오늘 2등.** 쉬는 표시가 없으면 그냥 다 돈다 |
| `IEnumerator`를 못 찾음 | `using System.Collections;` 없음 | 맨 위에 추가 |
| `System.Collections.Generic`을 씀 | 비슷한 이름 | `Generic`이 아니다 |
| `void Countdown()` 인 채로 `yield` | 반환 타입이 틀림 | `IEnumerator`로 |
| `new`를 빼먹음 | `WaitForSeconds(1f)` | `new WaitForSeconds(1f)` |
| `WaitForSecond` (s 빠짐) | 오타 | 자동완성으로 |
| 코루틴이 도중에 멈춤 | 오브젝트가 꺼지거나 파괴됨 | "붙어 있는 오브젝트가 죽으면 코루틴도 죽는다" |
| `Time.timeScale = 0`에서 안 감 | 정상 (⭐도전) | `WaitForSecondsRealtime` 이 따로 있다. 이름만 |
| `IEnumerator`가 뭐냐고 물음 | 좋은 질문 | **"쉴 수 있다는 표시"까지만.** 더 안 나간다 |
| 코루틴을 `Update`에서 매 프레임 시작 | 수십 개가 동시에 돈다 | 052에서 정식으로 다룬다. 오늘은 `Start`에서만 |
| 파일명 ≠ 클래스명 | 036 그대로 | 파일을 지우고 다시 만든다 |
