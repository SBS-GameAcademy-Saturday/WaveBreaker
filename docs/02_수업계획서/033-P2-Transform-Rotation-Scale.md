## 00:10–00:45 · 같이 치기 ★

### ① Rotation — Z만 쓴다 (7분)

`Square` 하나를 놓고 Rotation을 하나씩 건드린다. **순서가 중요하다.**

| 넣을 값 | 결과 | 반응 |
|---|---|---|
| **Z = `45`** | 마름모처럼 기울어진다 | "이게 우리가 쓸 거예요" |
| **X = `45`** | **납작해진다** | "어? 이상하죠" |
| **Y = `45`** | 역시 납작 | "이것도요" |
| X, Y를 `0`으로 | 정상 복귀 | |

> 💬 "X랑 Y로 돌리면 물체가 **화면 안쪽으로 누워버립니다.** 3D라면 맞는 동작인데, 2D에서는 쓸 일이 없어요."
> 💬 "**2D는 Z만.** 시계 방향으로 도는 게 아니라 **반시계 방향**이 양수입니다."

`Z = 90`, `Z = 180`, `Z = -90`을 넣어보게 한다.

> ⚠️ **X·Y를 0으로 되돌리는 법을 반드시 같이 알려준다.** 안 그러면 "납작해졌어요"가 남는다.
> Position 때와 같이 Transform 우측 `⋮` → **Reset**.

**회전 툴** `E` 키도 짚는다. 파란 원을 끌면 Z가 돈다.

> 💬 "빨강·초록 원은 건드리지 마세요. **파란 원만.**"

### ② Scale — 크기와 뒤집기 (6분)

| 넣을 값 | 결과 |
|---|---|
| Scale `1, 1, 1` | 기본 크기 |
| Scale `2, 2, 1` | 두 배 |
| Scale `0.5, 0.5, 1` | 절반 |
| Scale `3, 0.5, 1` | **가로로 늘어난 납작한 것** |
| **Scale `-1, 1, 1`** | **좌우로 뒤집힌다** |

> 💬 "`1`이 기본입니다. 2면 두 배, 0.5면 절반."
> 💬 "**X에 마이너스를 넣으면 거울처럼 뒤집힙니다.** 이거 나중에 캐릭터가 왼쪽 볼 때 씁니다." ← Phase 5 복선

**뒤집기를 반드시 실습시킨다.** 좌우 비대칭 도형(입 달린 얼굴 등)으로 해야 눈에 보인다.

> ⚠️ Scale에 `0`을 넣으면 사라진다. "크기가 0이면 없는 거죠"로 설명하고 되돌린다.
> ⚠️ Scale Z는 2D에서 의미 없다. **`1`로 두게 한다.**

### ③ 이상한 장면 먼저 (4분) — `032_WorldLocal_Demo` 씬

**설명 없이 씬부터 연다.** 사각형 두 개가 **화면상 같은 자리**에 겹쳐 있다.

1. `A_NoParent`를 클릭 → Inspector Position **`(3, 2)`**
2. `B_Child`를 클릭 → Inspector Position **`(0, 0)`**

> 💬 "둘이 같은 자리에 있죠? 그런데 숫자가 다릅니다. **하나는 (3,2), 하나는 (0,0).**"
> 💬 "어제 (0,0)은 원점이라고 했는데, 얘는 원점에 있지 않잖아요. **왜 그럴까요?**"

학생이 추측하게 둔다. Hierarchy를 보여준다 — `B_Child`는 `B_Parent` **아래에 들어가 있다.**

> 💬 "차이는 이거 하나예요. **부모가 있느냐 없느냐.**"

### ④ 월드 좌표와 로컬 좌표 (10분) — 오늘의 핵심

| | 무엇을 기준으로 재나 | 언제 보이나 |
|---|---|---|
| **월드 좌표** | 게임 세계의 원점 `(0,0)` | 부모가 **없을** 때 Inspector에 뜨는 값 |
| **로컬 좌표** | **부모가 있는 자리** | 부모가 **있을** 때 Inspector에 뜨는 값 |

> 🔑 **한 문장으로 못 박는다 (채팅 고정)**
> 💬 "**Inspector의 Position은 부모가 있으면 로컬 좌표, 없으면 월드 좌표입니다.**"

`B_Parent`를 클릭해 Position이 `(3, 2)`인 걸 확인시킨다.

> 💬 "부모가 (3,2)에 있고, 자식은 거기서 (0,0)만큼 떨어져 있어요. 그러니까 **실제 자리는 (3,2)**."
> 💬 "부모 자리 + 로컬 좌표 = 실제 자리. 이게 전부입니다."

**직접 확인시킨다.** `B_Parent`의 Position X를 `6`으로 바꾼다.
→ 자식이 따라 움직이는데 **자식의 Position은 여전히 `(0, 0)`이다.**

> 💬 "자식은 자기가 움직였다고 생각 안 해요. **부모가 움직인 거죠.**"

> 📌 **용어를 피하지 않는다.** "로컬"이라는 말을 그대로 쓴다.
> 038회차에 `transform.position`과 `transform.localPosition`이 나오는데,
> 그때 처음 들으면 늦다. 오늘 이름을 붙여두면 그건 그냥 **오늘 배운 것의 코드 버전**이 된다.

### ⑤ 부모자식 다루기 (8분)

**Hierarchy에서 오브젝트를 다른 오브젝트 위로 끌어다 놓으면** 자식이 된다.

**시연 순서 (태양-지구)**

1. `Sun` (큰 원), `Earth` (작은 원)을 따로 만든다
2. 둘 다 움직여 본다 → **따로 논다**
3. Hierarchy에서 `Earth`를 `Sun` **위로 드래그** → 들여쓰기 되며 자식이 된다
   → **이 순간 `Earth`의 Position 숫자가 바뀐다.** 월드 → 로컬로 바뀐 것
4. `Sun`의 Position을 바꾼다 → **`Earth`가 따라온다**
5. `Sun`의 Rotation Z를 돌린다 → **`Earth`가 궤도를 돈다**
6. `Sun`의 Scale을 키운다 → **`Earth`도 같이 커진다**

> 💬 "**위치만이 아니라 회전과 크기도 부모를 따라갑니다.** Transform 세 줄 전부요."
> 💬 "캐릭터가 움직이면 체력바도 따라와야 하죠. 그때 이걸 씁니다."

**자식에서 빼는 법**: Hierarchy에서 밖으로 드래그.

> ⚠️ 뺄 때 숫자가 또 바뀐다. 로컬 → 월드로 돌아가는 것.
> **화면상 위치는 그대로인데 숫자만 바뀐다** — 이걸 같이 확인시킨다.

## 00:55–01:35 · 개인 미션

### 필수 미션 — 로봇팔 만들기

`033_Transform_Start` 씬을 연다. **Square 4개가 이미 놓여 있다.**
이걸로 **3단 로봇팔**을 만든다. 어깨를 돌리면 팔 전체가 돌아야 한다.

```
Shoulder (어깨)          ← 부모. 이것만 월드 좌표
└── UpperArm (윗팔)      ← 여기서부터 전부 로컬 좌표
    └── LowerArm (아랫팔)
        └── Hand (손)
```

- [ ] Hierarchy 드래그로 위 계층을 만든다 (**좌표보다 계층이 먼저**)
- [ ] 각 마디가 이어져 보이게 Position을 잡는다
- [ ] `Shoulder`의 **Rotation Z를 돌리면 팔 전체가** 돌아간다
- [ ] `UpperArm`의 Rotation Z를 돌리면 **그 아래만** 돌아간다
- [ ] 마디마다 색을 다르게 준다
- [ ] 씬을 저장한다

**🔑 로컬 좌표 확인 (이게 오늘의 핵심)**

세 마디의 Position X를 **전부 `1`** 로 넣었는데, 화면에서는 1씩 벌어져 늘어선다.

- [ ] `UpperArm` / `LowerArm` / `Hand` 의 Inspector Position X가 **전부 `1`** 인 걸 확인한다
- [ ] 그런데 화면에서는 셋이 **다른 자리**에 있다. **왜 그런지 한 문장으로 설명한다**
- [ ] `Shoulder`를 `(0, 3)`으로 옮긴다 → 팔 전체가 따라가는데 **자식들 숫자는 전부 `1` 그대로다**

> 💬 "셋 다 `1`인데 자리가 다르죠. **각자 자기 부모에서 1만큼**이니까요."
> 💬 "`Hand`의 실제 위치는 어깨 + 1 + 1 + 1 입니다. 그걸 유니티가 대신 계산해 주는 거예요."

**실제 값 (강사 확인용)**

| 오브젝트 | 로컬 X | 월드 X |
|---|---|---|
| `Shoulder` | `0` | `0` ← 부모가 없어서 **둘이 같다** |
| `UpperArm` | `1` | `1` |
| `LowerArm` | `1` | **`2`** |
| `Hand` | `1` | **`3`** |

> 🔑 **`Shoulder`만 로컬과 월드가 같다.** 부모가 없기 때문이다. 이걸 꼭 짚는다.

**확인 조건**: `Shoulder`만 돌렸는데 손까지 따라 움직인다.
그리고 **자식 셋의 Position이 전부 `1`인데 왜 자리가 다른지 설명할 수 있다.**

<details>
<summary>막히면 열기 (값 예시)</summary>

| 오브젝트 | Position | 좌표 종류 | Scale |
|---|---|---|---|
| `Shoulder` | `0, 0, 0` | **월드** (부모 없음) | `1, 1, 1` |
| `UpperArm` | `1, 0, 0` | **로컬** (Shoulder 기준) | `1, 0.7, 1` |
| `LowerArm` | `1, 0, 0` | **로컬** (UpperArm 기준) | `1, 0.55, 1` |
| `Hand` | `1, 0, 0` | **로컬** (LowerArm 기준) | `1, 0.85, 1` |

**순서가 중요하다.** 계층부터 만들고 **그다음** 좌표를 넣는다.
좌표를 먼저 넣고 자식으로 만들면 위치가 튄다 — 월드 좌표가 로컬 좌표로 바뀌기 때문이다.

팔이 흩어져 보이면 → 자식의 Position은 **로컬 좌표**라는 걸 다시 확인한다.
`(1, 0)`은 "월드 원점에서 1"이 아니라 "**부모에서** 1"이다.

> ⚠️ **Scale X는 전부 `1`로 둔다.** 부모의 Scale X가 1이 아니면
> 자식의 로컬 거리가 그만큼 눌리거나 늘어나서 **로컬 1이 월드 1이 아니게 된다.**
> 오늘은 그 얘기까지 하지 않는다. 세로(Y)만 다르게 줘서 마디처럼 보이게 한다.
</details>

## 01:35–01:50 · 데모 + Transform 3줄 정리

학생 3명 데모. **어깨를 돌려서** 팔 전체가 도는 걸 보여주게 한다.

**마무리 정리 (한 장)**

| 줄 | 뜻 | 2D에서 |
|---|---|---|
| **Position** | 어디에 | X(가로), Y(세로). **Z는 0** |
| **Rotation** | 얼마나 돌았나 | **Z만.** 반시계가 양수 |
| **Scale** | 얼마나 큰가 | `1`이 기본. **음수면 뒤집힘** |

**그리고 오늘의 핵심 한 줄**

| | 기준점 | Inspector에 뜨는 때 |
|---|---|---|
| **월드 좌표** | 게임 세계의 원점 | 부모가 **없을** 때 |
| **로컬 좌표** | 부모가 있는 자리 | 부모가 **있을** 때 |

> 💬 "Transform 세 줄이 전부입니다. 앞으로 7개월 동안 **코드로 건드릴 것도 이 세 줄**이에요."
> 💬 "그리고 그 세 줄이 **월드 기준인지 로컬 기준인지**를 항상 같이 생각하세요. 그게 오늘 배운 겁니다."
>
> 📌 038회차 예고로 한 줄만 흘린다 — "코드에서는 `transform.position`이 월드,

## 🚨 흔한 사고 & 대응 (강사용)

| 에러/상황 | 진짜 원인 | 대응 |
|---|---|---|
| 물체가 납작해짐 | Rotation X 또는 Y | Transform Reset. **"2D는 Z만"** |
| 물체가 사라짐 | Scale에 `0` | `1`로 되돌린다 |
| 자식으로 넣었더니 위치가 튐 | **월드 → 로컬로 바뀜** | **오늘의 핵심.** 숫자만 바뀌고 화면 위치는 그대로인 것과 구분시킨다 |
| 자식으로 넣었더니 크기가 변함 | 부모 Scale이 1이 아님 | 부모 Scale을 1로 두고 시작하게 한다 |
| 드래그했는데 자식이 안 됨 | 오브젝트 **위**가 아니라 사이에 놓음 | 이름 위에 정확히 겹쳐 놓게 한다 |
| 실수로 자식이 됨 | Hierarchy 드래그 오조작 | 밖으로 다시 드래그. **자주 일어난다** |
| 팔 마디가 흩어짐 | 로컬인데 월드로 계산 | "월드 원점에서 1"이 아니라 "**부모에서** 1" |
