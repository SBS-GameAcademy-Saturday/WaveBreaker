## 3. 기존 배분의 문제 3가지

| # | 문제 | 근거 |
|---|---|---|
| 1 | **에디터 인터페이스를 30분에 훑고 넘어갔다** | ①은 통째로 한 편(B1). 창 6개 이름만 대는 건 설명이 아니다 |
| 2 | **Transform을 한 회차에 눌러담았다** | ②는 3강을 쓴다. Position / Rotation·Scale / 부모자식은 각각 실습이 필요하다 |
| 3 | **Rigidbody 물리를 첫 회차에 넣었다** | ①은 B9(11번째)에 둔다. "첫날 움직이는 결과"에 급해 순서를 뒤집었다 |

> 3번은 Phase 2 문서의 *"첫 회차에 반드시 화면에서 뭔가 움직이는 결과를 만든다"* 를 지키려다 나온 것이다.
> **움직임은 Inspector에서 Transform 값을 바꾸는 것으로 충분히 만들 수 있다.** 물리는 필요 없다.

## 4. 재설계한 Phase 2 배분 (031–040)

| 회차 | 주제 | 근거 |
|---|---|---|
| **031** | 에디터 인터페이스와 조작법 — **Inspector 중심** | ① B1 |
| **032** | Transform ① **Position**과 좌표계 | ② 트랜스폼(1) |
| **033** | Transform ② **Rotation · Scale · 부모자식** | ② 트랜스폼(2)(3) |
| **034** | GameObject와 Component — 그릇과 부품 | ① B5 / ② |
| **035** | 7주차 정리 — 조합 실습 + 자가진단 5단계 | — |
| **036** | 첫 스크립트 — `MonoBehaviour` / `Start`·`Update` / `Debug.Log` | ① B2·B3 |
| **037** | `[SerializeField]` — Inspector 연동 + Play 모드 함정 | ② 스크립트다루기 |
| **038** | 코드로 이동 — `transform.position` / `Vector2`·`Vector3` | ① B6·B7 |
| **039** | `Time.deltaTime` — 이동거리를 공평하게 | ① **B8 (이동 뒤)** |
| **040** | 키보드 입력 — WASD 캐릭터 + `SetActive` · `[ContextMenu]` | ① B6 / ② 키보드입력 |

### 바뀐 점

| | 이전 | 이후 |
|---|---|---|
| 에디터 인터페이스 | 031 안에서 12분 | **031 한 회차 전부** |
| Transform | 032 안에서 10분 | **032·033 두 회차** |
| Rigidbody 물리 | **031 (첫날)** | **Phase 3(041~)로 이동.** 031에서는 강사 데모만 |
| 첫 스크립트 | 033 | **036** |
| `Time.deltaTime` | 037 | **039** (여전히 이동 뒤 — ① B8과 동일) |

> ⚠️ **Phase 2 문서 수정 필요**: 7주차 항목의 *"Rigidbody 물리 실습"* 을 Phase 3로 옮긴다.
> Phase 3(041–055)는 이미 *"2D 물리와 충돌"* 이 첫 주제이므로 자연스럽게 이어진다.

### 유지한 설계

- **`Time.deltaTime`은 이동을 배운 뒤(039)** — ① B8과 같다. 037에서 심은 "속도가 제각각"을 회수한다
- **Input System 안 씀** — ④가 02+에서 다루지만 노베이스에겐 벽이다. 27주차 도전 과제
- **오브젝트 풀링은 101회차** — ④는 06강에 넣지만, 우리는 "렉을 겪은 뒤" 원칙을 우선한다
