# 🎯 확정 게임 기획서 — 웨이브 브레이커 (WaveBreaker)

> **확정일** 2026-08-26 / **후보 A 채택** ([비교 문서](./후보검토/README.md))
> **최종 형태**: 타이틀에서 **[혼자 하기]** 와 **[같이 하기]** 를 모두 고를 수 있는 2D 탑다운 웨이브 디펜스
> 이 문서가 Phase 4~9 수업의 **목표 사양서**다. 회차별 강의안은 전부 이 문서를 기준으로 작성한다.

## 1. 게임 개요

| | |
|---|---|
| 제목 | **웨이브 브레이커** / `WaveBreaker` (프로젝트·폴더명) |

## 2. 모드 구조 ★ (이번 확정의 핵심)

### 학생에게 보이는 것

```
        [ 타 이 틀 ]
              │
    ┌─────────┴─────────┐
[혼자 하기]          [같이 하기]
    │                   │
    │            ┌──────┴──────┐
    │        [방 만들기]   [코드 입력]
    │         코드 발급      친구 코드
    └──────────┬────────────┘
               ▼
           게임 시작
```

### 내부적으로는 하나의 코드다

> 🔑 **가장 중요한 설계 결정**
>
> **싱글 모드를 "네트워크 없는 별도 코드"로 만들지 않는다.**
> 싱글 = **아무도 안 들어온 방(호스트 1인)** 이다.

| 모드 | 내부 동작 |
|---|---|
| 혼자 하기 | `StartHost()` → 바로 게임 시작 (Relay 미사용, 접속 대기 없음) |
| 같이 하기 (방장) | `StartHost()` + Relay 코드 발급 → 1명 입장 대기 |
| 같이 하기 (참가) | 코드 입력 → `StartClient()` |

**왜 이렇게 하는가**

- 싱글용 코드와 멀티용 코드를 따로 두면 **같은 기능을 두 번 만들고 두 번 고쳐야 한다.** 노베이스 반에서 이건 재앙이다.
- "혼자 하기 = 손님이 안 온 방"이라는 설명이 노베이스에게도 직관적이다.
- 학생이 혼자 테스트할 때도 실제 네트워크 경로를 그대로 지난다 → **버그가 발표 직전이 아니라 개발 중에 드러난다.**

### 개발 순서상의 주의 ⚠️

**Phase 4~7은 네트워크 코드 없이 순수 싱글로 만든다.** NGO를 처음부터 켜면 노베이스가 Phase 4에서 무너진다.

| 시점 | 상태 |
|---|---|
| Phase 4~7 | 네트워크 없는 순수 싱글. **Phase 7에서 빌드해 백업** ← 안전장치 |
| Phase 8 초반 | NGO 도입, 기존 코드를 `NetworkBehaviour`로 이전 |
| Phase 8 후반 | **싱글 모드를 "호스트 1인"으로 재통합** → 코드 하나로 합쳐짐 |
| Phase 9 | 통합본 빌드 = 최종 제출물 |

> Phase 7의 순수 싱글 빌드는 **버리지 않고 보관한다.** Phase 8이 어떻게 되든 모든 학생이 완성작을 하나 갖고 있게 하는 장치다.

## 4. 플레이어

| 항목 | 값 | 비고 |
|---|---|---|
| 최대 체력 | 100 | |
| 이동 속도 | 5 | |
| 사격 | **자동** | 가장 가까운 적을 조준 |
| 무적 시간 | 피격 후 0.5초 | 연속 피격 방지 |
| 사망 | 쓰러짐(다운) 상태 | 즉시 게임오버 아님 |
| **부활** | 동료가 옆에서 3초 대기 | 협동의 핵심 장치 |
| 게임오버 | **둘 다** 쓰러지면 | 싱글은 본인 사망 시 즉시 |

> 💡 **자동 사격을 고른 이유**: 노베이스가 이동+조준+사격을 동시에 하면 게임이 안 된다. 코드도 단순해진다. 수동 사격은 ⭐도전 과제.

> 💡 **부활 장치**: 협동 모드에서 "같이 한다"는 감각을 만드는 유일한 메커닉. 이게 없으면 그냥 각자 하는 게임이 된다.

## 5. 무기 3종

| 무기 | 데미지 | 연사 | 특징 | 획득 |
|---|---|---|---|---|
| **기본총** | 10 | 0.3초 | 직선 1발 | 시작부터 |
| **관통총** | 15 | 0.6초 | 적 3마리 관통 | 웨이브 3 업그레이드 |
| **폭발탄** | 25 (범위) | 1.0초 | 착탄 지점 반경 2 피해 | 웨이브 6 업그레이드 |

- 무기는 **교체가 아니라 추가**된다. 획득하면 동시에 발사 → 웨이브가 갈수록 화면이 화려해진다.
- 각 무기는 `WeaponData`(ScriptableObject)로 관리 → **코드를 안 고치고 밸런싱한다.**

## 6. 적 3종 + 보스

| 적 | 체력 | 속도 | 공격 | 특징 |
|---|---|---|---|---|
| **돌진형** | 20 | 4 | 접촉 10 | 가장 흔함. 직선으로 달려듦 |
| **원거리형** | 15 | 2 | 투사체 8 | 일정 거리 유지하며 사격 |
| **탱커형** | 80 | 1.5 | 접촉 20 | 느리지만 단단함 |
| **보스** | 800 | 2 | 3패턴 | 웨이브 10. 소환 / 돌진 / 탄막 |

**클래스 구조** (Phase 4에서 배울 형태)

```
Enemy (부모)            ← 체력, 이동, 사망 처리
 ├─ ChargerEnemy        ← 플레이어를 향해 직진
 ├─ RangedEnemy         ← 거리 유지 + 발사
 └─ TankEnemy           ← 느리고 단단함

IDamageable (인터페이스) ← 플레이어와 적이 모두 구현
```

## 8. 업그레이드 (웨이브 클리어 시 3택 1)

| # | 이름 | 효과 |
|---|---|---|
| 1 | 공격력 강화 | 모든 무기 데미지 +20% |
| 2 | 연사 강화 | 발사 간격 -15% |
| 3 | 이동 강화 | 이동 속도 +15% |

## 11. 데이터 구조 (ScriptableObject)

| 애셋 | 담는 것 |
|---|---|
| `WeaponData` | 데미지, 연사, 투사체 프리팹, 관통 수, 범위 |

## 12. 네트워크 동기화 명세 (Phase 8)

| 대상 | 방식 | 권한 |
|---|---|---|
| 플레이어 위치·회전 | `NetworkTransform` | 소유자 |
| 입력 처리 | `IsOwner` 체크 | 소유자 |
| 플레이어 체력 | `NetworkVariable<int>` | 서버 쓰기 |
| 다운/부활 상태 | `NetworkVariable<bool>` | 서버 쓰기 |
| 적 생성·사망 | 서버 스폰 | **호스트 전용** |
| 적 위치 | `NetworkTransform` | 서버 |
| 피격 판정 | 서버에서만 계산 | **호스트 전용** |
| 웨이브 번호·상태 | `NetworkVariable<int>` | 서버 쓰기 |
| 업그레이드 선택 | `Rpc` (클라 → 서버) | 서버 검증 |
| 총알 시각효과 | 로컬 재생 | 각자 |

> 🔑 **Phase 4에서 심어둘 규칙 두 가지** (이때는 네트워크를 언급하지 않는다)
> 1. **적 스폰과 체력 계산은 매니저 한 곳에서만 한다**
> 2. **입력을 읽는 곳과 실제로 움직이는 곳을 분리한다**
>
> 이 두 규칙만 지키면 Phase 8에서 매니저에 `if (!IsServer) return;` 을 넣는 것으로 서버 권한 전환이 끝난다. **코드를 갈아엎지 않는다.**

## 14. 완성 판정 기준

이 목록을 전부 통과하면 **완성**이다. 학생에게 처음부터 공개한다.

**싱글 (Phase 7 시점)**

- [ ] 타이틀에서 게임을 시작할 수 있다
- [ ] WASD로 움직이고 자동으로 총이 나간다
- [ ] 적 3종이 나오고, 맞으면 죽는다
- [ ] 체력이 0이 되면 게임오버 화면이 뜬다
- [ ] 웨이브 10개가 순서대로 진행된다
- [ ] 웨이브 클리어마다 업그레이드를 고른다
- [ ] 보스를 잡으면 클리어 화면이 뜬다
- [ ] **빌드한 exe를 다른 사람이 실행할 수 있다**

**협동 (Phase 9 시점)**

- [ ] 방을 만들면 코드가 나온다
- [ ] 다른 사람이 코드로 들어온다
- [ ] 둘 다 움직이는 게 서로 보인다
- [ ] 적이 양쪽 화면에 똑같이 나온다
- [ ] 체력이 서로 보인다
- [ ] 쓰러진 동료를 부활시킬 수 있다
- [ ] 둘 다 쓰러지면 게임오버가 된다
- [ ] **[혼자 하기]도 여전히 정상 동작한다** ← 통합 후 반드시 재확인

## 15. 축소 계획 (진도가 밀릴 때 자르는 순서)

밀리는 건 정상이다. **뭘 자를지 미리 정해두면 당황하지 않는다.** 위에서부터 자른다.

| 순서 | 자를 것 | 영향 |
|---|---|---|
| 1 | 폭발탄 (무기 3종 → 2종) | 작음 |
| 2 | 보스 → 강화된 탱커 웨이브로 대체 | 중간 |
| 3 | 업그레이드 8종 → 5종 | 작음 |
| 4 | 탱커형 삭제 (적 3종 → 2종) | 중간 |
| 5 | 웨이브 10 → 7 | 작음 |
| 6 | 파티클·카메라 셰이크 연출 | 만족도 하락 ⚠️ |

**절대 자르지 않는 것**

- ❌ 업그레이드 3택 시스템 — 게임의 심장. 이게 없으면 그냥 총 쏘는 화면이다
- ❌ Phase 7의 싱글 빌드 — 안전장치
- ❌ 부활 메커닉 — 협동의 유일한 근거
