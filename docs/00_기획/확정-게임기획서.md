## 3. 모드 구조

### 학생에게 보이는 것

```
        [ 타 이 틀 ]
              │
    ┌─────────┴─────────┐
[혼자 하기]          [같이 하기]
    │                   │
    │            ┌──────┴──────┐
    │        [방 만들기]   [코드 입력]
    │         코드 발급      친구 코드
    └──────────┬────────────┘
               ▼
           게임 시작
```

### 내부적으로는 하나의 코드다

| 모드 | 내부 동작 |
|---|---|
| 혼자 하기 | `StartHost()` → 바로 시작 (Relay 미사용, 대기 없음) |
| 같이 하기 (방장) | `StartHost()` + Relay 코드 발급 → 1명 입장 대기 |
| 같이 하기 (참가) | 코드 입력 → `StartClient()` |

**왜 이렇게 하는가**

- 싱글용·멀티용 코드를 따로 두면 **같은 기능을 두 번 만들고 두 번 고쳐야 한다.** 노베이스 반에서 재앙이다.
- "혼자 하기 = 손님이 안 온 방"은 노베이스에게도 직관적이다.
- 혼자 테스트해도 실제 네트워크 경로를 지난다 → **버그가 발표 직전이 아니라 개발 중에 드러난다.**

### 개발 순서상의 주의 ⚠️

| 시점 | 상태 |
|---|---|
| Phase 5~7 | **네트워크 코드 0줄.** 순수 싱글 |
| **Phase 8 (101–105)** | **싱글 완성 → 빌드 → 전원 백업** ← 최대 안전장치 |
| Phase 9 초반 | NGO 도입, 기존 코드를 `NetworkBehaviour`로 이전 |
| Phase 9 후반 | 싱글을 "호스트 1인"으로 재통합 |
| Phase 10 | 통합본 빌드 = 최종 제출물 |

> Phase 8의 순수 싱글 빌드는 **버리지 않는다.** Phase 9가 어떻게 되든 모든 학생이 완성작을 하나 갖는다.

## 5. 무한 맵 ★ (골드메탈 04강)

### 원리

맵을 진짜로 무한히 만들지 않는다. **바닥 타일 9장을 카메라 주변에 두고, 카메라가 벗어나면 반대편으로 옮긴다.**

```
┌───┬───┬───┐
│   │   │   │   카메라가 오른쪽으로 나가면
├───┼───┼───┤   왼쪽 열 3장을 오른쪽으로 이동
│   │ 📷 │   │   → 무한히 이어져 보인다
├───┼───┼───┤
│   │   │   │
└───┴───┴───┘
```

| 항목 | 값 |
|---|---|
| 타일 1장 크기 | 20 × 20 |
| 타일 개수 | 9장 (3×3) |
| 이동 판정 | 카메라와 타일 거리가 타일 크기를 넘으면 반대편으로 |

> ⚠️ **배경만 순환시킨다.** 적·젬·플레이어는 옮기지 않는다.
> 배경까지 같이 옮기면 "적이 순간이동하는" 버그가 된다. 학생이 가장 많이 틀리는 지점이다.

### 적 스폰 위치

카메라 밖 화면 가장자리에서 스폰한다. 스폰 포인트를 **카메라 자식**으로 두면 자동으로 따라온다.

## 6. 카메라 ★★ (무한 맵 선택의 대가 — 반드시 설계)

싱글은 플레이어를 따라가면 끝이지만, **2인 협동에서 둘이 흩어지면 카메라를 어디에 둘지**가 문제가 된다.
무한 맵을 택한 이상 이걸 풀지 않으면 Phase 9에서 막힌다.

### 해법 — 중간점 + 줌아웃 + 소프트 리쉬

| 규칙 | 내용 |
|---|---|
| **위치** | 살아 있는 플레이어 **전원의 평균 좌표** |
| **줌** | 둘 사이 거리에 따라 `orthographicSize`를 늘린다 (기본 5 → 최대 8) |
| **소프트 리쉬** | 둘 사이 거리가 **최대치(14)** 를 넘으면 더 못 벌어진다 |

> 🔑 **싱글도 같은 코드로 돈다.** 플레이어가 1명이면 평균 = 그 플레이어 좌표, 거리 = 0이라 줌도 기본값이다.
> **분기문이 필요 없다.** 이게 "싱글 = 호스트 1인" 원칙이 카메라까지 이어지는 지점이다.

```
살아있는 플레이어 목록
    ↓
평균 좌표 → 카메라 위치 (부드럽게 따라감)
    ↓
최대 거리 → orthographicSize 결정
    ↓
거리 > 14 ? → 뒤처진 쪽을 당긴다 (소프트 리쉬)
```

> ⚠️ **소프트 리쉬를 "벽"으로 만들지 않는다.** 갑자기 멈추면 조작 불능처럼 느껴진다.
> 최대 거리에 가까워질수록 **이동 속도를 줄이는** 방식으로 한다.
>
> 📌 카메라는 Phase 7(091–100)에서 싱글 기준으로 먼저 만들고,
> **Phase 9에서 "플레이어 목록"으로 바꾸기만 한다.** 처음부터 목록으로 짜면 싱글에서 이해가 안 된다.

## 9. 적

### 일반 적 3종 (골드메탈 05강)

| 이름 | 체력 | 속도 | 특징 |
|---|---|---|---|
| `Walker` | 20 | 2.0 | 기본. 직선으로 다가온다 |
| `Runner` | 10 | 4.0 | 빠르고 약하다 |
| `Tank` | 60 | 1.2 | 느리고 단단하다 |

**전부 "플레이어를 향해 직진"만 한다.** 길찾기 없음 — 노베이스에게 A*는 과하다.

> 협동에서는 **가장 가까운 플레이어**를 쫓는다. 싱글에서는 그게 유일한 플레이어다. (분기 없음)

| 경과 | 스폰 간격 | 적 체력 배수 | 등장 종류 |
|---|---|---|---|
| 0–2분 | 1.0초 | ×1.0 | Walker |
| 2–4분 | 0.7초 | ×1.5 | \+ Runner |
| 4–7분 | 0.5초 | ×2.5 | \+ Tank |
| 7–10분 | 0.3초 | ×4.0 | 전부 |

### 보스 3회

| 시점 | 보스 | 처치 시 |
|---|---|---|
| 3:00 | `BossI` (체력 300) | 일반 적 스폰 재개 |

## 10. 성장 — 경험치와 레벨업 (골드메탈 11·12강)

### 경험치 젬

적이 죽으면 젬을 떨군다. 플레이어가 가까이 가면 **끌려온다** (자석 반경 1.5).

| 적 | 젬 경험치 |
|---|---|
| Walker | 1 |
| Runner | 1 |
| Tank | 3 |
| 보스 | 50 |

### 레벨업

| 레벨 | 필요 누적 경험치 |
|---|---|
| 2 | 10 |
| 3 | 25 |
| 4 | 45 |
| 5+ | 이전 필요량 × 1.4 |

레벨업하면 **시간이 멈추고 3택 1 카드**가 뜬다.

### 업그레이드 카드 (3택 1)

| 카드 | 효과 |
|---|---|
| 칼 하나 더 | 회전 근접 개수 +1 |
| 칼 빨라짐 | 회전 속도 +30% |
| 총알 빨라짐 | 원거리 연사 +25% |
| 관통 | 총알이 적 1명 더 뚫는다 |
| 피해 증가 | 전체 피해 +20% |
| 체력 회복 | 즉시 30 회복 |
| 이동 속도 | +15% |
| 자석 강화 | 젬 흡수 반경 +50% |

> ⚠️ **협동에서는 각자 고른다. 단, 시간은 둘 다 멈춘다.**
> 한 명이 고르는 동안 다른 한 명은 "상대가 고르는 중" 화면을 본다. 둘 다 고르면 재개.
> 각자 실시간으로 고르게 하면 동기화가 노베이스 수준을 넘는다.

## 15. 완성 판정 기준

### Phase 8 종료 시 (싱글 — 반드시 달성)

- [ ] 타이틀 → 게임 → 결과가 연결된다
- [ ] WASD로 움직이고 무기 2종이 자동 공격한다
- [ ] 무한 맵이 끊김 없이 이어진다
- [ ] 적 3종이 시간에 따라 강해지며 계속 나온다
- [ ] 젬을 먹어 레벨업하고 3택1을 고른다
- [ ] 보스 3회가 나오고 최종 보스를 잡으면 승리한다
- [ ] 적이 100마리 넘어도 **렉이 없다** (풀링)

- [ ] 둘의 이동·공격이 서로에게 보인다
- [ ] 카메라가 둘을 함께 담는다
- [ ] 다운된 동료를 부활시킬 수 있다
- [ ] 공유 경험치로 둘 다 레벨업한다
- [ ] 공유 링크로 남에게 보낼 수 있다
