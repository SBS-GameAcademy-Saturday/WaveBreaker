## ⚠️ 먼저 — 아트 스타일을 하나로 고정한다

Kenney 팩은 크게 **벡터/일러스트 계열**과 **픽셀 계열**로 나뉜다. **섞으면 게임이 조잡해 보인다.**
학생들이 "이거 왜 이렇게 안 예쁘죠"라고 느끼는 원인의 대부분이 스타일 혼용이다.

| 라인 | 구성 | 판단 |
|---|---|---|
| **A. 벡터/일러스트** | Top-down Shooter + Tower Defense (Top-Down) + UI Pack | ✅ **채택** — 필요한 게 다 있고 해상도가 커서 다루기 쉽다 |
| B. 픽셀 | Pixel Shmup 중심 | ❌ 16×16이라 탑다운 슈터용 소품이 부족. 픽셀은 임포트 설정 실수(블러)가 잦아 노베이스에 불리 |

> **결정: A 라인으로 통일. 픽셀 팩은 쓰지 않는다.**

## 4. ⚠️ Kenney로 해결 안 되는 것 2가지

### ① 한글 폰트

**Kenney Fonts에는 한글 글리프가 없다.** UI가 전부 한국어이므로 별도 폰트가 필요하다.

| 후보 | 라이선스 | 비고 |
|---|---|---|
| **Noto Sans KR** (Google Fonts) | OFL | 무난·안전. 기본값으로 권장 |
| 나눔고딕 / 나눔스퀘어 | 무료 (네이버) | 게임 느낌 살리기 좋음 |
| 눈누(noonnu.cc) 상업용 무료 폰트 | 폰트별 상이 | **폰트마다 조건이 다르니 반드시 개별 확인** |

> 📌 **강사가 폰트 1종을 정해 통합 패키지에 넣는다.** 학생이 각자 고르면 TMP 폰트 애셋 생성에서 시간이 통째로 날아간다.
> TMP 한글 폰트 애셋은 **글자 수가 많아 생성이 오래 걸린다.** 미리 만들어 배포할 것 (Phase 6 UI 회차 전에).

### ② 루프 BGM

Kenney의 [Music Jingles](https://kenney.nl/assets/music-jingles)는 **짧은 징글**이라 인게임 배경음악으로는 부족하다.

- **1안**: BGM 없이 진행 → SFX만으로도 게임은 성립한다. **가장 안전**
- **2안**: 외부 CC0/무료 음원 사이트에서 1곡만 골라 통합 패키지에 포함 (**강사가 라이선스 직접 확인**)
- **3안**: ⭐도전 과제로 학생이 각자 조달

> 노베이스 반에서 음악 찾기는 시간 블랙홀이다. **1안 또는 2안 권장.**

## 5. 통합 `.unitypackage` 제작 가이드 (강사 작업)

### 폴더 구조

```
Assets/
└── _GameAssets/
    ├── Sprites/
    │   ├── Characters/     플레이어, 적
    │   ├── Projectiles/    총알
    │   ├── Environment/    타일, 장애물
    │   └── UI/             버튼, 패널, 바, 아이콘
    ├── Audio/
    │   ├── SFX/
    │   └── UI/
    ├── Effects/            파티클 텍스처
    └── Fonts/              TMP 한글 폰트 애셋 (생성 완료본)
```

> `_GameAssets` 앞의 언더스코어는 Project 창 **맨 위에 고정**시키기 위함. 노베이스가 파일을 못 찾는 걸 줄인다.

### 임포트 설정 — 전원 동일하게

| 항목 | 값 | 이유 |
|---|---|---|
| Texture Type | Sprite (2D and UI) | |
| **Pixels Per Unit** | **100 통일** | ⚠️ 팩마다 다르면 캐릭터와 타일 크기가 안 맞는다 |
| Filter Mode | Bilinear | 벡터 계열이므로 |
| Compression | Normal Quality | |
| Sprite Mode | 스프라이트시트는 Multiple + Slice | 강사가 미리 잘라서 배포 |

> 🔑 **스프라이트시트 슬라이싱은 강사가 끝내서 배포한다.** Sprite Editor 사용법을 노베이스에게 가르치는 데 최소 1회차가 든다. 그 회차는 게임 만드는 데 쓰는 게 낫다.

### 배포 시 함께 줄 것

- `에셋_목록.md` — 어떤 파일이 뭔지 한 줄씩 (학생이 이름만 보고 못 찾는다)

**이펙트 팩 구조** — 파일 하나가 시트 하나이고, **행이 색상 변형 9종, 열이 애니메이션 프레임**이다.
180개 전부 가로·세로가 64로 정확히 나뉘고 **행 수는 예외 없이 9**다.

```
Part 1/03.png  832×576  =  13열 × 9행     ← 13프레임 × 색상 9종
Part 15/700.png 1408×576 = 22열 × 9행
```

**캐릭터 팩 구조** — 4캐릭터 전부 같은 상태 집합을 갖는다. 우리 코드가 필요한 것과 정확히 맞는다.

|---|---|---|

### 8.2 ✅ 임포트 설정 — 고쳤다 (2026-09-04)

**고치기 전 — Sprites 폴더 텍스처 277개 중 260개가 임포트되면서 크기가 바뀌었다.**

```
Texture Type = Default   →   NPOT Scale = ToNearest   →   가장 가까운 2의 제곱수로 리사이즈

Part 15/700.png      1408×576  →  1024×512   🚨
Soldier_Walk.png      800×100  →  1024×128   🚨
32x32-Tilesheet.png   384×352  →   512×256   🚨
Dungeon_Tileset.png   512×640  →   512×512   🚨  아래 2타일 줄이 뭉개진다
```

> 🔴 **블러가 아니라 데이터 손실이다.** 64 격자·100 격자가 어긋나서 슬라이스가 아예 안 맞는다.
> `Texture Type` 을 `Sprite` 로 바꾸면 `NPOT Scale` 이 `None` 이 되고 원본 크기가 유지된다.
> 실제로 `Part 1/03.png` 는 `Sprite` 로 되어 있어서 832×576 그대로다.

**기존 프로젝트 스프라이트와 설정이 다르다.**

| | 기존 (쓰고 있는 것) | 새로 들어온 것 |
|---|---|---|
| Texture Type | `Sprite` | 🚨 `Default` |
| Filter Mode | `Point` | 🚨 `Bilinear` — 픽셀아트가 흐려진다 |
| Compression | (Uncompressed) | 🚨 `Compressed` — 픽셀 경계가 깨진다 |
| Mip Maps | off | 🚨 on |
| PPU | 32 | 100 |

**고쳐야 하는 것 — 팩마다 PPU 가 다르다**

| 폴더 | Texture Type | Filter | Compression | **PPU** | Sprite Mode |
|---|---|---|---|---|---|

### 13.1 죽음 애니메이션 — 반납을 늦췄다

`Die()` 가 바로 `PoolManager.Despawn` 을 불러서 재생할 틈이 없던 문제.


## 16. Animator 로 갈아탐 — 2026-09-04

![Animator](에셋-참고/게임화면_Animator.png)

> 12절에서 `Animator` 대신 직접 만든 `SpriteAnimator` 를 썼다. **커리큘럼에 Animator 회차가 없다** 는 이유였다.
> **판단을 뒤집는다 — 유니티 기본 `Animator` 를 쓴다.** 직접 만든 두 컴포넌트는 지웠다.

### 16.1 만든 에셋

```

```

| 컨트롤러 | 상태 | 클립 길이 |
|---|---|---|
| `Soldier` · `Orc` (10fps) | Idle · Walk · Attack · Hurt · Death | 0.70 / 0.90 / 0.70 / 0.50 / 0.50초 |
| `Demon_A` (12fps) | 〃 | 0.58 / 0.75 / 0.67 / 0.42 / 0.42초 |
| `Blood` (7fps) | 〃 | 1.00 / 1.29 / 1.29 / 0.71 / 0.71초 |
| `Fx_Death` · `Fx_Hit` · `Fx_Pickup` · `Fx_LevelUp` | Play (한 번) | 0.65 / 0.33 / 0.38 / 0.80초 |
| `Blade` · `Projectile` · `Coin` | Play (반복) | 0.70 / 0.67 / 0.63초 |

**파라미터 4개** — `Speed`(float) · `Hurt` · `Attack` · `Die`(trigger)

| 전환 | 조건 |
|---|---|
| Idle → Walk | `Speed > 0.05` |
| Walk → Idle | `Speed < 0.05` |
| AnyState → Hurt / Attack / Death | 트리거 |
| Hurt · Attack → Idle | `exitTime 1.0` (끝나면) |
| **Attack → Walk** | `Speed > 0.05` — 아래 16.4 참고 |

> 🔑 **전환 시간(`duration`)을 전부 0 으로 뒀다.** 도트 애니메이션은 섞으면 안 된다.
> 기본값 0.25초로 두면 두 프레임이 반투명하게 겹쳐 보인다.

> 🔑 **마지막 프레임에 키를 하나 더 찍는다.** 안 그러면 클립 길이가 `(n-1)/fps` 라
> 마지막 장이 스쳐 지나간다. `frames.Length` 개가 아니라 `+1` 개를 만든다.

### 16.2 코드에서 부르는 법

```csharp
anim.SetFloat("Speed", rb.linearVelocity.magnitude);   // Idle / Walk 를 Animator 가 고른다
anim.SetTrigger("Hurt");                               // 어디서든 끼어든다
anim.SetTrigger("Attack");
anim.SetTrigger("Die");
```

`SpriteAnimator.PlayHurt()` → `anim.SetTrigger("Hurt")` 로 바뀐 것뿐이다. 부르는 자리는 그대로다.

**남긴 스크립트 하나** — [`FxAutoDespawn.cs`](../../Assets/_Project/Scripts/Effect/FxAutoDespawn.cs) (30줄).
`Animator` 는 재생만 하고 "끝나면 치우기" 는 안 해준다. 길이는 `runtimeAnimatorController.animationClips[0].length` 로 물어본다.

### 16.3 겪은 것 ① — 자식이 `Move()` 를 override 하면 안 돈다

`Speed` 를 `Enemy.Move()` 안에서 넘겼더니 **`RunnerEnemy` 만 Hurt 프레임에 멈춰 있었다.**
`RunnerEnemy` 가 `Move()` 를 override 하고 `base.Move()` 를 안 부른다.

```
Enemy_Runner(Clone)   Speed 0.00   Demon_A_Hurt_003   ← 안 움직이는 것처럼 보인다
Enemy_Charger(Clone)  Speed 2.00   Orc_Walk_007       ← 얘만 정상
```

**`FixedUpdate` 로 옮겼다.** `Move()` 를 누가 어떻게 갈아끼워도 그 다음 줄은 항상 돈다.

> 🔑 **가상 함수 안에 공통 처리를 넣으면 자식이 덮어쓸 때 같이 사라진다.**

### 16.4 겪은 것 ② — 플레이어가 Attack 에 갇혔다

총이 자동으로 계속 쏘는데 `Attack` 클립이 0.70초다. **끝나기 전에 다시 트리거되어 영원히 Attack** 이었다.
걷는 모습이 한 번도 안 나온다.

```

플레이어 Attack:Soldier_Attack01_000
플레이어 Attack:Soldier_Attack01_001   ← 계속 이것만
```

```
9.63초  상태 Walk  Soldier_Walk_002
9.69초  상태 Walk  Soldier_Walk_000
```

### 16.5 겪은 것 ③ — 컬링 모드는 재보고 정했다

`CullCompletely` 로 뒀더니 **화면 밖 몬스터가 엉뚱한 프레임에 멈춰 있었다.**
`CullUpdateTransforms` 는 상태는 돌지만 **스프라이트 커브를 안 쓴다.** `AlwaysAnimate` 만 완전하다.

> ⚠️ **상한치(250마리)에서는 미실측이다.** 51마리 기준이다.
> 나중에 프레임이 모자라면 `CullCompletely` 로 되돌리면 된다 — 대신 화면에 들어오는 순간 한 프레임이 어긋난다.

## 18. 버튼 상태 색 · 타이틀 캐릭터 — 2026-09-04

![타이틀](에셋-참고/UI_타이틀.png)
![버튼 눌림](에셋-참고/UI_버튼눌림.png)

### 18.1 버튼 상태 색 — 기본값은 반응이 없었다

```
고치기 전 (Btn_Start)
  normal      #FFFFFF
  highlighted #FFFFFF     ← 🚨 normal 과 같다. 마우스를 올려도 아무 일이 없다
  pressed     #B2B2BF     ← 푸른 회색. 이 팩의 금색 팔레트와 안 맞는다
  fade 0.08
```

**`ColorTint` 는 스프라이트 색에 곱한다.** 값이 1을 넘을 수 없으니 "밝게" 는 못 한다.
파란 채널을 낮춰 **따뜻하게** 만드는 식으로 강조했다.

| 상태 | 색 | 뜻 |
|---|---|---|
| normal | `#FFFFFF` | 원래 아트 그대로 |
| **highlighted** | `#FFE9B0` | 마우스를 올리면 **금색으로 따뜻해진다** |
| **pressed** | `#B08D4E` | 누르면 **Camel 쪽으로 확 어두워진다** |
| selected | `#FFE9B0` | 키보드로 옮겨도 같게 |
| disabled | `#6E6E6E` 알파 128 | |

`fadeDuration` 은 **0.08 그대로** 뒀다 — 097회차에 정한 값이다.
네 씬 **버튼 16개 전부**에 넣었다 (Title 3 · Result 2 · Coop 6 · Game 5).

### 18.2 타이틀에 Soldier

> 🚨 **Canvas 가 `ScreenSpaceOverlay` 라 월드 스프라이트는 캔버스 뒤로 가려진다.**
> 12절에서 만든 캐릭터 클립은 `SpriteRenderer.m_Sprite` 에 묶여 있어서 **UI `Image` 에는 안 먹는다.**

`Image.m_Sprite` 에 묶은 클립을 따로 만들었다.

```csharp
var binding = EditorCurveBinding.PPtrCurve("", typeof(Image), "m_Sprite");   // 🔑 Image
```

```
Soldier_Idle_UI.anim        6프레임 @10fps = 0.70초 (반복)
Soldier_Idle_UI.controller  상태 하나(Idle)
```

**위치는 재서 맞췄다 — 좌표를 손으로 안 적는다.**

```
칸 안 그림 17x21   칸 중심에서 (-1.0, 0.0) 만큼 치우쳐 있다
화면에서 220px 높이로 세우려면 → Image 1048x1048, 위치 (-410, -30)
```

100×100 칸에 그림이 21px 뿐이라(8.2-b) **Image 를 1048px 로 키워야 캐릭터가 220px** 이 된다.
칸 안에서 그림이 치우친 만큼 위치를 되돌려서 캐릭터가 정확히 `(-420, -30)` 에 선다.

> ⚠️ **`raycastTarget = false`** 를 꼭 넣는다. 1048px 짜리 투명 이미지가 버튼 클릭을 다 먹는다.
> `SetSiblingIndex(2)` — 배경 두 겹 바로 위, 글자·버튼보다 아래.

### 18.3 실측

```
[버튼 색]
  설정  normal #FFFFFF · highlighted #FFE9B0 · pressed #B08D4E · fade 0.08
  누른 상태 실제 색 = #B08D4E        ← CanvasRenderer 에서 읽은 값

[실제 마우스]
  Clicked 'Btn_Start' at (640.0, 352.0)   HitGameObject = Btn_Start
  클릭 후 씬 = Game                        ← EventSystem 경로로 씬 전환까지 확인

```

> ⚠️ **마우스를 "올리기만" 한 상태(highlighted)는 화면으로 못 봤다.**
> `simulate-mouse-ui` 에 hover 동작이 없다. 설정값과 `pressed` 실측으로 갈음했다.

### 18.4 겪은 것 — LongPress 를 백그라운드로 돌리면 릴리스가 안 된다

누른 화면을 찍으려고 `LongPress` 를 `&` 로 백그라운드에 돌리고 스크린샷을 찍었다.
누른 색은 잘 찍혔는데 **버튼이 눌린 뒤 씬이 안 넘어갔다.**

부모 명령이 끝나면서 백그라운드 셸이 끊겨 **릴리스가 안 간 것**이다. 버그가 아니다.
평범한 `Click` 으로 다시 재니 `Btn_Start` → `씬 = Game` 으로 정상이었다.

### 19.1 규격이 다섯 가지로 갈려 있었다

```
고치기 전
  Title   Btn_Start 340x72 (32px, Label 고정)
          Btn_Coop  340x72 (32px, Label stretch)   ← Label 설정만 다름
          Btn_Quit  340x60 (26px)                  ← 높이·글자 다름
  Result  170x66 (28px)
  Coop    180x60 (24px)
  Game    320x66 (28px)
```

**표준 하나로 맞췄다.**

| 항목 | 값 |
|---|---|
| 높이 | **72** (전부) |
| 글자 | **30px** + auto-size (최소 16) |
| Label | **stretch** anchor · 여백 **좌우 24 / 상하 12** |
| 정렬 | Center (가로·세로 가운데) |
| 세로 간격 | **94** = 버튼 72 + 틈 22 |
| 너비 | 메뉴 **340** · 나란히 놓는 것 **200** |

`Result` 는 200 폭 두 개가 겹치지 않게 가로 위치를 `±95 → ±110` 으로 벌렸다.

### 19.2 🔴 진짜 원인은 RectTransform 이 아니었다

크기를 다 맞췄는데도 **화면에서 높이가 달라 보였다.** 스프라이트 칸 안의 여백을 재봤다.

| 스프라이트 | 칸 | 그림 범위 | 위 여백 | 아래 여백 |
|---|---|---|---|---|
| `Btn_Navy` · `Btn_Olive` | 32×32 | y **7~21** (높이 15) | 10 | 7 |
| `Btn_Dark` · `Btn_Gray` | 32×32 | y **0~26** (높이 27) | 5 | 0 |

**같은 340×72 라도 Navy 는 Dark 의 55% 높이로 그려진다.** 32 격자로 자를 때
그림이 칸을 얼마나 채우는지는 안 봤기 때문이다.

**조각을 그림에 딱 맞게 다시 잘랐다.**

```
Btn_Navy   32x32 → 32x15   border (10, 4, 10, 4)
Btn_Olive  32x32 → 32x15   border (10, 4, 10, 4)
Btn_Dark   32x32 → 28x27   border (10, 8, 10, 8)
Btn_Gray   32x32 → 28x27   border (10, 8, 10, 8)
```

> 🔑 **9-slice 는 조각 안의 빈 여백까지 늘린다.** 여백이 다르면 크기를 맞춰도 다르게 보인다.
> 격자로 자른 뒤에는 **그림이 칸을 얼마나 채우는지**를 한 번 재야 한다.

> ⚠️ 나머지 18조각은 그대로다. 패널·바는 칸을 꽉 채우고 있어서 문제가 없다.

### 19.3 좁은 창에서 제목이 잘렸다

```
보내준 창 279x330
  scaleFactor = (279/1280)^0.5 x (330/720)^0.5 = 0.3161
  화면을 기준 단위로 환산하면 폭 883
  제목 RectTransform 폭 = 900   →  🚨 883 < 900 이라 넘친다
```

`CanvasScaler` 가 `match 0.5` 라 세로가 상대적으로 넉넉한 창에서는
**기준 폭이 1280 보다 좁아진다.** 900 짜리 고정 폭이 그걸 넘었다.

**고정 폭 대신 좌우로 늘리고(anchor stretch) 여백을 줬다.** 092회차 내용 그대로다.

| 씬 | 대상 | 여백 | 글자 |
|---|---|---|---|
| Title | Title · Sub · Hint | 40 | 30~82 · 12~22 · 10~18 자동 |
| Result | Title | 40 | 26~68 자동 |
| Result | 기록 세 줄 | 60 | 14~30 자동 |
| Coop | Status · Hint | 40 | 14~28 · 10~18 자동 |

320×380 에서 확인했다 — **제목이 안 잘린다.**
