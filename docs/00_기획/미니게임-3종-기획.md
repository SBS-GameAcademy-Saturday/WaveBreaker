# 미니게임 3종 기획 — 배경 · 규칙 · 필요 리소스

> **회차**: 055–065 (Phase 4, 12~13주차) · **선행 문서**: [확정-게임기획서.md](./확정-게임기획서.md) · [에셋-리소스.md](./에셋-리소스.md)
>
> 이 문서의 목적은 두 가지다.
> 1. 미니게임 3종의 **배경과 규칙을 확정**해 강의안·씬과 어긋나지 않게 한다
> 2. **필요한 리소스를 한 목록으로 모아** 나중에 Kenney 팩을 한 번에 임포트할 때 바로 쓰게 한다
>

## 0. 왜 배경을 붙이는가

미니게임은 원래 **기술 연습**이다. 그런데 배경 없이 흰 네모만 두면 학생이
"이걸 왜 만드는지" 를 못 느낀다. 그래서 **셋 다 본편(웨이브 브레이커)과 같은 세계**로 묶었다.

| 이득 | 내용 |
|---|---|
| **리소스 재사용** | Kenney 팩 **한 세트**로 미니게임 3종 + 본편이 전부 커버된다 |
| 몰입 | "본편의 프롤로그" 라고 하면 학생이 더 붙는다 |
| 연결 | 14주차에 "③번 기억나죠?" 로 자연스럽게 이어진다 |

> 🔑 **배경은 한 줄이면 충분하다.** 세계관을 길게 쓰면 아무도 안 읽는다.
> 각 게임의 배경은 **수업 시작 30초 분량**으로 잡았다.

## 1. 미니게임 ① 낙하 지대 (피하기)

**회차**: 055 · 056 · 057 | **씬**: `055_Dodge_*` · `056_Score_*` · `057_GameOver_*`

> "여러분은 **붕괴 중인 전초기지**에 있습니다. 천장이 무너져 내려요.

> 얼마나 오래 버티는지가 전부입니다."

## 3. 미니게임 ③ 웨이브 브레이커: 프롤로그 (생존 슈팅) ★

**회차**: 063 · 064 · 065 | **씬**: `063_Survival_*` ~ `065_Survival_*`

> ⭐ **3종 중 가장 중요하다.** 본 프로젝트의 축소판이고, 14주차가 여기서 이어진다.
> 진도가 밀리면 ①②를 잘라서라도 ③은 완주시킨다.

### 배경 (강사 대사 30초)

> "**여기가 본편입니다.** 여러분이 7개월 동안 만들 게임의 축소판이에요.
> 사방에서 적이 몰려오고, 총은 **알아서** 나갑니다. 여러분은 **움직이기만** 합니다.
> 시간이 지날수록 더 많이, 더 자주 나와요. **얼마나 버티나** 보는 겁니다."

### 규칙

| 항목 | 값 |
|---|---|
| 조작 | **WASD** (전방향) |
| 발사 | **자동** — 0.4초마다 가장 가까운 적에게 |
| 적 | 플레이어를 향해 직진 (속도 2), 체력 20 |
| 적 스폰 | 화면 밖 반지름 12 원 위 랜덤, 처음 2초 간격 |
| 피해 | 적이 닿으면 체력 −10, 적은 사라진다 |
| 체력 | 50 (다섯 대) |
| **웨이브** | **10초마다** 스폰 간격 −0.15초 (하한 0.25초) |
| 점수 | **버틴 시간(초)** + 도달 웨이브 |
| 끝 | 체력 0 → 결과 화면 → `R` 재시작 |

### 화면 구성

│ 생존 26초     웨이브 3        │  ← 좌상단 HUD

## 5. 임포트 체크리스트 (한 번에 할 때)

Kenney 팩을 받은 뒤 **이 순서대로** 한 번에 처리한다.

- [ ] 1. Kenney 팩 6종 다운로드 ([에셋-리소스.md](./에셋-리소스.md) 목록)
- [ ] 2. 필요한 것만 골라 `Assets/_GameAssets/Sprites/` 아래 폴더별로 배치
- [ ] 3. **임포트 설정 일괄 적용** — 여러 파일 선택 후 한 번에
  - `Texture Type = Sprite (2D and UI)`
  - **`Pixels Per Unit = 32`** ← 반드시 통일
  - `Filter Mode = Point (no filter)`
  - `Compression = None`
- [ ] 4. 걷기 시트는 `Sprite Mode = Multiple` + `Grid By Cell Size 32×32` 슬라이스
- [ ] 5. **슬라이스 이름을 `Player_Walk_0` ~ `_3` 으로 맞춘다** ← 애니메이션 클립 유지
- [ ] 6. 프리팹의 `Sprite` 칸 교체 ([리소스-교체-가이드.md](./리소스-교체-가이드.md))
- [ ] 7. **Collider 재조정** — 그림이 바뀌면 초록 선은 안 따라온다 (043)
- [ ] 8. 배경을 `Background` Sorting Layer 에 배치 (045)
- [ ] 9. 사운드는 `Assets/_GameAssets/Audio/` 에만 넣어두고 Phase 7까지 대기
- [ ] 10. 씬 10종을 열어 **Play 로 확인** (미니게임 3종 전부)
- [ ] 11. 통합 `.unitypackage` 로 내보내 학생에게 배포

> 🔑 **3번을 개별로 하면 반드시 어긋난다.** Project 창에서 여러 파일을 선택하면
> Inspector 에서 한 번에 바꿀 수 있다. PPU 가 파일마다 다르면 캐릭터 크기가 제각각이 된다.

## 6. 진도가 밀렸을 때 — 자르는 순서

[Phase4 문서](../01_Phase개요/Phase4-미니게임.md)의 방침을 여기에 구체화한다.

| 순위 | 자르는 것 | 회수 | 영향 |
|---|---|---|---|
| 1 | 배경·사운드·이펙트 | 0회차 | **없음.** 흰 네모로도 게임은 돈다 |
| 2 | 미니게임 ② 개조(062) | 1회차 | 개조 경험이 2회 → 1회 |
| 3 | 미니게임 ② 전체(058–062) | 5회차 | 배열 배치·반사를 못 한다 |
| 4 | 미니게임 ①의 개조(057 후반) | 0.5회차 | 개조 경험이 1회 |

> 🚨 **③번은 절대 자르지 않는다.** 본 프로젝트가 여기서 이어진다.
> **3개 시키려다 0개가 되는 게 최악**이다 — 하나만 남긴다면 ③.
