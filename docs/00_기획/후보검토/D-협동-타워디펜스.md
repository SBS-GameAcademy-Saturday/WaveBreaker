# 후보 D · 2인 협동 타워디펜스 + 직접 전투

> **한 줄**: 준비 시간에 둘이 타워를 짓고, 웨이브가 오면 캐릭터로도 같이 싸운다.
> **종합 평가**: ★★★★☆ — **2순위. A가 단조롭다고 판단되면 이것.**

## 1. 코어 루프

```
방 만들기 / 코드로 입장
        ↓
  준비 시간 30초 ── 자원으로 타워 건설/업그레이드
        ↓
   웨이브 시작 (적이 경로를 따라 진격)
        ↓
  타워 자동 공격 + 플레이어 직접 전투
        ↓
   웨이브 클리어 → 자원 획득
        ↓
   (10웨이브 반복)
        ↓
      보스전
```

**한 판 8~12분.** A안보다 길지만 준비/전투가 나뉘어 있어 지루하지 않다.

## 2. 화면 & 조작

| | |
|---|---|
| 시점 | 2D 탑다운 고정 카메라 |
| 이동 | WASD |
| 사격 | 자동 |
| **건설** | 준비 시간에 그리드 클릭 → 타워 선택 |
| 협동 분업 | 한 명은 건설 특화, 한 명은 전투 특화 (자연 발생) |

> 💡 **협동감이 A안보다 강하다.** "너 왼쪽 막아, 나 오른쪽에 타워 지을게"라는 대화가 자연스럽게 나온다. 비대면 수업에서 학생끼리 대화를 만드는 건 큰 가치다.

## 3. 콘텐츠 규모

| 항목 | 수량 | 비고 |
|---|---|---|
| 플레이어 | 2인 협동 | |
| **타워** | **3종** | 단발 / 연사 / 범위 |
| 플레이어 무기 | 2종 | A안보다 줄임 (타워가 있으니) |
| 적 | 3종 + 보스 1 | 경로를 따라 진격 |
| 맵 | 1~2개 | 경로가 정해진 맵 |
| 웨이브 | 10 | |
| 자원 | 1종 | 처치 시 획득 → 건설·업그레이드에 사용 |

> ⚠️ **A안의 약 1.3배 규모.** 전투 시스템과 건설 시스템을 둘 다 만들어야 한다. 버퍼 10회를 여기에 다 쓸 각오가 필요하다.

## 4. 학생이 배우게 되는 것

A안이 배우는 걸 다 배우고, 추가로:

| 추가 항목 | 형태 | 교육 가치 |
|---|---|---|
| **경제 시스템** | 자원 획득·소비·검증 | "돈이 모자라면 못 짓는다" — 조건문의 실전 |
| **그리드 배치** | 좌표 계산, 중복 배치 방지 | 배열·좌표 감각 |
| **경로 이동** | 웨이포인트 따라가기 | 간단한 AI. A* 없이 가능 |
| 타워 사거리 판정 | 범위 내 적 탐색 | `Physics2D.OverlapCircle` |

## 5. 네트워크 설계 — **여기가 D안의 숨은 강점**

| 동기화 대상 | 방식 | 난이도 |
|---|---|---|
| 플레이어 위치 | `NetworkTransform` | 하 |
| 적 (경로 진격) | 호스트 권한 스폰 | 중 |
| **타워 건설** | `Rpc` → 서버가 검증 후 모두에게 생성 | 중 |
| **자원 보유량** | `NetworkVariable` | 중 |
| 웨이브 번호·준비 시간 | `NetworkVariable` | 하 |

> 🔑 **"내가 설치한 타워가 상대 화면에도 보여야 한다"** 는 A안보다 RPC를 가르치기 좋은 소재다.
>
> A안에서는 네트워크가 "위치를 계속 보낸다"에 머무는데, D안에서는 **"내가 요청 → 서버가 판단 → 모두에게 반영"** 이라는 서버 권한 흐름이 눈에 보이는 사건으로 나타난다. 자원 검증(`돈이 있나?`)까지 서버가 하므로 **왜 클라이언트를 믿으면 안 되는지**를 자연스럽게 설명할 수 있다.

## 6. 에셋 조달 — 전부 Kenney CC0

| 필요한 것 | 출처 |
|---|---|
| **타워 3종·경로 타일·바닥** | Tower Defense (Top-Down) 팩 — **이 게임을 위해 만들어진 팩** |
| 플레이어·적·총알 | Top-down Shooter 팩 |

**A안보다 오히려 에셋 궁합이 좋다.** Tower Defense 팩이 그대로 쓰인다.

## 7. 수업 관점 장점

- **재미의 폭이 A보다 넓다.** 건설의 전략적 재미 + 전투의 손맛이 둘 다 있다.
- **협동 분업이 자연스럽다.** 학생끼리 역할을 나누게 되고, 이게 비대면 수업의 대화를 만든다.
- **경제 시스템이 조건문·검증을 가르치기 좋다.** "자원이 부족하면 못 짓는다"는 노베이스에게 조건문의 필요성을 설명하는 최고의 예제다.
- 네트워크에서 **서버 권한 개념을 사건으로 보여줄 수 있다** (5번 참고).

## 8. 리스크

| 리스크 | 심각도 | 대응 |
|---|---|---|
| **시스템이 2개 (전투 + 건설)** | 🟡 중간 | 규모가 A의 1.3배. 버퍼 10회를 여기 배정. 플레이어 무기를 2종으로 줄여 상쇄 |
| 그리드 배치 구현 | 🟡 중간 | 좌표 반올림으로 단순 구현. **A\* 경로탐색은 절대 넣지 않는다** (웨이포인트만) |
| 준비 시간이 지루할 수 있음 | 🟢 낮음 | 30초로 짧게. 준비 중에도 이동 가능하게 |
| 밸런싱 대상이 늘어남 | 🟡 중간 | ScriptableObject로 분리해두면 감당 가능 |
| 진도 밀릴 위험 | 🟡 중간 | **타워를 3종 → 2종으로 줄이는 축소 계획을 미리 준비** |

## 10. A vs D — 무엇으로 갈릴까

| | A로 가야 할 때 | D로 가야 할 때 |
|---|---|---|
| 반 분위기 | 진도 따라가기 벅찬 학생이 많을 것 같다 | 의욕이 높고 편차가 크지 않다 |
| 강사 여력 | 7개월 내 안전하게 완주가 최우선 | 버퍼까지 쓸 여유가 있다 |
| 원하는 결과물 | 확실히 완성된 게임 | 좀 더 "게임다운" 게임 |

> **판단이 안 서면 A.** D는 Phase 5(콘텐츠 16회)에서 건설 시스템을 얹는 방식으로 **중간에 A → D 전환도 가능하다.** 반대(D → A)는 어렵다. 이 비대칭 때문에도 A로 시작하는 게 안전하다.
