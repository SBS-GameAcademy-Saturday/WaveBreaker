# 후보 B · 2인 협동 던전 탐험 (탑다운 액션)

> **한 줄**: 방을 하나씩 깨며 던전을 내려간다. 문이 잠기고, 적을 다 잡으면 열린다.
> **종합 평가**: ★★★☆☆ — **학생 만족도는 최고, 강사 난이도도 최고**

## 1. 코어 루프

```
던전 입장 (2인)
      ↓
  방 진입 → 문 잠김
      ↓
   적 전멸
      ↓
 문 열림 + 보상(무기·회복)
      ↓
  (10~15방 반복)
      ↓
    보스방
      ↓
   클리어 / 전멸
```

**한 판 15~20분.** A안(5~7분)의 3배다 — 이게 수업에서 문제가 된다(리스크 참고).

## 2. 화면 & 조작

| | |
|---|---|
| 시점 | 2D 탑다운, **카메라가 플레이어를 따라감** |
| 이동 | WASD |
| 공격 | 마우스 클릭 (근접 or 원거리) |
| 상호작용 | `E` — 문·상자·레버 |
| 2인 카메라 | ⚠️ **미해결 문제** — 둘이 떨어지면 화면을 어떻게 할 것인가 |

> ⚠️ **2인 카메라가 이 안의 최대 난제다.** 선택지는 셋인데 전부 대가가 있다.
> - 각자 자기 카메라 → 서로 안 보임, 협동 체감 저하
> - 둘의 중간을 비추는 카메라 → 멀어지면 화면이 계속 줌아웃 (구현 난이도 상승)
> - **방 단위 고정 카메라** → 가장 안전하지만 결국 A안에 가까워진다

## 3. 콘텐츠 규모

| 항목 | 수량 | 비고 |
|---|---|---|
| 플레이어 | 2인 협동 | |
| 무기 | 3~4종 | 던전에서 획득 |
| 적 | 4종 + 보스 1 | 방마다 조합이 달라야 함 |
| **맵(방)** | **10~15개** | ⚠️ **여기가 공수 폭탄** |
| 상호작용 오브젝트 | 문·상자·회복 3종 | |

## 4. 학생이 배우게 되는 것

A안이 배우는 걸 **거의 다 배우고**, 추가로:

| 추가 항목 | 형태 |
|---|---|
| 씬/영역 관리 | 방 전환, 활성/비활성 처리 |
| 상호작용 시스템 | `IInteractable` 인터페이스 |
| 인벤토리(간이) | 획득한 무기 교체 |
| 레벨 데이터 | 방 프리팹 관리 |

**교육 소재 폭은 A와 대등하거나 살짝 넓다.** 문제는 소재가 아니라 공수다.

## 5. 네트워크 설계

| 동기화 대상 | 방식 | 난이도 |
|---|---|---|
| 플레이어 위치 | `NetworkTransform` | 하 |
| 적 (방 단위) | 호스트 권한 스폰 | 중 |
| **문 잠김/열림 상태** | `NetworkVariable` | 중 |
| **방 전환 (둘 다 도착 대기)** | 상태 동기화 + 대기 처리 | **상** ⚠️ |
| 아이템 획득 (선점 처리) | `Rpc` + 서버 검증 | **상** ⚠️ |

> ⚠️ **"둘 다 문 앞에 와야 다음 방으로 넘어간다"** 가 이 안의 네트워크 벽이다.
> 한 명만 넘어가면? 한 명이 접속을 끊으면? 한 명이 뒤처져 있으면? — 노베이스가 이 예외 처리를 감당하기 어렵다.
> **아이템 선점**(둘이 동시에 같은 상자를 열었을 때)도 마찬가지로 서버 권한 개념을 제대로 이해해야 풀린다.

## 6. 에셋 조달

| 필요한 것 | 출처 |
|---|---|
| 캐릭터·적 | Kenney Top-down / Tiny Dungeon 팩 |
| **던전 타일셋** | Kenney 팩 사용 가능하나 **방마다 배치를 직접 해야 함** |
| 문·상자·소품 | Kenney 팩 |

**아트 자체는 조달되지만, 방 10~15개를 배치하는 노동이 남는다.** 이건 에셋 문제가 아니라 시간 문제다.

## 7. 수업 관점 장점

- **"진행한다"는 감각이 가장 강하다.** 방을 넘어갈 때마다 성취가 생겨서 학생 몰입도는 A보다 높다.
- 던전을 각자 다르게 꾸밀 수 있어 **개인 색깔이 잘 드러난다.** 발표회에서 결과물이 다양해진다.
- 상호작용·인벤토리 등 "게임다운 시스템"을 배운다.

## 8. 리스크 (이 안을 2순위에서 뺀 이유)

| 리스크 | 심각도 | 설명 |
|---|---|---|
| **방 전환 동기화** | 🔴 높음 | 대기·이탈·예외 처리를 노베이스가 감당하기 어렵다. Phase 8 18회로 부족할 수 있음 |
| **레벨 디자인 공수** | 🔴 높음 | 방 10~15개 배치 = 코딩이 아닌 일에 최소 10회차를 쓴다. 7개월에서 이 손실이 크다 |
| **2인 카메라 문제** | 🟡 중간 | 정답이 없다. 어떻게 풀든 학생에게 설명할 게 늘어난다 |
| **한 판 15~20분** | 🟡 중간 | 수업 중 전체 루프 검증이 사실상 불가능. "고쳤다 → 확인" 사이클이 끊긴다 |
| 진도 편차 시 격차 폭발 | 🟡 중간 | 방 수가 학생마다 달라져서 "누구는 15방, 누구는 3방"이 된다 |

## 9. 적합도 세부

| 기준 | 평가 |
|---|---|
| 싱글 완결 | ★★★★★ 혼자 하는 던전 크롤러로 성립 |
| 기능 계단 | ★★★★☆ 완만하나 방 시스템이 한 덩어리로 들어옴 |
| 동기화 부담 | ★★☆☆☆ **방 전환·아이템 선점이 벽** |
| 아트 부담 | ★★☆☆☆ 에셋은 있으나 배치 노동이 큼 |
| 교육 소재 | ★★★★★ 넓음 |

## 10. 그래도 이걸 하고 싶다면

**규모를 이렇게 줄이면** 현실적이 된다.

- 방 **10~15개 → 5개** (보스방 포함)
- 방 전환을 **씬 전환이 아니라 같은 씬 안의 영역 이동**으로 (동기화 난이도 급감)
- 카메라는 **방 단위 고정** (2인 카메라 문제 회피)
- 아이템 선점 문제 회피: 상자를 열면 **양쪽 모두에게 지급**

> 다만 이렇게 줄이고 나면 A안과의 차이가 "웨이브냐 방이냐" 정도로 좁아진다. 그럴 거면 A가 낫다.
