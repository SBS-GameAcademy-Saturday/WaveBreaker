# 만들 게임 후보 — 비교 & 선정

> 7개월(130회) 노베이스 반이 **끝까지 완성할 수 있는** 게임을 고르는 문서.
> 재밌는 게임을 고르는 게 아니라 **가르칠 수 있는 게임**을 고른다.

## 선정 기준 5가지

| # | 기준 | 왜 |
|---|---|---|
| 1 | **싱글로도 완결되는가** | Phase 7에서 싱글 완성본을 확정해야 네트워크 실패 시 안전장치가 생긴다. **PvP 전용은 이 조건에서 탈락** |
| 2 | **기능을 하나씩 얹을 수 있는가** | 노베이스는 "오늘 뭐가 늘었는지" 눈에 보여야 안 나간다. 한 방에 다 만들어야 완성되는 구조는 실패 |
| 3 | **동기화할 대상이 적은가** | 화면에 100마리 뜨는 게임은 노베이스가 네트워크로 못 옮긴다 |
| 4 | **Kenney CC0 팩으로 아트가 해결되는가** | 아트에 시간을 쓰면 7개월이 부족하다 |
| 5 | **문법 전 범위가 자연스럽게 나오는가** | 억지로 끼워넣는 교육용 예제는 학생이 바로 알아챈다 |

## 결론 — ✅ **A 확정 (2026-08-26)**

> **최종 사양서: [확정-게임기획서.md](../확정-게임기획서.md)**
> 추가 결정: 최종 빌드에 **싱글 모드를 정식 기능으로 남긴다.** 타이틀에서 [혼자 하기] / [같이 하기] 선택.
> 내부적으로는 싱글 = 호스트 1인 세션이라 **코드는 하나**다.

### 1순위 — **A. 2인 협동 웨이브 디펜스** ← 채택

기준 5개를 전부 통과하는 유일한 안. 특히 **맵 1개로 끝난다**는 게 결정적이다. 노베이스 반에서 레벨 디자인은 "코딩이 아닌 일"에 시간을 쏟게 만드는 최대 함정인데, 아레나 하나에서 웨이브만 바꾸면 콘텐츠가 나온다.

### 2순위 — **D. 협동 타워디펜스** (A가 단조롭다고 판단되면)

A보다 재미 폭이 넓고, **"내가 설치한 타워가 상대 화면에도 보여야 한다"** 가 네트워크 RPC를 가르치기에 A보다 오히려 좋은 소재다. 대신 전투 + 건설 두 시스템이라 규모가 A의 1.3배. 버퍼 10회를 여기에 다 쓸 각오가 필요하다.

### C를 탈락시킨 이유 (중요)

1v1 대전은 스코프가 가장 작아 매력적으로 보이지만 **두 가지가 치명적이다.**

- **싱글 완성본이 안 나온다.** 상대가 없으면 게임이 성립하지 않으니, Phase 7의 "네트워크가 안 돼도 완성작은 남는다"는 안전장치가 통째로 사라진다. 7개월 수업에서 이걸 포기하면 안 된다.
- **적 AI를 안 만든다 = 교육 소재의 절반이 날아간다.** 상속(`Enemy` → 하위 적), 인터페이스(`IDamageable`), 상태 머신, 스폰 관리가 전부 사라진다. 남는 건 입력과 동기화뿐이다.

> 대전 요소를 넣고 싶다면 **A를 완성한 뒤 버퍼 회차에 "2인 대전 모드"를 얹는** 방식이 안전하다.

### B를 2순위에서 뺀 이유

던전 탐험은 학생 만족도가 가장 높은 안이지만 **방 전환 동기화**가 노베이스에게 큰 벽이다. "둘 다 문 앞에 와야 다음 방으로 넘어간다"를 구현하려면 상태 동기화 + 씬/영역 전환 + 대기 처리를 한꺼번에 다뤄야 한다. 게다가 방을 10개 이상 만드는 레벨 디자인 공수가 코딩 시간을 잡아먹는다.
