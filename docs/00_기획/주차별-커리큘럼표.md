# 유니티 커리큘럼 (7개월) — 주차별 제출용

> **구성 방침: C# 선행.** 1~4주차는 C# 문법 전용(콘솔 기반), 5~6주차 객체지향, **7주차부터 C# + 유니티 병행.**
> **회차 환산**: 주 5일 × 2시간 = 주당 5회 10시간. N주차 = (5N-4) ~ 5N회차. 총 28주 140회.
> 최종 산출물: 타이틀에서 **[혼자 하기] / [같이 하기]** 를 모두 지원하는 2D 협동 웨이브 디펜스.

## 📌 C# 선행 구성으로 바꾸면서 생긴 변화

### 무엇이 달라졌나

| | 이전(게임 우선) | 현재(C# 선행) |
|---|---|---|
| 유니티 진입 | 1주차 | **7주차** |
| 본 프로젝트 착수 | 12주차(056회) | **14주차(066회)** |
| 미니게임 | 12회 | **10회** |
| 본 프로젝트 제작 기간 | 45회 | **35회** |
| 21주차 싱글 빌드 | 유지 | **유지** ⭐ |

**게임 제작에 쓰는 시간이 10회차(20시간) 줄었다.** 21주차 싱글 완성·빌드 시점은 그대로 지켰지만, 그 앞 구간이 그만큼 촘촘해졌다.

### 그래서 미리 정해두는 것

**① 진도가 밀리면 자르는 순서** (위에서부터)

1. 폭발탄 (무기 3종 → 2종)
2. 보스 → 강화된 탱커 웨이브로 대체
3. 업그레이드 8종 → 5종
4. 탱커형 몬스터 삭제
5. 웨이브 10 → 7

> **절대 자르지 않는 것**: 업그레이드 3택 시스템 / 21주차 싱글 빌드·백업 / 동료 부활 메커닉

**② 그래도 부족하면**: 미니게임을 3개 → 2개(①③)로 줄여 5회차를 회수한다. ③ 웨이브 슈팅은 본 프로젝트의 축소판이라 반드시 남긴다.

### ⚠️ C# 선행 구간의 최대 리스크와 대응

**1~4주차 4주 동안 콘솔 화면만 본다.** 비대면 노베이스 반에서 이 구간이 이탈 위험이 가장 높다.

| 대응 장치 | 내용 |
|---|---|
| **1주차 첫날 완성작 시연** | 7개월 뒤 만들 게임을 먼저 보여주고 시작한다. 필수 |
| **매주 마지막 회차 결과물 발표** | 콘솔 프로그램도 "내가 만든 것"이다. 시연 자리를 매주 만든다 |
| **콘솔 실습을 게임 소재로** | 숫자 맞히기·구구단 대신 **체력/데미지 계산, 몬스터 스탯 출력** 등 게임 문맥으로 예제를 구성 |
| (선택) **주 1회 유니티 미리보기** | 그 주 배운 문법을 유니티에서 한 번 써보는 회차를 넣으면 이탈이 크게 준다. 단 진도가 5회 늘어난다 |

> 마지막 항목은 **아직 표에 반영하지 않았다.** 넣으실 거면 27~28주차 버퍼에서 5회를 당겨오면 된다.

### 레퍼런스 커리큘럼과의 차이

레퍼런스에 있던 문법 중 **구조체(struct), 템플릿(제네릭) 클래스, 연산자 오버로딩**은 뺐다. 만들 게임에서 사용처가 없고 노베이스에게 추상도가 높아서인데, 기관이 요구하면 4주차 또는 27주차에 편성할 수 있다. **property, static, switch, Visual Studio 디버깅은 전부 포함**했다.
