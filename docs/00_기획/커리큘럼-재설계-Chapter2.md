# 🔁 Chapter 2 커리큘럼 재설계 (071–090)

> **원칙 한 줄 — 한 종류로 전투를 먼저 완주하고, 종류는 데이터로 늘린다.**
> 14주차(066–070)는 그대로 둔다. **071부터 다시 짠다.**
>
> ⚠️ 설계안이다. 강의안은 아직 안 고쳤다.

---

## 1. 왜 바꾸나

기존 순서는 **072에서 몬스터를 3종으로 늘린다.** 그런데 그 시점에 게임은 아직
"적이 쫓아오기만" 하는 상태다. 스폰도 웨이브도 공격도 없다.

```
기존   071 추적 → 072 3종 → 073 스폰 → 074 웨이브 → 075 공격
                    ↑
            한 바퀴도 안 돌았는데 종류부터 늘린다
```

**문제 셋.**

| | |
|---|---|
| ① | 적을 **죽일 수 없는 상태**에서 "단단한 적" 을 만든다. 탱커인지 아닌지 확인할 방법이 없다 |
| ② | 종류를 늘리려고 **클래스를 셋 만든다.** 그런데 088에서 전부 지운다 (B안) |
| ③ | 한 바퀴를 안 돌려봐서 **뭐가 부족한지 모른 채** 콘텐츠를 늘린다 |

**바꾼 순서.**

```
새로   071 추적 → 072 스폰 → 073 웨이브 → 074 공격 → 075 다듬기
       ───────────── 오크 한 종류로 여기까지 ─────────────

       088 EnemyData → 에셋 3개로 3종이 된다 (클래스 0개)
```

## 3. 새 075 — "한 판을 돌려보고 고친다"

**신설 회차다.** 074까지 하면 게임이 한 바퀴 돈다. 그런데 돌려보면 **눈에 띄는 문제가 셋** 나온다.
그걸 고치는 게 075다.

> 🔑 이 과정의 원칙 4번 — **"불편함을 먼저 겪게 한 뒤 해결책을 준다."**
> 075는 그 원칙을 한 회차로 만든 것이다.

### ① 몬스터가 기둥처럼 쌓인다

**실측** — 오크 7마리가 모인 상태에서 서로의 거리를 쟀다.

```
Enemy x Enemy 충돌 무시 = True
가장 가까운 두 마리 거리  0.000      ← 완전히 포개짐
거리 0.3 미만인 쌍        1 / 21    (콜라이더 폭이 1.2 다)
```

화면에는 8마리가 있는데 **기둥 두 개처럼** 보인다.

**원인** — 072에서 "몬스터끼리 서로 때려 죽는다" 를 `Enemy × Enemy` 충돌 해제로 막았다.
그랬더니 **서로 밀어내지 않아서** 한 점으로 모인다.

**고치는 법 — 충돌은 켜고, 같은 편은 안 때린다.**

```csharp
private void OnCollisionEnter2D(Collision2D collision)
{
    // 🔑 같은 편은 때리지 않는다
    if (collision.gameObject.CompareTag("Enemy")) return;

    if (collision.gameObject.TryGetComponent(out IDamageable target))
    {
        Attack(target);
    }
}
```

> 💬 "충돌을 **끄는 게** 답이 아니었어요. 끄니까 겹쳤죠."
> 💬 "**누구를 때릴지** 를 정하는 게 답입니다. 한 줄이에요."
>
> ⚠️ **미실측** — 충돌을 켜고 이 한 줄을 넣었을 때 실제로 안 겹치는지는 아직 안 재봤다.
> 075 강의안을 쓰기 전에 측정한다.

### ② 플레이어가 밀린다

`Player.Rigidbody2D.bodyType` 을 `Kinematic` 으로.

**실측** — 몬스터 6마리가 붙어도 플레이어 위치가 `(0.00, 0.00)` 에서 안 움직였고,
체력은 20 → 11 로 깎였다. **안 밀리면서 피해는 받는다.**

### ③ 죽어도 아무 일이 없다

게임오버 화면이 없다. `GameState.GameOver` 로 바꾸고 멈춘다.
(기존 080 "코어 루프 완성" 의 일부를 여기로 당긴다)

### ④ 그리고 군집 — 4장

문제를 고친 뒤에 **오크 군집**을 넣는다. 15주차의 마지막 장면이다.

> 🚨 **075 가 빡빡하다.** 겹침 + 밀림 + 게임오버 + 군집 = 네 덩어리다.
> 2시간에 안 들어가면 **③(게임오버)을 080 으로 되돌린다.**
> ④(군집)는 빼지 않는다 — 088 의 근거가 되는 경험이다.

## 4. 새 075 의 ④ — "군집"

문제 셋을 고친 **뒤에** 넣는다. **오크로 한다** — 아직 한 종류다.

```
SpawnRoutine    2초마다 한 마리       (자기 일만)
WaveRoutine     15초마다 난이도 ↑     (자기 일만)
ClusterRoutine  20초마다 8마리 × 3연속 (자기 일만)
```

**실측** — 군집 1회에 러너 0 → 8마리, 중심에서 가장 먼 거리 2.94 (반지름 2.5).
자동 버스트도 매번 다른 지점에서 돌았다: `(0,-14)` `(-9.9,9.9)` `(9.9,9.9)` `(14,0)`.

> 🔑 **여기가 이 재설계의 핵심 장면이다.** 그래서 15주차의 **마지막**에 둔다.
> 겹침·밀림을 고쳐 놓은 뒤라야 떼가 제대로 보인다 —
> 안 고치고 떼를 부르면 **기둥 하나**가 밀려올 뿐이다.
>
> 적은 **한 종류뿐인데** 한 마리씩 올 때와 떼로 올 때가 완전히 다르다.
>
> 💬 "적을 늘리지 않고도 **다른 적**을 만들었습니다."
> 💬 "종류를 가르는 건 셋이에요 — 그림, 숫자, 그리고 **나오는 방법.**"

이 경험이 **088에서 클래스를 지울 때의 근거**가 된다.

## 5. 새 088 — 에셋 3개로 3종이 된다

기존 072(몬스터 3종)의 내용이 여기로 온다. **다만 클래스를 안 만든다.**

| | 기존 072 | 새 088 |
|---|---|---|
| 만드는 것 | 클래스 3개 + 프리팹 3개 | **에셋 3개** |
| 코드 | `override Move` · `override TakeDamage` | **없음** |
| 시점 | 전투도 안 되는 때 | SO 를 배운 직후 |

```
Enemy_Orc     체력 20 · 속도 2.0 · 피해 2 · 크기 1.0
Enemy_Demon   체력  4 · 속도 5.5 · 피해 1 · 크기 0.85
Enemy_Blood   체력 45 · 속도 1.1 · 피해 4 · 크기 1.3 · 감소 0.5
```

> 🎉 💬 "**스크립트를 한 줄도 안 짜고** 몬스터가 셋이 됐습니다."
> 💬 "073에서 군집으로 한 번 겪었죠? 그때 '나오는 방법' 으로 늘렸고, 오늘은 '숫자' 로 늘립니다."

**상속은 090에서 돌아온다** — 보스는 죽을 때 하는 일이 다르다. 숫자가 아니라 **행동**이다.

## 6. 상속은 어디서 가르치나

072를 없애면 **다형성 수업이 사라진다.** 어디서 가르치는지 정리한다.

| 회차 | 가르치는 것 | 남는가 |
|---|---|---|
| 026–030 (6주차) | 상속 · `virtual` · 인터페이스 (콘솔) | ✅ 그대로 |
| 070 | `abstract Enemy` · `IDamageable` **를 유니티에서** | ✅ 그대로 |
| 088 | **안 나눠도 되는 경우**를 배운다 | ✅ 신규 |
| 090 | **나눠야 하는 경우**를 배운다 (`BossEnemy.Die`) | ✅ 그대로 |

> 🔑 **상속 수업이 줄어든 게 아니라 순서가 바뀐 것이다.**
> 전: 070 배운다 → 072 세 번 쓴다 → 088 다 지운다 (**혼란**)
> 후: 070 배운다 → 088 "안 써도 되네" → 090 "이건 써야겠네" (**판단**)
