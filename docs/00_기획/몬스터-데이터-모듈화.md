# 🧩 몬스터 데이터 모듈화 — ScriptableObject 설계

> 2주에 걸쳐 단계별로 간다. 1주차는 **한 종류로 전투를 돌리고**, 2주차는 **그걸 데이터로 뺀다.**
> 관련: [몬스터-기획.md](./몬스터-기획.md) · [확정-게임기획서.md](./확정-게임기획서.md) 13장 · [Phase6](../01_Phase개요/Phase6-콘텐츠.md)
>
> ⚠️ **이 문서는 설계안이다. 아직 구현하지 않았다.**

## 1. 2주 계획 — 무엇을 언제

### 1주차 · 한 종류로 전투를 완성한다

**`OrcWalker` 한 종류만** 쓴다. 러너·탱커는 꺼둔다.

| 끝났을 때 되는 것 |
|---|
| 오크가 화면 밖에서 나와 플레이어를 쫓는다 |
| 부딪히면 피가 깎인다 |
| Space 로 때리면 죽는다 |
| 웨이브가 올라가며 더 자주 나온다 |
| HUD 에 체력·웨이브·처치가 보인다 |

> 🔑 **종류를 늘리지 않는 게 요점이다.** 한 종류로 "나온다 → 쫓는다 → 맞는다 → 죽는다"
> 한 바퀴가 제대로 돌아야 한다. 그 다음에 늘려야 늘린 게 뭔지 보인다.
>
> 🚨 지금 코드는 이미 3종이 들어가 있다. **2종을 빼는 것부터 시작한다.** 5장 참고.

**수치는 코드에 박아둔다.** 일부러 그런다 — 2주차에 "고치기 불편하다" 를 겪어야 하기 때문이다.
087회차 강의안의 설계 의도가 그렇다.

### 2주차 · 데이터로 빼고 레벨 디자인을 한다

| 끝났을 때 되는 것 |
|---|
| 적 종류를 **에셋 하나 만들면** 추가된다. 스크립트를 안 짠다 |
| 언제 무엇이 어떻게 나올지를 **표 하나**로 정한다 |
| 밸런싱이 **Play 를 멈추지 않고** 된다 |

**이 두 번째 줄이 레벨 디자인이다.** 2장의 `WaveTable` 이 그 표다.

## 2. SO 두 장으로 끝난다

```
EnemyData   "이 적은 어떤 적인가"      ← 적 한 종류당 에셋 1개
WaveTable   "언제 무엇이 나오는가"      ← 스테이지당 에셋 1개
```

### EnemyData — 적 한 종류

```csharp
[CreateAssetMenu(menuName = "WaveBreaker/Enemy Data")]
public class EnemyData : ScriptableObject
{
    [Header("정체")]
    public string displayName;
    public Sprite icon;                       // HUD·도감용

    [Header("보이는 것")]
    public RuntimeAnimatorController animator;
    public float scale = 1f;                  // 보스는 2.5~3.5
    public Color tint = Color.white;          // 보스 색조

    [Header("수치")]
    public int maxHealth = 20;
    public float moveSpeed = 2f;
    public int contactDamage = 2;

    [Header("보상")]
    public int gemExp = 1;                    // 081회차
}
```

**적 종류를 늘리는 게 에셋 하나 만드는 일이 된다.** 스크립트를 안 짠다.
그림 3종으로 6종, 10종을 만들 수 있다 — 배율과 색조가 있기 때문이다.

### WaveTable — 레벨 디자인 ⭐

```csharp
public enum SpawnPattern { Trickle, Cluster, Surround, Boss }

[System.Serializable]
public class SpawnStep
{
    public float startTime;        // 이 초부터 적용
    public SpawnPattern pattern;
    public EnemyData enemy;

    public float interval = 2f;    // Trickle: 몇 초마다 한 마리
    public int count = 8;          // Cluster/Surround: 한 번에 몇 마리
    public int burst = 1;          // 연달아 몇 번
    public float burstGap = 1.5f;  // 연달아 나올 때 간격
    public float healthScale = 1f; // 체력 배수
}

[CreateAssetMenu(menuName = "WaveBreaker/Wave Table")]
public class WaveTable : ScriptableObject
{
    public SpawnStep[] steps;
}
```

**이 에셋 한 장이 한 판의 전부다.** 예를 들면 이렇게 짠다.

| startTime | pattern | enemy | 설정 | 의도 |
|---|---|---|---|---|
| 0 | `Trickle` | Orc | 2.0초마다 | 혼자 다 잡힌다. 조작을 익힌다 |
| 60 | `Trickle` | Orc | 1.2초마다 | 슬슬 벅차다 |
| 90 | `Cluster` | Runner | 8마리 × 3연속 | **첫 위기.** 떼가 온다 |
| 150 | `Trickle` | Tank | 6초마다, 체력 ×1.5 | 안 죽는 놈이 섞인다 |
| 180 | `Boss` | BossOrc | — | 리듬이 끊긴다 |

> 💬 **"이 표를 고치면 다른 게임이 됩니다. 코드는 한 줄도 안 건드려요."**
> 089회차 밸런싱 실습이 바로 이 표를 만지는 시간이다.

## 3. 무엇을 빼고 무엇을 남기나

088회차 강의안이 이미 선을 그어 놓았다 — **"전부 빼는 게 정답이 아니다."**

| | 어디로 | 왜 |
|---|---|---|
| 체력 · 속도 · 접촉 피해 | **`EnemyData`** | 종류마다 다른 **숫자** |
| 스프라이트 · 컨트롤러 · 배율 · 색조 | **`EnemyData`** | 종류마다 다른 **겉모습** |
| 젬 경험치 | **`EnemyData`** | 숫자 |
| 스폰 시점 · 패턴 · 마릿수 · 체력 배수 | **`WaveTable`** | 레벨 디자인 |
| **탱커의 피해 감소 공식** | 코드에 남긴다 | 숫자가 아니라 **규칙**이다 |
| **돌진형의 충돌 판정** | 코드에 남긴다 | 행동이다 |
| **보스의 고유 행동** | 코드에 남긴다 | 행동이다 |

> 🔑 **가르는 기준: "숫자를 바꾸면 되나, 코드를 바꿔야 하나."**
> `damageReduction = 0.5` 라는 **값**은 SO 로 뺄 수 있다.
> 하지만 "받은 피해에 (1−감소율)을 곱하고 최소 1을 보장한다" 는 **공식**은 코드다.
>
> 💬 "값은 데이터, **판단은 코드**입니다."

## 4. 코드가 어떻게 바뀌나

### Enemy — 수치를 SO 에서 읽는다

```csharp
public abstract class Enemy : MonoBehaviour, IDamageable
{
    [SerializeField] protected EnemyData data;   // ← 이거 하나로 바뀐다

    protected int currentHealth;
    private float healthScale = 1f;              // WaveTable 이 넘겨준다

    // 🔑 Setup 은 WaveManager 가 스폰 직후 부른다.
    //    Start() 보다 먼저 값이 들어가야 한다.
    public void Setup(EnemyData d, float scale)
    {
        data = d;
        healthScale = scale;

        GetComponent<SpriteRenderer>().color = d.tint;
        GetComponent<Animator>().runtimeAnimatorController = d.animator;
        transform.localScale = Vector3.one * d.scale;
    }

    protected virtual void Start()
    {
        currentHealth = Mathf.RoundToInt(data.maxHealth * healthScale);
        ...
    }

    protected virtual void Move()
    {
        rb.linearVelocity = dir * data.moveSpeed;   // 필드 대신 data.
    }
}
```

**프리팹이 하나로 줄어든다.** 지금은 `Enemy_Charger` · `Enemy_Runner` · `Enemy_Tank`
세 개인데, 수치·그림이 전부 SO 로 가면 **`Enemy_Base` 하나**면 된다.
`TankEnemy` 처럼 행동이 다른 것만 프리팹을 따로 둔다.

| | 지금 | 2주차 뒤 |
|---|---|---|
| 프리팹 | 3개 | **1~2개** |
| 적 종류를 늘리려면 | 프리팹 + 스크립트 | **에셋 1개** |

### WaveManager — 표를 읽고 돌린다

```csharp
public class WaveManager : MonoBehaviour
{
    [SerializeField] private WaveTable table;
    [SerializeField] private GameObject enemyBasePrefab;
    [SerializeField] private Transform[] spawnPoints;

    // 지금 시각에 해당하는 step 들을 골라 각자의 코루틴으로 돌린다
    private IEnumerator Run() { ... }

    public GameObject SpawnAt(EnemyData d, float healthScale, Vector3 pos)
    {
        var go = Instantiate(enemyBasePrefab, pos, Quaternion.identity);
        go.GetComponent<Enemy>().Setup(d, healthScale);
        return go;
    }
}
```

> 🔑 **생성 통로는 여전히 `SpawnAt()` 하나다.** 설계 규칙 ① 은 그대로다.
> 패턴이 넷으로 늘어도, 분열이 생겨도 전부 여기를 거친다.

### 1주차 — 빼는 것부터

> 🚨 프리팹을 지우지 않는 이유 — 2주차에 `EnemyData` 로 되살린다. 지우면 다시 만들어야 한다.

### 2주차 — 빼낸다

| 파일 | 박혀 있는 값 | 어디로 |
|---|---|---|
| `Enemy.cs` | `maxHealth 10` · `damage 1` · `moveSpeed 2` | `EnemyData` |
| `TankEnemy.cs` | `damageReduction 0.5` | `EnemyData`(값) / 공식은 코드 |
| `ChargerEnemy.cs` | `chargeDamage 3` | `EnemyData` |
| `WaveManager.cs` | `spawnInterval 2` · `minInterval 0.4` · `intervalStep 0.3` · `waveDuration 15` | **`WaveTable`** |

| `PlayerAttack.cs` | `attackRadius 3` · `damage 4` · `cooldown 0.4` | `WeaponData` (088) |
| `PlayerHealth.cs` | `maxHealth 20` | `PlayerData` (088) |

> `CameraFollow` · `InfiniteGround` · `PlayerController` 의 값은 **안 뺀다.**
> 레벨 디자인에서 건드릴 일이 없고, 한 번 정하면 끝이다.

## 6. 회차 매핑

커리큘럼에 이미 자리가 있다. **새로 만들 필요 없이 그 10회차를 쓴다.**

### 17주차 (081–085) — 1주차에 해당

| 회차 | 원래 주제 | 이 설계에서 |
|---|---|---|
| 081 | 경험치 젬 드롭 | 오크만 떨군다 |
| 082 | 자석 흡수 | — |
| 083 | 경험치·레벨업 곡선 | — |
| 084 | 시간을 멈춘다 | — |
| 085 | 업그레이드 3택 1 | — |

> 전투 한 바퀴는 이미 075에서 돌고 있다. 17주차는 그 위에 **성장**을 얹는 주차다.
> "1주차 = 한 종류로 전투 완성" 은 **075까지로 이미 끝나 있다.** 5장의 "빼는 것" 만 하면 된다.

### 18주차 (086–090) — 2주차에 해당

| 회차 | 하는 것 |
|---|---|
| 086 | 업그레이드 8종 (SO 전 단계) |
| **087** | **불편을 겪는다 → `EnemyData` 하나만** (오크) |
| **088** | **3종 전부 + 무기 수치.** 무엇을 남길지 판단 (3장) |
| **089** | `UpgradeData` + **밸런싱 실습** — `WaveTable` 을 만진다 |
| 090 | 보스 3종 — `EnemyData` 의 배율·색조로 |

> 🔑 **087 의 순서를 바꾸면 안 된다.** 강의안에 🔴 로 적혀 있다.
> "수치 여덟 군데를 손으로 고치는 불편" 을 먼저 겪어야 SO 가 왜 필요한지 안다.
> 먼저 SO 를 주면 학생은 "그냥 그렇게 하라니까 했다" 가 된다.

## 7. `WaveTable` 이 보스까지 먹는다

보스를 따로 만들지 않는다. **`SpawnPattern.Boss` 한 줄이다.**

| startTime | pattern | enemy | 효과 |
|---|---|---|---|
| 180 | `Boss` | `BossOrc` (EnemyData) | 한 마리 소환 + **일반 스폰 정지** |

`BossOrc` 는 `EnemyData` 에셋 하나다 — 오크 그림에 `scale 2.5`, `maxHealth 300`.
**스크립트를 안 짠다.** 보스의 고유 행동이 필요해질 때만 그때 코드를 만든다.

> 기획서는 보스 3종을 요구하는데, 그림이 없다. [몬스터-기획.md](./몬스터-기획.md) 6장 A안이
> `EnemyData` 의 `scale` · `tint` 로 그대로 구현된다.

## 8. 설계 검토 — 찾은 구멍 6개

설계를 쓰고 다시 뜯어봤다. **구현 전에 메워야 하는 것들이다.**

### 구멍 ① `WaveTable` 의 step 이 겹칠 때 규칙이 없다 🔴 *(10장 — 이번 2주에는 안 만든다)*

```
startTime 0   Trickle  Orc  2.0초마다
startTime 60  Trickle  Orc  1.2초마다
startTime 90  Cluster  Runner  8마리
```

60초가 되면 **앞의 Trickle 이 멈추나, 둘 다 도나?** 문서에 안 적혀 있었다.

| 모델 | 동작 | 문제 |
|---|---|---|
| **구간** | step 은 "다음 step 까지"의 설정. 항상 하나만 활성 | "꾸준히 + 가끔 떼" 를 **동시에 못 한다** |
| **레이어** | step 마다 독립 코루틴 | 언제 끝나는지를 정해야 한다 |

이 게임은 Trickle 과 Cluster 가 **동시에 돌아야 한다.** 그래서 레이어 모델이고,
`SpawnStep` 에 **`endTime` 을 추가해야 한다.**

```csharp
public float startTime;
public float endTime = 9999f;   // ← 추가. 이 시각에 이 step 이 멈춘다
```

### 구멍 ② 보스가 일반 스폰을 멈추는 방법이 없다 🔴

기획서는 "보스 등장 중에는 일반 적 스폰을 멈춘다" 고 못박았다.
레이어 모델에서는 각 step 이 독립 코루틴이라 **서로를 모른다.**

```csharp
// WaveManager
public bool BossActive { get; private set; }

// Trickle·Cluster 코루틴 안에서 매 반복마다
if (BossActive) { yield return null; continue; }
```

보스가 죽으면 `BossActive = false`. 이걸 안 넣으면 보스전에 잡졸이 계속 쏟아진다.

### 구멍 ③ `SpawnStep` 필드가 8개라 089 에서 혼란스럽다 🟡

`pattern` 에 따라 쓰는 필드가 다르다. Trickle 은 `interval` 만, Cluster 는 `count`·`burst`·`burstGap` 만.
**학생 Inspector 에는 안 쓰는 칸이 항상 절반 보인다.** 밸런싱 실습 시간에 "이 칸은 뭐예요?" 가 쏟아진다.

| 해결 | 비용 |
|---|---|
| 커스텀 에디터로 패턴별 필드만 표시 | **과하다.** 노베이스 과정에 에디터 확장은 범위 밖 |
| `[Header]` 로 묶고 "Trickle 전용" 처럼 라벨링 | 싸다. **이걸로 간다** |
| Phase 6 에서는 `Trickle`·`Cluster` **둘만** 노출 | 같이 한다. Surround·Boss 는 090 에서 연다 |

### 구멍 ④ `Wave` 번호와 `startTime` 이 공존하지 못한다 🔴 *(10장 — 이번 2주에는 안 만든다)*

현재 코드는 **웨이브 번호** 기반이다.

```csharp
Wave++;                                      // 15초마다
spawnInterval = Max(spawnInterval - 0.3, 0.4);
GameObject prefab = enemyPrefabs[Random.Range(0, Min(Wave, 길이))];
```

설계는 **경과 초** 기반이다. 둘은 같이 못 산다.
그리고 **HUD 가 `Wave` 를 표시하고 있다.** 없애면 화면이 바뀐다.

**해결 — `Wave` 는 표시용으로만 남기고 파생값으로 만든다.**

```csharp
public int Wave => Mathf.FloorToInt(elapsed / 15f) + 1;   // 표시 전용
```

스폰 판단에는 `Wave` 를 안 쓴다. `WaveTable` 의 `startTime` 만 본다.

### 구멍 ⑤ `data` 가 비면 터진다 🟡

```csharp
protected virtual void Start()
{
    currentHealth = Mathf.RoundToInt(data.maxHealth * healthScale);  // data 가 null 이면 NRE
}
```

`Setup()` 은 `WaveManager` 가 부른다. 그런데 **씬에 손으로 놓은 적**(테스트용, 강사 시연용)은
`Setup` 이 안 불린다. 수업 중에 학생이 프리팹을 Hierarchy 로 끌어다 놓으면 바로 터진다.

```csharp
// 방어 — data 가 없으면 Inspector 기본값을 쓴다
if (data != null) { maxHealth = data.maxHealth; moveSpeed = data.moveSpeed; ... }
currentHealth = Mathf.RoundToInt(maxHealth * healthScale);
```

필드를 지우지 말고 **남겨두고 덮어쓰는** 방식이 안전하다. 087 의 "하나만 바꿔본다" 와도 맞다.

### 구멍 ⑥ 프리팹을 하나로 합치면 072 수업이 사라진다 🟡

**측정했다.** 세 프리팹은 **스크립트와 스프라이트만 다르고 나머지가 전부 같다.**

```
콜라이더   size (1.20, 2.00) · offset (0.00, -0.60) · trigger False   ← 3종 동일
스프라이트 PPU 25 · rect (100, 100)                                   ← 3종 동일
rb         Dynamic · Interpolate                                      ← 3종 동일
layer/tag  Enemy / Enemy                                              ← 3종 동일
scale      (1, 1, 1)                                                  ← 3종 동일
```

즉 **합칠 수 있다.** 그런데 어디까지 합치냐가 갈린다.

| 안 | 프리팹 | 072 수업 재료 |
|---|---|---|
| A. 2개 `Enemy_Base` + `Enemy_Tank` | 탱커만 스크립트가 다르니 따로 | `TakeDamage()` override 하나 남음 |
| **B. 1개** `damageReduction` 도 `EnemyData` 로 | 전부 데이터 | 없어진다 |

> ✅ **B 로 확정했다.** 자식 클래스 셋을 전부 지우고 프리팹도 하나로 간다.
> 072 의 다형성 재료가 사라지는 문제는 **088 수업 안에서 푼다** —
> "지울 수 있는지 판단하려면 먼저 쓸 줄 알아야 한다" 로 설명하고,
> **090 에서 보스가 `BossEnemy` 로 다시 상속을 꺼낸다.** 보스는 숫자가 아니라
> **죽을 때 하는 일**이 다르기 때문이다. 기준은 그대로다 —
> **숫자가 다르면 데이터, 행동이 다르면 클래스.**

B 가 코드로는 더 깔끔하다. 하지만 072 가 다형성 수업이라 override 가 **하나는 있어야 한다.**

> **A 를 추천한다.** 그리고 088 에서 이 선택 자체를 수업 재료로 쓴다 —
> 💬 "탱커도 데이터로 뺄 수 있어요. 근데 그러면 **클래스가 하나도 안 남습니다.**"
> 💬 "어디까지 뺄지는 정답이 없어요. **팀이 정하는 겁니다.**"
>
> 이건 088 강의안이 이미 말하려던 것("무엇을 남길지 스스로 판단한다")과 정확히 같다.

## 10. `WaveTable` 은 086–090 에 넣지 않는다

설계 2장에서 `WaveTable` 을 레벨 디자인의 핵심으로 잡았는데, **강의안을 열어보니 자리가 없다.**

| 회차 | 이미 들어 있는 것 | 여유 |
|---|---|---|
| 086 | 업그레이드 8종 | 없음 |
| 087 | 밸런싱 지옥 15분 + SO 도입 4단계 + 함정 2개 | 없음 |
| 088 | 몬스터 + 무기 + **클래스 지우기** | 없음 |
| 089 | `UpgradeData` 4단계 + **밸런싱 실습 40분** | 없음 |
| 090 | `BossEnemy` + 데이터 + 시각 소환 + 클리어 + 회고 | 없음 |

그리고 **090 이 이미 시각 기반 소환을 갖고 있다.**

```csharp
Elapsed += Time.deltaTime;
if (Elapsed >= bossTimes[nextBoss]) SpawnBoss(nextBoss++);
```

`WaveTable` 을 넣으면 이걸 **대체**하게 된다. Phase 마지막 회차에서 이미 되는 걸
갈아엎는 건 위험하고, 새 SO 개념 하나를 더 얹을 시간도 없다.

**결론 — 2주 안에서는 이만큼이 레벨 디자인이다.**

| 레벨 디자인 수단 | 어디서 | 회차 |
|---|---|---|
| 적 수치·겉모습 | `EnemyData` 에셋 | 087·088 |
| 무기 수치 | `WeaponData` 에셋 | 088 |
| 업그레이드 | `Upgrade_*` 에셋 8~9개 | 089 |
| 스폰 간격·웨이브 길이 | `WaveManager` Inspector | 089 실습 |
| 보스 시각·종류 | `bossTimes` · `bossData` | 090 |

**스폰 타이밍만 아직 SO 가 아니다.** 그래도 Inspector 에서 고칠 수 있어서
089 의 40분 밸런싱 실습은 그대로 성립한다.

`WaveTable` 은 **Phase 7 이후 또는 도전 과제**로 미룬다. 설계 9장의 `SpawnStep` 은
그때 쓸 수 있게 남겨 둔다.

## 11. 아직 안 정한 것

- **`healthScale` 을 `WaveTable` 에 둘지 `EnemyData` 에 둘지** — 지금 안은 `WaveTable`.
  같은 오크를 후반에 더 단단하게 쓰려면 이쪽이 맞다
- **구멍 ⑥ 의 A/B 선택** — 추천은 A(프리팹 2개)지만 결정 필요
- **087 에서 다룰 "불편" 의 구체적 목록** — 강의안에 밸런싱 지시문이 있다는데 **내용 미확인**
- **1주차에 러너·탱커를 끄는 방법** — `WaveTable` 이 아직 없으므로 프리팹 배열에서 뺀다
- **젬 경험치의 순서** — 081(하드코딩) → 087~088(`EnemyData` 로 이동). 두 번 만지게 된다.
  081 때부터 `EnemyData` 를 쓰면 순서가 꼬인다(087 이 "첫 SO" 여야 함). **두 번 만지는 게 맞다**
- **상용작 구현 확인** — [몬스터-기획.md](./몬스터-기획.md) 1장의 미실측. 검색이 되면 다시 확인할 것
