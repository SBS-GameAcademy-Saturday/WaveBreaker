# 게임개발 입문 · 7개월 과정 — 강의 문서 허브

> 코딩을 처음 하는 학습자가 **7개월 뒤 협동 멀티플레이 게임 하나를 빌드해서 남에게 보내는 것**까지 가는 과정.
> 이 강의의 모든 문서가 여기에 있다. **여기서부터 읽는다.**
>
> 📦 이 문서들이 설명하는 게임을 실제로 구현하는 곳이 이 저장소(`WaveBreaker`)의 Unity 프로젝트다.
> 저장소 개요는 [../README.md](../README.md), 프로젝트 규격은 [05_Unity프로젝트/](./05_Unity프로젝트/README.md).

| | |
|---|---|
| 대상 | 코딩 경험 0, 연령대 혼합 |
| 형태 | **비대면 실시간**, 평일 2시간 × 주 5일 |
| 기간 | 7개월 = 28주 = **실수업 130회 + 버퍼 10회 = 140회 (280시간)** |
| 도구 | **Unity 6 LTS** + C# / Netcode for GameObjects + Relay |
| 만드는 것 | **웨이브 브레이커** (`WaveBreaker`) — [혼자 하기] / [같이 하기] 를 모두 지원하는 2D 협동 웨이브 디펜스 |

## 🔑 이 과정을 지탱하는 원칙 4가지

**1. C# 선행 — 1~4주차 문법, 7주차부터 유니티**
게임 제작 시간이 10회차 줄어드는 대신 문법 기반이 탄탄해진다. **콘솔 구간 이탈이 최대 리스크**이므로 1주차 완성작 시연 · 매주 결과물 발표 · 게임 문맥 예제를 반드시 병행한다.

**2. Phase 8(21주차)에서 싱글 완성본을 확정하고 백업한다**
네트워크는 그 위에 얹는 별도 레이어다. 네트워크가 끝내 안 되는 학생도 **이미 빌드된 완성작을 갖고 종강한다.** 이 과정의 최대 안전장치.

**3. Phase마다 스냅샷 프로젝트를 배포한다**
뒤처진 학생이 완성된 중간 프로젝트를 받아 다음 회차에 정상 합류한다. 7개월 과정에서 완주율을 가장 크게 바꾸는 장치.

**4. 불편함을 먼저 겪게 한 뒤 해결책을 준다**
풀링은 렉을 겪은 뒤에(101회차), 씬 전환 데이터 소실은 겪은 뒤에. 순서가 바뀌면 코드만 베낀다.

**5. 14주차에 Phase 1 콘솔 코드를 다시 꺼낸다**
6주차에 콘솔로 짠 `Enemy` 상속·`IDamageable`을 유니티로 옮기는 형태로 본 프로젝트를 시작한다. C# 선행의 투자를 회수하는 지점.
