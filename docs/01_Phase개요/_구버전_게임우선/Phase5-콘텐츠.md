## 🎯 목표

1. 기획서의 콘텐츠 규모를 전부 구현한다
2. **ScriptableObject로 데이터를 코드에서 분리**한다
3. 업그레이드 3택 시스템을 완성한다

## 📚 다루는 내용

| 주제 | 내용 |
|---|---|

| 적 3종 | 돌진형 / 원거리형 / 탱커형 |
| 보스 1종 | 3패턴 (소환 / 돌진 / 탄막) |

| 경험치/레벨 대신 웨이브 클리어 보상 | 구조 단순화 |

## ✅ 종료 조건

- [ ] 무기 3종이 동시에 발사된다
- [ ] 적 3종이 각각 다르게 행동한다
- [ ] 웨이브 1~10이 순서대로 진행되고 난이도가 올라간다
- [ ] 웨이브 클리어마다 업그레이드 3개가 뜨고, 고르면 실제로 반영된다
- [ ] 보스를 잡으면 클리어 화면으로 간다
- [ ] **코드를 안 고치고 ScriptableObject만으로 밸런스를 바꿀 수 있다**

## 📦 스냅샷 — `Snapshot_P5`

콘텐츠가 다 들어간 싱글 프로젝트 (UI·연출 전).

## 🚨 위험 신호 (강사용)

| 신호 | 의미 | 대응 |
|---|---|---|
| **여기서 학생별 결과물이 갈라진다** | 정상이자 의도된 것 | 필수 3종만 한 학생과 8종 만든 학생을 **둘 다 정상으로 취급** |
| 적을 마음대로 늘려 렉 발생 | 좋은 신호 | 막지 말 것. **Phase 7 풀링 수업의 소재로 저장** |
| ScriptableObject에서 막힘 | 정상. 개념이 낯설다 | "엑셀 표 하나 만든다고 생각하세요"로 접근. 에셋을 눈으로 만들며 |
| 보스에서 시간 초과 | 흔함 | **축소 계획 발동**: 보스 → 강화된 탱커 웨이브로 대체 |
| 업그레이드가 안 붙음 | 🔴 심각 | **절대 자르면 안 되는 기능.** 다른 걸 자르고 이걸 살린다 |

> 📌 **축소 순서** (기획서 15장): 폭발탄 → 보스 → 업그레이드 8→5종 → 탱커형 → 웨이브 10→7.
> **절대 안 자르는 것**: 업그레이드 3택 시스템.

## ⏭ 연결

업그레이드 선택창·체력바 등 UI가 임시 상태로 남는다. Phase 6이 이를 정식 UI로 만든다.
