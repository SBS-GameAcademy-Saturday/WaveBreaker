# Phase 7 · 싱글 완성 & 1차 빌드 ★

| | |
|---|---|
| **회차** | 098–105 (8회) |
| **기간** | 1.5주 |
| **선행** | Phase 6 |
| **산출물** | ✅ **빌드된 싱글 게임 (전원 백업 완료)** |

> 🔴 **이 과정 전체의 분기점.** 여기를 통과하면 이후 무슨 일이 있어도 모든 학생이 완성작을 갖는다.

## 🎯 목표

1. 성능 문제를 **직접 겪고** 오브젝트 풀링으로 해결한다
2. 밸런싱을 마친다
3. **PC 빌드를 산출하고 전원 백업한다**

## 📚 다루는 내용

| 주제 | 접근 |
|---|---|
| **오브젝트 풀링** | ⚠️ **순서 엄수** — 적을 잔뜩 늘려 렉을 만든 뒤 원인을 찾고, 그다음 풀링 |
| GC / Instantiate 비용 | 깊이 들어가지 않는다. "만들고 부수는 게 비싸다" 수준 |
| 밸런싱 | ScriptableObject 수치 조정. 학생끼리 교차 플레이 |
| 빌드 설정 | Player Settings, 해상도, 아이콘, 게임 이름 |
| PC 빌드 산출 | Windows / IL2CPP |
| **백업** | 프로젝트 압축 + 빌드 파일 보관 |

## 🗓 회차 배분

| 회차 | 주제 |
|---|---|
| 098 | **일부러 렉 만들기** — 적 200마리 소환, 프로파일러로 원인 보기 |
| 099–101 | 오브젝트 풀링 구현 (적 → 총알) |
| 102 | 밸런싱 ① — 수치 조정 |
| 103 | 밸런싱 ② — 교차 플레이 + 피드백 |
| 104 | **빌드 설정 + PC 빌드 산출** |
| 105 | **서로 다운받아 플레이 + 전원 백업 확인** |

## ✅ 종료 조건 — 전원 통과 필수

- [ ] 적이 많아져도 프레임이 유지된다
- [ ] 타이틀부터 클리어/게임오버까지 완주된다
- [ ] 웨이브 10 + 보스가 정상 동작한다
- [ ] **빌드한 실행 파일이 다른 사람 PC에서 실행된다**
- [ ] **프로젝트 압축본 + 빌드 파일이 안전한 곳에 백업됐다**

> ⚠️ **한 명이라도 빌드가 안 나오면 Phase 8로 넘어가지 않는다.** 버퍼를 여기 쓴다.

## 🚨 위험 신호 (강사용)

| 신호 | 의미 | 대응 |
|---|---|---|
| 풀링을 먼저 설명해버림 | 🔴 교육 설계 실패 | **반드시 렉을 먼저 겪게 한다.** 순서가 바뀌면 "왜 이걸 하는지" 모른 채 코드만 베낀다 |
| 빌드 에러 (경로 한글/공백) | Phase 0에서 예방했어야 함 | 002회차 한글 경로 금지의 이유가 여기서 나온다. 프로젝트 이동으로 해결 |
| WebGL 빌드 시도하다 시간 소모 | 함정 | **PC 빌드만 한다.** WebGL은 Phase 9 |
| 백업을 안 한 학생 | 🔴 치명적 | 105회차에 **한 명씩 확인.** 이 확인을 생략하면 안전장치가 무의미해진다 |
| 밸런싱이 끝없이 늘어짐 | 흔함 | 2회로 자른다. 완벽한 밸런스는 목표가 아니다 |
