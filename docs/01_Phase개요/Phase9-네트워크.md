# Phase 9 · 네트워크 협동

| | |
|---|---|
| **회차 / 주차** | 106–125 (20회) / 22~25주차 |
| **선행** | **Phase 8 완료 + 전원 백업 확인** |
| **산출물** | 친구와 접속해서 같이 하는 게임 (+ 싱글 모드 유지) |
| **사양서** | [확정-게임기획서.md](../00_기획/확정-게임기획서.md) 3·6·11장 |
| **레퍼런스** | ⚠️ **골드메탈 강좌 범위 밖.** 강사가 직접 레퍼런스를 만들어야 한다 |

> 🚨 **강사 준비 부담이 가장 큰 구간.** 골드메탈 뱀서라이크 강좌는 싱글 전용이라 여기부터는 대응 강의가 없다.
> **22주차 시작 전에 강사가 이 구간을 통째로 한 번 완주해 둘 것.**

## 🎯 목표

1. 호스트/클라이언트 구조를 **감각으로** 이해한다
2. 두 플레이어가 서로의 화면에서 움직인다
3. 몬스터·젬을 **호스트만 만들고** 모두에게 보이게 한다
4. **협동 카메라**로 둘을 함께 담는다
5. **싱글 모드를 "호스트 1인"으로 통합한다**

## 🔧 기술 스택

> ✅ **2026-09-03 · 실제로 설치하고 검증한 버전** (Unity 6.5 / 6000.5.4f1)
>
> | 패키지 | 버전 | 비고 |
> |---|---|---|
> | `com.unity.netcode.gameobjects` | **2.13.2** | |
> | `com.unity.multiplayer.playmode` | **2.0.2** | ⚠️ **문서만 들어 있다.** 기능은 에디터 내장 |
> | `com.unity.multiplayer.tools` | 2.2.11 | 네트워크 프로파일러 |
> | `com.unity.services.core` | 1.18.0 | |
> | `com.unity.services.authentication` | 3.7.4 | Relay 선행 |
> | `com.unity.services.relay` | 1.2.0 | 124회차 |
>
> 🚨 **설치 직후에는 `Window → Multiplayer` 메뉴가 없다. 에디터를 재시작해야 생긴다.**
> 강사가 실제로 겪었고, 108회차 강의안의 '오늘 1등 사고' 로 넣었다.
>
> 🚨 **가상 플레이어는 메모리를 3.3 GB 더 쓴다** (메인 에디터 3.5 GB + Player 2 3.3 GB).
> 램 8GB 이하 학생은 **빌드 테스트**로 대체한다 — 110회차에 대안을 넣었다.


| 항목 | 선택 | 이유 |
|---|---|---|
| 네트워크 | **Netcode for GameObjects** | Unity 공식, 개념 수가 적다 |
| 접속 | **Relay** | 포트포워딩 불필요. 비대면 필수 |
| 로컬 테스트 | **Multiplayer Play Mode** | 에디터 하나에서 가상 플레이어. 외부 도구 불필요 |

> ⚠️ **MPPM 제약**: 가상 플레이어에서는 **GameObject 생성·수정과 Package Manager가 안 된다.**
> 수정은 메인 에디터에서 한다. **110회차 첫머리에 공지한다.**
> ⚠️ **Relay는 UGS 프로젝트 연동**(Project Settings → Services)이 필요하다. **강사가 22주차 전에 절차를 검증해 둘 것.**

## 🗓 회차 배분

### 22주차 (106–110) — 개념과 첫 접속 ✅

| 회차 | 주제 |
|---|---|
| 106 | **왜 멀티는 어려운가** — "각자 화면에서 따로 도는 게임 2개" (코드 0줄) |
| 107 | 호스트/클라이언트 구조 · 동기화가 필요한 이유 |
| 108 | NGO 설치 + `NetworkManager` 설정 |
| 109 | `NetworkObject` 등록 + **첫 로컬 접속** |
| 110 | **MPPM 가상 플레이어 세팅** |

> 🔑 **106회차는 코드를 한 줄도 안 친다.** 그림으로만 설명한다.
> 💬 "두 사람이 **각자 자기 컴퓨터에서 게임을 따로 돌리고** 있어요. 화면이 두 개인 게 아니라 **게임이 두 개**입니다."
> 💬 "그래서 내 화면에서 일어난 일을 상대 게임에도 **알려줘야** 합니다. 그게 오늘부터 할 일이에요."

### 23주차 (111–115) — 동기화와 소유권

| 회차 | 주제 |
|---|---|
| 111 | 가상 플레이어 **2인 테스트 실습** |
| 112 | **`NetworkTransform`** — 이동 동기화 |
| 113 | 동기화 문제 진단 — 끊김·튐 관찰 |
| 114 | **`IsOwner`** — 내 캐릭터만 내가 조종 (Phase 5 규칙 ② 회수) |
| 115 | **`NetworkVariable`** — 체력·레벨 동기화 |

> 🔑 **114회차가 Phase 5 규칙 ②의 회수 지점이다.**
> "입력 읽는 곳과 움직이는 곳을 분리"해 뒀으므로 `if (!IsOwner) return;` **한 줄**로 끝난다.
> 💬 "14주차에 왜 나눠 놨는지 오늘 알게 됩니다."

### 24주차 (116–120) — 서버 권한

| 회차 | 주제 |
|---|---|
| 116 | **`Rpc`** — 클라이언트↔서버 통신 |
| 117 | **호스트 전용 몬스터 스폰** (Phase 5 규칙 ① 회수) |
| 118 | 경험치 젬 생성·획득의 서버 처리 |
| 119 | 서버 기반 피격 판정 |
| 120 | **협동 카메라 ①** — 살아있는 플레이어 평균 좌표 |

> 🔑 **117회차가 Phase 5 규칙 ①의 회수 지점이다.**
> 스폰이 매니저 한 곳에만 있으므로 `if (!IsServer) return;` **한 줄**로 끝난다.
> 💬 "여기저기서 몬스터를 만들었으면 오늘 전부 뜯어고쳐야 했어요."
>
> 🔑 **120회차 — Phase 7에서 만든 카메라를 "플레이어 목록의 중심"으로 바꾼다.**
> 목록의 원소가 1개면 싱글과 동작이 완전히 같다. **분기문이 필요 없다.**

### 25주차 (121–125) — 협동 기능과 통합

| 회차 | 주제 |
|---|---|
| 121 | **협동 카메라 ②** — 거리 기반 줌 + 소프트 리쉬 |
| 122 | **다운 · 동료 부활** (3초 곁에 있으면 부활) |
| 123 | **레벨업 시 양쪽 시간 정지** + 각자 카드 선택 |
| 124 | **Relay** — 접속 코드 입장 |
| 125 | **싱글/협동 모드 통합** + 원격 합동 플레이 + **[혼자 하기] 재확인** |

> 📌 **주 1회 "합동 플레이 데이" 고정 편성.** 실제로 서로 접속해 노는 시간이 이 구간 이탈을 막는다.
> 네트워크는 혼자 붙들고 있으면 재미가 하나도 없다.

## ✅ 종료 조건

- [ ] 방을 만들면 접속 코드가 나온다
- [ ] 코드로 입장한 사람이 서로 보인다
- [ ] 상대의 이동과 공격이 내 화면에서 보인다
- [ ] 몬스터·젬이 양쪽 화면에 **똑같이** 나온다
- [ ] 경험치가 공유되고 둘 다 레벨업한다
- [ ] 레벨업 시 **둘 다 멈추고** 각자 카드를 고른다
- [ ] **카메라가 둘을 함께 담는다** (멀어지면 줌아웃)
- [ ] 다운된 동료를 부활시킬 수 있다
- [ ] 둘 다 다운되면 게임 오버가 된다
- [ ] **[혼자 하기]도 여전히 정상 동작한다** ⭐

> 마지막 항목을 반드시 매 회차 확인한다. **협동을 만들다 싱글을 깨뜨리는 게 이 구간 최대 사고다.**

## 🚨 위험 신호 (강사용)

| 신호 | 의미 | 대응 |
|---|---|---|
| **내가 움직이면 상대도 움직임** | `IsOwner` 체크 누락 | 114회차 핵심. `if (!IsOwner) return;` |
| **몬스터가 두 배로 나옴** | 양쪽이 각자 스폰 | 117회차 핵심. `if (!IsServer) return;` |
| 상대가 안 보임 | `NetworkObject` 미등록 / 프리팹 목록 누락 | `NetworkManager`의 프리팹 목록 확인 |
| 움직임이 끊기고 튐 | 보간 설정 | `NetworkTransform`의 Interpolate 켜기 |
| **[혼자 하기]가 깨짐** | 🔴 최대 사고 | **매 회차 확인.** 깨지면 즉시 되돌린다 |
| MPPM에서 오브젝트 수정이 안 됨 | MPPM 제약 | 정상. 메인 에디터에서 수정 |
| Relay 접속 실패 | UGS 연동 안 됨 | **강사가 미리 검증해 둘 것** |
| 카메라가 한 명만 따라감 | 목록이 아니라 단일 참조 | 120회차. Phase 7 구조를 그대로 쓴다 |
| 둘이 너무 멀어져 서로 안 보임 | 소프트 리쉬 미적용 | 121회차 |
| 진도가 밀림 | 20회차도 빠듯하다 | **부활 → 협동 전체** 순으로 축소 (기획서 16절) |
| 네트워크가 끝내 안 됨 | 발생 가능 | **Phase 8 완성본으로 종강한다.** 그게 안전장치의 목적 |

## ⏭ 연결

Phase 10에서 최종 빌드를 만들고 공유 링크로 배포한다.
**협동이 안 되면 Phase 8 싱글 빌드를 제출물로 쓴다.** 미리 정해둔 길이므로 당황하지 않는다.
