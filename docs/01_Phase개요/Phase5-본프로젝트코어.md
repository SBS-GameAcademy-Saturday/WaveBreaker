1. Phase 1 객체지향을 유니티에 그대로 적용한다
2. 코어 루프를 완성한다
3. **네트워크 대비 설계 규칙 2가지를 심는다** (네트워크는 언급하지 않는다)

## 📚 다루는 내용

| 주차 | 내용 |
|---|---|
| 14주 (066–070) | 프로젝트 착수·에셋 임포트 / **Enemy 상속 구조** / **IDamageable** / enum 게임 상태 / GameManager·WaveManager |
| 15주 (071–075) | **코어 루프 연결** (이동→자동사격→스폰→피격→게임오버) / 기본 무기 / 관통 무기 |

> 🔑 **Phase 1 콘솔 코드를 다시 꺼낸다.** 6주차에 콘솔로 짰던 `Enemy` 상속·`IDamageable`을 유니티로 옮기는 형태로 진행하면 체감 난이도가 크게 떨어진다. "그때 만든 거 기억나죠? 이번엔 화면에서 움직입니다."

## 🔑 네트워크 대비 규칙 2가지 ★

**네트워크를 한마디도 하지 않고** 아래 두 가지만 "좋은 코드 습관"으로 심는다.

| 규칙 | 학생에게 하는 설명 |
|---|---|
| **① 몬스터 스폰·체력 계산은 매니저 한 곳에서만** | "여기저기서 몬스터를 만들면 나중에 누가 만들었는지 못 찾아요" |
| **② 입력을 읽는 곳과 실제 움직이는 곳을 분리** | "키보드 읽는 일이랑 움직이는 일은 다른 일이에요" |

> Phase 9에서 매니저에 `if (!IsServer) return;` 한 줄로 서버 권한 전환이 끝난다. **코드를 갈아엎지 않기 위한 포석.**

## ✅ 종료 조건

- [ ] `Enemy`를 상속한 몬스터가 3종 동작한다
- [ ] `IDamageable`로 플레이어와 몬스터가 같은 방식으로 피해를 받는다
- [ ] 시작 → 스폰 → 전투 → 사망 → 게임오버가 **끊김 없이 한 바퀴 돈다**
- [ ] 무기 3종이 동시에 발사된다
- [ ] 몬스터 스폰이 매니저 한 곳에서만 일어난다
- [ ] 입력 처리와 이동 처리가 분리돼 있다

> 재미없어도 된다. **한 바퀴 도는 것**이 기준.
