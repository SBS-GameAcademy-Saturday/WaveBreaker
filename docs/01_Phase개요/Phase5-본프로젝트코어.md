## 🎯 목표

1. Phase 1 객체지향(상속·인터페이스)을 **유니티에 그대로 옮긴다**
2. **무한 맵**을 만든다 — 이 게임의 정체성
3. 코어 루프를 완성한다 (이동 → 자동공격 → 피격 → 게임오버)
4. **네트워크 대비 설계 규칙 2가지를 심는다** (네트워크는 한마디도 안 한다)

## 🔑 네트워크 대비 규칙 2가지 ★

**네트워크를 한마디도 하지 않고** 아래 두 가지만 "좋은 코드 습관"으로 심는다.

| 규칙 | 학생에게 하는 설명 | 회수 시점 |
|---|---|---|
| **① 몬스터 스폰은 매니저 한 곳에서만** | "여기저기서 몬스터를 만들면 나중에 누가 만들었는지 못 찾아요" | 117회차 |
| **② 입력을 읽는 곳과 움직이는 곳을 분리** | "키보드 읽는 일이랑 움직이는 일은 다른 일이에요" | 114회차 |

> Phase 9에서 매니저에 `if (!IsServer) return;` 한 줄로 서버 권한 전환이 끝난다.
> **코드를 갈아엎지 않기 위한 포석.**

## ✅ 종료 조건

- [ ] 무한 맵이 **끊김 없이** 이어진다 (어디로 가도 바닥이 있다)
- [ ] 카메라가 플레이어를 따라간다
- [ ] `Enemy`를 상속한 몬스터 3종이 동작한다
- [ ] `IDamageable`로 플레이어와 몬스터가 같은 방식으로 피해를 받는다
- [ ] 몬스터가 화면 밖에서 계속 스폰되고 시간이 갈수록 강해진다
- [ ] 회전 근접 무기와 자동 원거리 무기가 **동시에** 자동 공격한다
- [ ] 시작 → 전투 → 사망 → 게임오버가 **끊김 없이 한 바퀴 돈다**
- [ ] 몬스터 스폰이 매니저 한 곳에서만 일어난다
- [ ] 입력 처리와 이동 처리가 분리돼 있다

> 재미없어도 된다. **한 바퀴 도는 것**이 기준. 재미는 Phase 6의 레벨업이 만든다.

## 🚨 위험 신호 (강사용)

| 신호 | 의미 | 대응 |
|---|---|---|
| **무한 맵에서 적이 순간이동** | 배경과 함께 적까지 옮김 | **최다 사고.** "배경 타일만 옮깁니다" |
| 무한 맵 이음새가 보임 | 타일 크기와 이동 거리 불일치 | 타일 크기 = 이동 거리로 정확히 맞춘다 |
| Phase 1 내용을 다 잊음 | 8주 전 배운 것 | **070회차를 콘솔 코드 복습으로 시작.** 생략 금지 |
| 회전 무기가 안 돌거나 튐 | 부모자식 회전 이해 부족 | 033회차 로봇팔로 되돌아간다 |
| 자동 조준이 엉뚱한 적을 봄 | 거리 비교 로직 | `Vector3.Distance` 최솟값. 디버그로 선을 그려 보여준다 |
| **총알이 안 사라져 쌓임** | 수명 처리 없음 | 지금은 `Destroy`로 둔다. **풀링은 101회차** — 렉을 겪게 한다 |
| 진도 격차 최대 | 이 Phase의 구조적 특성 | 스냅샷 배포 주기를 줄인다 |
| 싱글톤 남용 | 위험 | `GameManager` 하나만 허용 |
| **C# 선행 때문에 회차가 빠듯함** | 🔴 구조적 | 16주차 종료 시 진도 점검. 밀리면 **몬스터 3종 → 2종부터** 축소 |
