# Phase 6 · 성장 시스템 — 경험치 · 레벨업 · 보스

| | |
|---|---|
| **회차 / 주차** | 081–090 (10회) / 17~18주차 |
| **선행** | Phase 5 (코어 루프) |
| **산출물** | 레벨업으로 강해지고 보스까지 나오는 "게임다운" 싱글 |
| **사양서** | [확정-게임기획서.md](../00_기획/확정-게임기획서.md) 10장 |
| **레퍼런스** | 골드메탈 뱀서라이크 06+·11·12강 |

## 🎯 목표

1. **경험치 젬 → 레벨업 → 3택 1** 순환을 완성한다 ← 이 게임의 심장
2. **ScriptableObject로 데이터를 코드에서 분리**한다
3. 보스 3회를 넣어 한 판에 리듬을 만든다

> 🔑 **Phase 5까지는 "잡는 게임"이었고, Phase 6이 끝나면 "강해지는 게임"이 된다.**
> 로그라이크의 재미는 전부 레벨업 순환에서 나온다. 여기가 이 과정에서 재미가 생기는 유일한 구간이다.

## 🗓 회차 배분

### 17주차 (081–085) — 경험치와 레벨업

| 회차 | 주제 | 골드메탈 |
|---|---|---|
| 081 | **경험치 젬 드롭** — 몬스터가 죽으면 젬을 떨군다 | 12 |
| 082 | **자석 흡수** — 가까이 가면 젬이 끌려온다 | 12 |
| 083 | 경험치 누적 + **레벨업 곡선** 설계 | 12 |
| 084 | **`Time.timeScale = 0`** — 레벨업 시 시간 정지 | 11 |
| 085 | **업그레이드 3택 1** 선택 구조 (3종: 칼 +1 · 연사 + · 이동 +) | 11 |

> 🔑 **084회차가 개념적으로 가장 어렵다.** "시간이 멈춘다"는 게 코드로 뭘 뜻하는지 짚는다.
> `Time.timeScale = 0`이면 `Time.deltaTime`이 0이 되고, **`Update`는 계속 돌지만 아무것도 안 움직인다.**
> 039회차의 `Time.deltaTime`이 여기서 다시 나온다. **"그때 곱한 그거예요."**
>
> ⚠️ UI 버튼은 `timeScale`과 무관하게 동작한다. 안 그러면 카드를 못 고른다.

### 18주차 (086–090) — 데이터 분리와 보스

| 회차 | 주제 | 골드메탈 |
|---|---|---|
| 086 | **업그레이드 8종 구현** — 효과 적용 | 11 |
| 087 | **ScriptableObject 도입** — 왜 필요한가 | — |
| 088 | `EnemyData` / `WeaponData` 분리 | — |
| 089 | `UpgradeData` 분리 + **인스펙터 밸런싱 실습** | — |
| 090 | **보스 3회** (3분 / 6분 / 10분) + 스냅샷 | — |

> 🔑 **087회차는 불편을 겪은 뒤에 연다.**
> 086회차까지 업그레이드 8종의 수치가 전부 코드에 박혀 있다. 강사가 시킨다 —
> **"공격력 증가를 20%에서 25%로 바꾸세요. 몬스터 체력도 다 조정하세요."**
> 코드를 8군데 열고 고치고 저장하고 컴파일을 기다린다. 그 직후에 SO를 꺼낸다.
> 이 순서를 바꾸면 "왜 굳이 파일을 따로 만들죠?"가 나오고 학생은 코드만 베낀다.

## ✅ 종료 조건

- [x] 몬스터를 잡으면 젬이 떨어지고, 가까이 가면 끌려온다
- [x] 젬을 모으면 경험치가 차고 레벨이 오른다
- [x] 레벨업하면 **시간이 멈추고** 카드 3장이 뜬다
- [x] 카드를 고르면 실제로 강해진다 (칼이 늘거나 총알이 빨라진다)
- [ ] 업그레이드 8종이 전부 동작한다
- [ ] 몬스터·무기·업그레이드 수치가 **ScriptableObject 에셋**에 있다
- [ ] **코드를 열지 않고** 인스펙터만으로 밸런싱할 수 있다
- [ ] 3분·6분·10분에 보스가 나온다
- [ ] 최종 보스를 잡으면 승리 화면으로 간다

## 🚨 위험 신호 (강사용)

| 신호 | 의미 | 대응 |
|---|---|---|
| **레벨업 창에서 버튼이 안 눌림** | `timeScale = 0`인데 버튼이 시간에 묶임 | UI는 `unscaledDeltaTime`. **084회차 최다 사고** |
| 시간 정지 후 재개가 안 됨 | `timeScale = 1` 복구 누락 | 카드 선택 직후 반드시 복구 |
| 젬이 안 끌려옴 | 거리 판정 또는 이동 코드 | `Vector3.MoveTowards`. 자석 반경을 크게 해 확인 |
| 젬이 화면을 덮음 | 드롭이 많고 안 사라짐 | 수명 또는 최대 개수 제한. **풀링은 101회차** |
| 레벨업이 너무 빠르거나 느림 | 곡선 설계 | 인스펙터에서 조절하게 한다. **그게 089회차 실습** |
| **SO를 왜 쓰는지 이해 못 함** | 불편을 안 겪음 | **087 전에 반드시 코드 8군데 고치기를 시킨다** |
| SO 에셋을 만들었는데 인스펙터에 안 뜸 | `[CreateAssetMenu]` 누락 | 애트리뷰트 확인 |
| SO 값을 Play 중에 바꿈 | **저장된다** (일반 컴포넌트와 반대) | ⚠️ 학생이 혼란스러워한다. "SO는 Play 중 변경이 남습니다" |
| 보스가 너무 강해 아무도 못 깸 | 밸런스 | 089회차 실습으로 학생이 직접 조정하게 한다 |
| 진도가 밀림 | 10회차는 빠듯하다 | **보스 II·III부터 축소** (기획서 16절) |
