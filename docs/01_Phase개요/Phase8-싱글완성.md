### 101회차 — 불편을 겪게 하는 마지막이자 가장 중요한 회차

Phase 5부터 지금까지 몬스터·총알·젬을 전부 `Instantiate`/`Destroy`로 만들어 왔다.
**후반부(7분 이후)로 가면 프레임이 눈에 띄게 떨어진다.** 그걸 먼저 겪게 한다.

> 💬 "지금 몇 프레임 나와요?" → 학생들이 각자 숫자를 말한다. 20, 15, 10...
> 💬 "왜 느려졌을까요?" → 추측하게 둔다
>
> **프로파일러를 연다.** `Window → Analysis → Profiler`
> GC(가비지 컬렉션) 스파이크와 `Instantiate` 비용을 눈으로 보여준다.
>
> 💬 "만들고 버리고 만들고 버리고를 초당 수백 번 하고 있었어요. **안 버리고 재활용하면** 됩니다."

> 🔑 **골드메탈 강좌는 풀링을 06강(초반)에 넣는다. 우리는 일부러 여기까지 미뤘다.**
> 처음부터 풀링으로 만들면 학생은 "왜 이렇게 복잡하게 하지?"만 남고 코드를 베낀다.
> 렉을 겪은 뒤에 주면 **해결책으로 기억된다.** ([레퍼런스-분석.md](../00_기획/레퍼런스-분석.md))

## 🚨 위험 신호 (강사용)

| 신호 | 의미 | 대응 |
|---|---|---|
| **풀링 후 오브젝트가 안 나옴** | `SetActive(true)` 누락 | 최다 사고. 꺼내올 때 켜야 한다 |
| 풀링 후 이전 상태가 남음 | 초기화 누락 | **재활용 시 체력·속도를 리셋**해야 한다. 개념적으로 어렵다 |
| 풀이 계속 커짐 | 반납 누락 | `Destroy` 대신 `SetActive(false)` 로 반납했는지 |
| 풀링을 이해 못 함 | 개념 난이도 | **"쓰레기통 대신 서랍"** 비유. 실물로 비유해야 붙는다 |
| **빌드 실패 — 경로에 한글** | 🔴 031회차 경고 무시 | **가장 비싼 사고.** 프로젝트를 옮기고 다시 빌드 |
| 빌드가 아주 오래 걸림 | IL2CPP 백엔드 | Player Settings에서 **Mono**로 바꾸면 훨씬 빠르다 |
| 빌드는 됐는데 실행 시 검은 화면 | 씬이 Build Settings에 없음 | `File → Build Settings`에 씬 3개 전부 추가 |
| 백업을 안 함 | "나중에 할게요" | **절대 넘어가지 않는다.** 105회차 종료 조건 |
| 진도가 밀려 빌드를 못 함 | 🔴 최악 | **다른 걸 다 자르고 빌드를 한다.** 완성도보다 완성이 우선 |
