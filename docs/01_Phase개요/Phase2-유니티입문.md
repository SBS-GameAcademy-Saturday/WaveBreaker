## 🎯 목표

1. 유니티 에디터에 손이 익는다
2. GameObject = 그릇 / Component = 부품 구조를 안다
3. C# 스크립트를 컴포넌트로 붙인다
4. 입력으로 캐릭터를 움직인다

> 📚 이 순서는 [레퍼런스-분석.md](../00_기획/레퍼런스-분석.md) 에서 검증된 입문 강의 5종을 조사해 재설계한 것이다.
> 핵심 근거 3가지:
> 1. **Inspector에 한 회차 전부** — 골드메탈 엔진입문도 인터페이스에 통째로 한 편(B1)을 쓴다
> 2. **Transform에 두 회차** — 기관 교육과정(한국디지털컨버전스협회)은 트랜스폼에만 3강을 쓴다
> 3. **`Time.deltaTime`은 이동 뒤(039)** — 골드메탈 B8과 같다. 037·038에서 겪은 불편을 회수한다

> 🔑 **Phase 0~1과의 연결을 계속 짚는다.** "이 스크립트도 클래스예요", "Start는 우리가 만들던 메서드예요", "`[SerializeField]`는 private 필드를 인스펙터에만 여는 겁니다(property 배웠죠)". 6주간 배운 게 헛되지 않았다는 확인이 이 구간 동기의 핵심이다.

## ✅ 종료 조건

- [ ] 에디터 6개 창의 역할을 말한다
- [ ] `F` 키로 오브젝트 앞으로 이동한다
- [ ] Component를 추가·제거한다
- [ ] 스크립트를 만들어 GameObject에 붙인다
- [ ] `Start`/`Update` 차이를 한 문장으로 말한다
- [ ] `[SerializeField]` 변수를 인스펙터에서 조절한다
- [ ] WASD로 캐릭터를 움직인다
- [ ] Play 중 변경은 저장되지 않음을 안다

## 🚨 위험 신호 (강사용)

| 신호 | 의미 | 대응 |
|---|---|---|
| **스크립트가 안 붙음** ("Can't add script") | 파일명 ≠ 클래스명 | 파일을 지우고 다시 만든다. 이름 바꾸기보다 빠르다 |
| "물체가 안 보여요" | 카메라 문제 | Hierarchy 클릭 → `F`. 7주차에 반복 훈련 |
| Play 모드에서 작업하고 다 날림 | 반드시 나온다 | 7주차에 예고하고, 나와도 화내지 않는다 |
| 저장 안 하고 Play | 흔함 | "저장 → 유니티로 전환 → 잠깐 기다림" 3회 반복 강조 |
| 콘솔 문법을 못 이어붙임 | 예상보다 흔함 | 매 회차 "이거 O주차에 배운 거예요"를 명시적으로 연결 |
| 프로젝트 경로 한글·공백 | 21주차 빌드에서 터진다 | 7주차 프로젝트 생성 시 못 박는다 |
