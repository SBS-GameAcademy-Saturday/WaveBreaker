# 강의 운영 매뉴얼

> 수업 **내용**이 아니라 **운영**에 관한 것. 7개월 내내 이 규칙을 바꾸지 않는다.

## 1. 하루 2시간 고정 포맷

| 시간 | 블록 | 포인트 |
|---|---|---|
| 00:00–00:10 | 복습 + 퀴즈 1~3문제 | 채팅 동시 답변 → 이해도 스캔 |
| 00:10–00:45 | **같이 치기 라이브코딩** | 강사 화면공유 + 학생 동시 타이핑. "보기"가 아니라 "치기". **복붙 금지** |
| 00:45–00:55 | 휴식 | 화면 끄기 허용 |
| 00:55–01:35 | **개인 미션** | 골격 코드 + `// TODO` 빈칸. 강사는 브레이크아웃 순회 |
| 01:35–01:50 | 코드 리뷰 / 학생 1명 데모 | 순번제 |
| 01:50–02:00 | 체크리스트 + **결과 제출** + 예고 | 제출이 곧 출석 |

**포맷을 고정하는 이유**: 비대면에서 매번 진행이 달라지면 학생이 "언제 집중해야 하는지" 모른다. 리듬이 곧 집중력이다.

## 2. 제출 규칙

- 매 회차 끝에 **그날 화면 스크린샷 또는 GIF 1개**
- 잘 된 것만 올리는 게 아니다. **안 되면 안 되는 화면을 올린다** — 그게 가장 좋은 질문
- 채널: 결과가 눈에 보이는 날은 `#자랑`, 아니면 `#제출`
- **2회 연속 미제출 → 개별 연락** (공개 채널에서 언급하지 않는다)

## 3. 질문 규칙

에러가 나면:

1. Console **빨간 줄 전체** 스크린샷
2. 해당 코드 부분도 함께
3. `#질문` 채널에 올리기

> "안 돼요"만으로는 도울 수 없다. **화면을 보여주게 한다.**
> Phase 8부터는 `IsServer` / `IsOwner` 로그도 함께 요구한다.

## 4. 디스코드 채널 구성

| 채널 | 용도 |
|---|---|
| `#공지` | 준비물, 일정, 버전 |
| `#질문` | 에러·막힘 |
| `#자랑` | 결과물 — **가장 중요한 채널.** 남의 결과물이 최고의 동기 |
| `#제출` | 스크린샷 제출 |
| `#자료` | 골격 코드, 스냅샷, 에셋 패키지 |

## 5. 진도 편차 대응

| 장치 | 내용 |
|---|---|
| **필수 / ⭐도전 2단계 미션** | 필수는 전원 통과 가능한 난이도로 고정. **필수 난이도를 올리지 않는다** |
| **Phase 스냅샷 배포** | 뒤처진 학생이 완성된 중간 프로젝트로 다음 회차 정상 합류 |
| 골격 코드 + `// TODO` | 백지에서 시작시키지 않는다 |
| 도전 과제 = 본인 게임 콘텐츠 | 빠른 학생의 결과물이 그대로 자기 게임이 된다 |

> ⚠️ **진도 빠른 학생에게 다음 회차 내용을 미리 알려주지 않는다.** 다음 시간에 할 게 없어진다.

## 6. 연령대 혼합 반 운영

- **닉네임으로만 부른다.** 1일차에 이 문화를 고정하면 질문 장벽이 크게 낮아진다
- 나이·직업·소속을 묻지 않는다
- 발표·마이크는 **권유하되 강요하지 않는다.** 채팅·녹화 대체 허용

## 7. 절대 지키는 것 5가지

1. **Unity 버전 하나로 고정.** 버전 자유 허용 금지
2. **프로젝트 경로에 한글·공백 금지** (Phase 7 빌드에서 터진다)
3. **문법을 먼저 가르치지 않는다.** 불편함 → 해결책 순서
4. **Phase 7 싱글 빌드 백업을 전원 확인**하고 Phase 8로 넘어간다
5. **에셋은 강사가 정리해 배포한다.** 학생 개별 탐색 금지
