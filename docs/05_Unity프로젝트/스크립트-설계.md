# 스크립트 설계 — WaveBreaker

> [확정-게임기획서.md](../00_기획/확정-게임기획서.md)를 코드 구조로 옮긴 문서. **강사 레퍼런스 프로젝트를 만들 때의 설계도.**
> 학생에게는 이 표 그대로 주지 않는다 — 회차마다 필요한 부분만 골격 코드로 가공해서 배포한다.

---

## 1. 설계 원칙 3가지

**① 네트워크 대비 규칙 2개를 처음부터 지킨다** (14주차에 "좋은 습관"으로 심는다)

| 규칙 | 코드에서의 의미 |
|---|---|
| **몬스터 스폰·체력 계산은 매니저 한 곳에서만** | `Instantiate(enemy)`가 `WaveManager` 밖에 존재하면 안 된다 |
| **입력 읽는 곳과 움직이는 곳을 분리** | `PlayerInput`(읽기)과 `PlayerController`(이동)를 나눈다 |

> 이 둘만 지키면 22~25주차에 `if (!IsServer) return;` 과 `if (!IsOwner) return;` 을 넣는 것으로 네트워크 전환이 끝난다.

**② 데이터는 ScriptableObject로 뺀다** (17주차)
수치가 코드에 박혀 있으면 밸런싱이 "코딩"이 된다. 데이터를 빼면 진도 느린 학생도 밸런싱에 참여할 수 있다.

**③ 상속은 몬스터에만 쓴다**
플레이어·무기까지 상속 계층을 만들면 노베이스가 길을 잃는다. 무기는 상속을 쓰되 **1단계까지만**.

## 2. 클래스 목록

### Player

| 클래스 | 책임 | 도입 |
|---|---|---|
| `PlayerInput` | 키 입력을 읽어 방향 값만 보관 | 15주차 |
| `PlayerController` | `PlayerInput`의 값으로 이동 | 15주차 |
| `PlayerHealth` : `IDamageable` | 체력, 피격, 무적시간, 다운/부활 | 15주차 |
| `PlayerStats` | 업그레이드로 변하는 스탯(공격력·연사·속도·최대체력) | 18주차 |
| `WeaponHolder` | 보유 무기 목록 관리, 발사 요청 | 15주차 |

> 🔑 `PlayerInput` / `PlayerController` 분리가 규칙 ②다. 학생에게는 **"키보드 읽는 일과 움직이는 일은 다른 일"** 로만 설명한다.

### Weapon

| 클래스 | 책임 | 도입 |
|---|---|---|
| `WeaponBase` (abstract) | 쿨다운, 타겟 탐색, `Fire()` 추상 메서드 | 15주차 |
| ├ `StraightWeapon` | 직선 1발 | 15주차 |
| ├ `PierceWeapon` | 관통 (최대 3마리) | 15주차 |
| └ `ExplosiveWeapon` | 착탄 지점 범위 피해 | 16주차 |
| `Projectile` | 이동, 충돌, 수명, 관통 카운트 | 15주차 |

### Enemy

| 클래스 | 책임 | 도입 |
|---|---|---|
| `Enemy` (abstract) : `IDamageable` | 체력, 피격, 사망 처리, `Move()` virtual | 14주차 |
| ├ `ChargerEnemy` | 플레이어를 향해 직진 | 14주차 |
| ├ `RangedEnemy` | 일정 거리 유지 + 투사체 발사 | 16주차 |
| ├ `TankEnemy` | 느리고 단단함 | 16주차 |
| └ `BossEnemy` | 3패턴 (소환 / 돌진 / 탄막) | 18주차 |

**상속 구조 (학생에게 보여줄 형태)**

```
        IDamageable  ← 인터페이스
         ↑        ↑
   PlayerHealth  Enemy (abstract)
                  ↑    ↑     ↑     ↑
            Charger Ranged Tank  Boss
```

> 💬 6주차 콘솔 실습에서 만든 구조와 **똑같다.** 14주차 첫 회차에 그 코드를 다시 띄우고 "여기에 MonoBehaviour만 붙입니다"로 시작한다.

### Manager

| 클래스 | 책임 | 도입 | 네트워크 |
|---|---|---|---|
| `GameManager` | 게임 상태(enum), 시작/종료, 씬 전환 | 14주차 | 상태를 `NetworkVariable`로 |
| `WaveManager` | **유일한 스폰 지점.** 웨이브 진행, 클리어 판정 | 14주차 | **서버 전용** ⭐ |
| `UpgradeManager` | 업그레이드 3개 추첨, 선택 반영 | 18주차 | `Rpc` 요청 → 서버 검증 |
| `PoolManager` | 몬스터·총알 오브젝트 풀 | 21주차 | 서버 스폰과 연동 |
| `AudioManager` | BGM·SFX 재생 | 20주차 | 로컬 |

```csharp
public enum GameState { Title, Playing, Upgrading, Paused, GameOver, Clear }
```

### Data (ScriptableObject) — 17주차

| 클래스 | 담는 것 |
|---|---|
| `WeaponData` | 데미지, 연사 간격, 투사체 프리팹, 관통 수, 폭발 반경 |
| `EnemyData` | 체력, 이동 속도, 공격력, 스프라이트, 점수 |
| `WaveData` | 몬스터 종류별 수량, 스폰 간격, 동시 최대 수 |
| `UpgradeData` | 이름, 설명, 아이콘, 효과 종류(enum), 수치 |

### UI — 19~20주차

| 클래스 | 책임 |
|---|---|
| `HUDView` | 체력바, 동료 체력바, 웨이브, 잔여 몬스터, 보유 무기 |
| `UpgradeSelectView` | 카드 3장 표시, 선택 전달 |
| `TitleView` | [혼자 하기] / [같이 하기] / 종료 |
| `PauseView` | 계속 / 타이틀로 |
| `ResultView` | 클리어·실패, 생존 시간, 처치 수, 최종 스탯 |

### Network — 22~25주차 (별도 브랜치)

| 클래스 | 책임 | 회차 |
|---|---|---|
| `NetworkGameManager` | 접속 상태, 플레이어 등록, 게임 시작 동기화 | 116~120 |
| `RelayConnector` | 방 만들기(코드 발급) / 코드로 입장 | 121~122 |
| `LobbyView` | 코드 표시·복사, 코드 입력, 참가자 목록 | 121~122 |
| `ModeSelector` | [혼자 하기] = `StartHost()` 후 즉시 시작 / [같이 하기] = Relay | 123~124 |

**기존 클래스에 붙는 변경**

| 클래스 | 변경 |
|---|---|
| `PlayerController` | `NetworkBehaviour` 상속 + `if (!IsOwner) return;` |
| `PlayerHealth` | 체력을 `NetworkVariable<int>`로 |
| `WaveManager` | `if (!IsServer) return;` + `NetworkObject.Spawn()` |
| `Enemy` | `NetworkBehaviour` + `NetworkTransform` |
| `UpgradeManager` | 선택을 `Rpc`로 서버에 요청 |

> 🔑 **변경 목록이 이렇게 짧은 게 규칙 ①②를 지킨 결과다.** 스폰이 여기저기 흩어져 있었다면 이 표가 세 배로 늘어난다.

## 3. 인터페이스

```csharp
public interface IDamageable
{
    void TakeDamage(int amount);
    bool IsAlive { get; }
}
```

> 💬 "몬스터랑 플레이어는 부모가 다른데 둘 다 맞아야 하잖아요" — 인터페이스를 설명하는 한 문장. 6주차에 이미 쓴 표현을 그대로 재사용한다.

## 6. 강사가 미리 검증할 것

- [ ] `WaveManager`의 스폰이 **정말 한 곳뿐인지** — 나중에 서버 전용으로 바꿀 지점
- [ ] `PlayerInput` → `PlayerController` 분리가 어색하지 않은지 (노베이스에게 설명 가능한 형태인가)
- [ ] `WeaponBase` 상속이 1단계를 넘지 않는지
- [ ] 풀링 도입 시 `WaveManager` 코드가 얼마나 바뀌는지 — 21주차 수업 분량 산정용
- [ ] 네트워크 전환 시 실제로 바뀌는 줄 수 — 위 "변경 목록"이 맞는지 직접 확인
