# 브랜치 전략

> 이 저장소(레퍼런스 프로젝트)를 **주차별 · 컨텐츠별 브랜치로 나눠 가며 수업을 준비**하는 규칙.
> 프로젝트 3종(레퍼런스 / 템플릿 / 스냅샷) 구분은 [README.md](./README.md) 참고.

---

## 1. 브랜치 4종

| 브랜치 | 예시 | 파생 원본 | 역할 |
|---|---|---|---|
| `main` | `main` | — | **항상 동작하는 최신 진행분.** 주차 준비가 끝난 것만 들어온다 |
| `week/NN` | `week/07` | `main` | **그 주 5회차 분량**을 준비하는 작업 브랜치 |
| `feat/<주제>` | `feat/player-move` | `week/NN` | 주차 안에서 **기능 하나** 단위. 시행착오는 여기서 |
| `snapshot/<이름>` | `snapshot/P8_Final_Single` | `main` | **학생 배포용 고정점.** Phase 종료 시 만들고 이후 건드리지 않는다 |

> 🔑 **`main`에 직접 커밋하지 않는다.** 수업 중 실수로 깨진 상태가 `main`에 남으면
> 그 시점 이후 스냅샷을 뽑을 수 없다. `main`은 언제 잘라도 학생에게 줄 수 있는 상태로 유지한다.

### 왜 회차(`lesson/031`)가 아니라 주차인가

회차 단위 브랜치는 100개가 되고, 회차 하나에서 실제로 커밋할 만한 변화가 안 나오는 날이 많다.
**준비 단위는 주차, 개발 단위는 기능**이 실제 작업 리듬에 맞는다. 회차 대응은 커밋 메시지에
`[035]` 처럼 남겨서 추적한다.

## 2. 작업 흐름

```
main ──────●───────────────────────────────●──────────────●─────▶
            \                             /                \
   week/07   ●────●──────────●───────────●            snapshot/P2
                   \        /
      feat/player-move ●───●
```

### ① 주차 준비 시작

```powershell
.\tools\lesson.ps1 week 7
```

`main`에서 `week/07`을 만들고 이동한다. (이미 있으면 그냥 이동)

### ② 기능 단위로 쪼개기

```powershell
.\tools\lesson.ps1 feat player-move
```

현재 `week/NN`에서 `feat/player-move`를 만든다. **수업에서 보여줄 코드는 여기서 완성한다.**
막히면 이 브랜치를 버리고 다시 파면 되고, `week/07`은 그대로다.

### ③ 기능 완료 → 주차 브랜치로

```powershell
.\tools\lesson.ps1 done
```

현재 브랜치를 부모(`feat/*` → `week/NN`, `week/NN` → `main`)로 `--no-ff` 머지한다.
머지 커밋이 남으므로 "이 기능이 어디서 들어왔는지"가 히스토리에 보인다.

### ④ 주차 끝 → main

`week/07`에서 다시 `done`. 이때 **반드시 Unity를 열어 컴파일·플레이가 되는지 확인**하고 머지한다.

### ⑤ Phase 끝 → 스냅샷 고정

```powershell
.\tools\lesson.ps1 snapshot P8_Final_Single
```

`main`에서 스냅샷 브랜치를 딴다. 스냅샷 이름은 각 Phase 문서의 `📦 스냅샷` 절을 따른다
([01_Phase개요/](../01_Phase개요/README.md)). **한 번 만든 스냅샷 브랜치에는 커밋하지 않는다.**

## 4. 커밋 메시지 규칙

```
[회차] 요약

예)
[035] Player에 SerializeField 이동속도 노출
[066] 콘솔 Enemy 상속 구조를 MonoBehaviour로 이식
[101] 오브젝트 풀링 도입 — 렉 체감 후 해결책 제시
```

회차 번호가 붙으면 `git log --oneline | grep '\[10'` 같은 식으로 특정 구간을 바로 찾을 수 있다.
회차와 무관한 작업(리팩터링, 문서)은 `docs:` `chore:` `refactor:` 접두어를 쓴다.

## 5. 학생 배포와의 관계

학생에게는 **Git이 아니라 압축본을 준다.** (Git은 27주차 ⭐도전 과제)
스냅샷 브랜치는 압축본을 뽑아내는 원본일 뿐이다.

```powershell
git archive --format=zip -o Snapshot_P8_Final_Single.zip snapshot/P8_Final_Single
```

> ⚠️ `git archive`는 `.gitignore`된 `Library/`를 빼고 뽑는다. 학생이 열면 Unity가 다시 임포트하므로
> **첫 실행이 몇 분 걸린다는 걸 미리 공지**한다.
